**学习目标**:学完本章,你将能够——

1. 用自己的话说清预训练的定义,并区分教学规模与生产级训练;
2. 为 Mini GPT 写出可执行的目标、预算和成功标准;
3. 估算参数量、数据量、训练时长之间的基本关系;
4. 建立实验目录与配置记录,让实验可复现、可判断成败。

## 1. 预训练的概念

- **预训练(Pretraining)** 是使用大量无标注文本,让模型学习「根据前文预测下一个 token」的过程。训练完成的模型称为**基础模型(Foundation Model)**:它具备语言模式与部分通用知识,但尚未针对具体任务优化。
- 为什么叫「预」训练?因为它只是**第一步**:后续还要经过指令微调(SFT)、偏好对齐(如 RLHF/DPO)才能变成好用的助手——本单元(01.02)只做第一步,微调在 01.03。
- 一句话:**预训练的目标是让模型先「懂语言」,而不是直接「会聊天」。**

### 1.1 为什么需要「自己训一个模型」

你可能会问:开源模型那么多,直接下载 Llama 用不就行了吗?为什么还要亲手训练?三个理由:

| 理由 | 说明 | 收获 |
|---|---|---|
| 理解黑盒 | 只用 API 永远不知道 tokenizer、loss、采样之间如何咬合 | 建立完整心智模型 |
| 排障能力 | 微调/部署出问题时,能判断是数据、模型还是训练环节 | 可迁移的工程判断 |
| 规模洞察 | 亲手把百万参数训到 loss 下降,才真正理解「为什么 7B 模型需要那么多数据」 | 对算力成本的敬畏 |

- **取舍**:自己训不等于和商业大模型比能力。教学 Mini GPT 的目的是**复现完整链路**,不是复现通用智能。

## 2. 三种规模,分清边界

| 层次 | 典型规模 | 本课程要求 |
|---|---|---|
| 教学 Mini GPT | 百万级参数、MB~GB 文本、单卡或 CPU | **必做,可完整复现** |
| 开源小模型 | 亿级参数、数十 GB 数据、多卡可选 | 了解训练计划与成本 |
| 通用基础模型 | 70 亿以上参数、TB 级数据、大规模集群 | 理解工程方法,不要求个人训练 |

- 本模块的目标不是复现商业大模型,而是独立完成一条完整链路:

```mermaid
flowchart LR
    A[文本数据] --> B[Tokenizer]
    B --> C[DataLoader]
    C --> D[Decoder-only Transformer]
    D --> E[训练循环]
    E --> F[Checkpoint]
    F --> G[生成与评测]
```

- 该链路与大规模训练**结构相同**,差别只在数据、参数、硬件和工程复杂度。

> 从本章开始,所有操作都在**同一个空项目**中完成。不要只阅读代码块:每出现一个文件,就在你的电脑上创建同名文件并运行。本系列最后得到的不是笔记,而是一个能从原始文本训练并生成文字的项目目录。

## 3. 项目目标与非目标

- **本项目目标**:训练一个能生成结构化短文本的小型语言模型。成功不等于生成内容像 ChatGPT 一样自然,而是训练过程和工程产物完整、可复现、可解释。
- **非目标**(不在本模块解决):RLHF 完整生产流程、千卡分布式集群、商业语料采购、互联网规模数据治理——这些分别在 01.03 微调、01.07 安全等模块展开。

## 4. 建立实验契约

- 为什么要「契约」?因为训练实验最大的敌人是**事后编故事**:跑完说「成功了」,却说不清用了什么数据、多少步、为什么算成功。实验卡把答案固定在动手之前。

在仓库根目录建立六个目录,并为第一次实验填写下表:

| 项目 | 示例 |
|---|---|
| 数据集 | Shakespeare 字符级文本或已获许可的公开语料 |
| 任务 | 根据前文生成后续字符/词元 |
| 模型 | 4 层 decoder、128 hidden size、4 attention heads |
| 硬件 | 本地 CPU 或单张 GPU |
| 预算 | 训练不超过 2 小时,显存不超过可用上限 |
| 指标 | 验证损失下降;固定提示词产生可读输出 |

### 4.1 从空文件夹建立可运行环境

先确认 Python 版本(3.11+):

```bash
python --version
```

然后创建项目与虚拟环境:

```bash
mkdir minigpt-course
cd minigpt-course
python -m venv .venv
```

激活虚拟环境(出现 `(.venv)` 才算成功):

```bash
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell(只执行这一行)
.venv\Scripts\Activate.ps1
```

安装本阶段最少依赖:

```bash
python -m pip install --upgrade pip
pip install torch tokenizers pyyaml numpy
```

验证安装(而不是假设成功):

```bash
python -c "import torch, tokenizers, yaml; print('torch=', torch.__version__); print('device=', 'cuda' if torch.cuda.is_available() else 'cpu')"
```

> [!note] 没有 GPU 怎么办
> `cpu` 完全可以完成本教程,只是训练时间更长;不要因为没有 GPU 而跳过后续步骤。

### 4.2 创建每一章都会使用的目录和配置

```bash
mkdir -p data/raw data/processed data/tokenized artifacts src configs runs reports eval
```

创建 `configs/minigpt.yaml`(YAML 缩进是语法,只用空格不用 Tab):

```yaml
seed: 42
run_name: alice-bpe-v1
data_dir: data
tokenizer_path: artifacts/tokenizer.json
model:
  context_length: 128
  d_model: 128
  n_heads: 4
  n_layers: 4
training:
  batch_size: 16
  learning_rate: 0.0003
  max_steps: 1000
  eval_every: 100
  checkpoint_every: 250
```

## 5. 预算与风险:为什么「先小后大」

- 参数量、上下文长度、数据量三者都会**放大成本**:参数量翻倍 → 前向/反向计算翻倍;上下文变长 → 注意力开销按长度平方增长;数据变多 → 训练时长线性增长。
- 因此铁律是:**先用极小数据和极小模型跑通,再逐步扩大**;不要在代码尚未验证时启动长时间训练。
- 同时必须保存:随机种子、配置、数据版本、依赖版本——否则「看起来训练成功」的结果无法复现(第 10 章详讲)。

## 6. 动手活动:编写实验卡

> [!example] 动手活动:编写实验卡
>
> **目标**:提交第一份 `reports/experiment-00.md`,把「训练什么、花多少钱、怎样算成功」写死在动手之前。
>
> **步骤**:
> 1. 按 4.1 建立并激活 `.venv`;运行依赖检查;
> 2. 创建目录和 `configs/minigpt.yaml`;
> 3. 按第 4 节表格,把数据来源、许可证、硬件、训练时长上限、模型参数和三条成功标准写入 `reports/experiment-00.md`;
> 4. 运行 `nvidia-smi`(无 NVIDIA GPU 时记录 CPU 与内存信息)。
>
> **完成标准**:第三方能够据此判断实验是否可运行、成本是否可接受、何时算成功。

## 7. 总结

| 产物 | 用途 |
|---|---|
| 实验卡 | 固定目标、边界、预算与验收标准 |
| 目录结构 | 分离代码、数据、配置、权重与报告 |
| 小规模基线 | 在低成本下先验证完整链路 |

**思考题**:为什么「验证损失下降」比「某一次生成读起来不错」更适合作为首个成功标准?为何本项目不应宣称自己从零训练了可通用使用的大模型?

> [!note] 参考答案
> 验证损失是在固定、未参与参数更新的数据上重复计算的量化信号;单次生成可能受提示词和随机抽样影响。教学 Mini GPT 的数据、参数和评测范围都很小,只能证明完整训练链路跑通,不能证明通用能力或安全性。
