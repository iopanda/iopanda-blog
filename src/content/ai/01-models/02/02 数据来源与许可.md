> 上一章定义了「训练什么、怎样算成功」并建好项目骨架;这一章回答动手前最后一道关卡:**这些文本从哪里来、我们有没有权利拿它们训练模型**。你将理解为什么「网页打得开」不等于「可以训练」,并为真实语料 *Alice's Adventures in Wonderland* 建立可审计的数据清单(Data Manifest)。

**学习目标**:学完本章,你将能够——

1. 用自己的话区分「数据可访问」与「数据可训练」,并解释版权与许可为何是预训练绕不开的问题;
2. 阅读数据集许可证与 dataset card,识别商业、署名、再分发等使用边界;
3. 说明 Data Manifest 的作用,为每个数据源登记来源、许可、版本与用途;
4. 独立完成真实语料的下载、校验与登记全流程;
5. 在授权无法确认时选择「拒绝该来源」,而不是「先用了再说」。

## 1. 数据可访问 ≠ 数据可训练

- **概念**:「数据可访问」是技术状态——网页打得开、文件能下载、脚本能抓取;「数据可训练」是法律状态——你**有权**把它复制进训练集、用它产生派生模型,并(可能)再分发训练产物。两者之间隔着**版权(著作权)与许可**。
- 版权保护的是「表达」而不是「思想」:一段新闻、一本小说、一篇论坛回帖都可能自带权利人。**公开可见不等于权利人放弃权利**;页面底部的版权声明与平台服务条款,往往是在声明相反的意思。
- **为什么预训练绕不开它**:预训练的本质是把海量文本「复制」进参数——先整段读入,再压缩成权重;模型可能记忆并逐字复现训练片段,而权重与输出又会继续分发。一次数据使用因此同时触碰「复制、派生、再分发」三个受控动作,无法用「我只是读了它」来回避授权问题。
- **如果不做会怎样**:轻则收到删除或下架要求,项目被迫中断;重则面临诉讼与赔偿。自 2023 年起,针对训练语料的版权诉讼已在多个国家展开,文本、图像、音乐均有涉及;同一行为在不同司法辖区可能得到不同结论(「合理使用」主要存在于美国法)。教学项目也不自动豁免:成果一旦公开或再分发,就要按许可逐条核验。
- **动手前核对四项**:① 数据集自身的许可证;② 原始内容的版权归属;③ 是否含个人信息(PII);④ 平台条款与你所在地区、机构的规则。任何一项无法确认,都不应进入训练集(见 3.1)。
- **一个直觉例子**:你能在线阅读一篇报道的摘要,但这不给你复制全文用于训练的权利;同理,能从 Hugging Face 一键下载,不代表能商用——下载按钮验证的是网络连通性,不是法律。训练前把「能不能下载」与「能不能训练、能不能再分发」分开问,是本章最重要的习惯。

### 1.1 常见来源与风险对照

| 来源类型 | 常见风险 | 推荐处理 |
|---|---|---|
| 公共领域文本 | 版本与转录错误;公共领域判断因国家而异 | 保存来源链接与版本 |
| 明确开放许可证数据集 | 商业、署名、再分发限制 | 阅读 LICENSE 与 dataset card |
| 网页抓取 | 条款、版权、PII、robots 协议 | 不作为入门项目语料 |
| 企业内部数据 | 隐私、商业机密、访问权限 | 先脱敏并获得书面授权 |

## 2. Data Manifest:给每个数据源建立档案

### 2.1 Data Manifest 是什么、解决什么问题

- **概念**:Data Manifest(数据清单,通常是一个 `data/manifest.csv`)是描述每个数据源「从哪来、何时取得、授权边界是什么、当前处于什么状态」的机器可读记录。
- **为什么需要它**:训练几周后你会问自己三个问题——这个文件是谁、在哪天下载的?许可允许商用吗?清洗前的原始版本在哪?若答案只存在于聊天记录或记忆里,就等于没有答案。Manifest 把这些判断**外置成工件**,使数据治理可审计、可交接、可复现——这正是它与「在 README 里写两句」的本质区别。
- **它不是什么**:不是合规证明,也不替代阅读许可;它只是把你读许可时作出的判断**固定下来**。判断错了,记录再工整也无济于事——但至少错误可以被发现、被追溯。

### 2.2 manifest 的字段与含义

| 字段 | 含义 | 为什么记录 |
|---|---|---|
| source_id | 来源短标识 | 供清洗与代码稳定引用 |
| url | 来源地址 | 定位原始出处 |
| downloaded_at | 下载日期 | 数据会更新,日期锁定版本 |
| license_or_terms | 许可或条款 | 使用边界的依据 |
| allowed_purpose | 允许的用途 | 明确教学、研究、商业边界 |
| contains_pii | 是否含个人信息 | 风险提示字段 |
| raw_file | 原始文件路径 | 保证可回溯 |
| reviewer | 核验人 | 留下责任人与联系方式 |

### 2.3 本教程的练习数据:Project Gutenberg

- **推荐起步数据**:Tiny Shakespeare、Project Gutenberg 中已确认公共领域的文本,或 Hugging Face 上带明确许可与 dataset card 的小型语料。教学实验应优先追求**可解释与合规**,而不是数据量。
- 拿到一个 HF 数据集后,dataset card 是授权的第一现场,按四处读:license 标签(如 `apache-2.0`、`cc-by-4.0`)、「Intended uses & limitations」、数据来源与构建过程、讨论区是否有人报告版权或 PII 问题——全程五分钟,却决定了后续清洗与发布是否安全。
- **本教程的明确练习来源**:为使每个人都有相同输入,教程使用 Project Gutenberg 的 *Alice's Adventures in Wonderland*(编号 11)作为**技术练习样本**。它在美国属公共领域;但版权与数据库权具有**地域性**,下载前请阅读该站条款,并确认你的所在地、机构与未来用途允许使用。若不能确认,请改用你已获得书面授权的文本——后续命令不变。

在项目根目录执行:

```bash
curl -L https://www.gutenberg.org/files/11/11-0.txt -o data/raw/alice.txt
```

Windows PowerShell 的 `curl` 有时是别名。若上述命令失败,使用:

```powershell
Invoke-WebRequest 'https://www.gutenberg.org/files/11/11-0.txt' -OutFile 'data/raw/alice.txt'
```

下载后立刻校验文件不是 HTML 错误页:

```bash
python -c "from pathlib import Path; p=Path('data/raw/alice.txt'); print(p.exists(), p.stat().st_size); print(p.read_text(encoding='utf-8')[:80])"
```

预期是 `True`、一个大于 10 万的字节数,以及英文书名开头;若看到 `<html`、大小为 0 或网络错误,**不要继续做清洗**,先回到网络与来源问题。

### 2.4 手工创建机器可读的 manifest

创建 `data/manifest.csv`,复制一行表头和一行记录。`downloaded_at` 填当天日期,`reviewer` 填自己名字或代号:

```csv
source_id,url,downloaded_at,license_or_terms,allowed_purpose,contains_pii,raw_file,reviewer
gutenberg-11,https://www.gutenberg.org/ebooks/11,2026-09-02,Project Gutenberg License,local educational experiment,unknown,data/raw/alice.txt,student
```

这里的 `unknown` 不是「没有风险」,而是提醒你:未核验之前,不能把该数据用于公开产品。不要把原始文件放进公开仓库,也不要删除它来掩盖来源。

> [!example] 动手活动:建立数据清单
>
> **目标**:选择一个公开文本数据源,完成可审计的记录。
>
> **步骤**:下载前阅读其说明与 LICENSE;创建 `data/manifest.csv`;记录许可证链接、训练用途、是否允许再分发与数据版本;将原始文件保存至 `data/raw/`,不修改原件。
>
> **完成标准**:能用一段话说清「为什么该数据可以用于本次教学训练」,并能定位原始文件与许可证。

## 3. 边界与取舍:什么时候该停下来

### 3.1 停止条件

若许可证、组织规则或个人信息风险有任何一项**无法判断**,本章的正确操作是:停止将该来源加入训练集,并在 manifest 中把状态记为 `rejected` 并写明原因。模型效果不能成为绕过数据授权的理由——这一条在课程结束、进入真实项目后依然成立。

### 3.2 最小化原则

只收集完成目标**必需**的数据。Mini GPT 用一个小型、来源清楚的语料,就足以学会 token 化、损失下降与采样;盲目扩大数据不会补偿错误的训练代码,只会线性放大清洗成本与法律风险面。数据治理从下载前开始,而不是上线前补文档。

### 3.3 本章常见问题排查

| 现象 | 通常原因 | 处理 |
|---|---|---|
| 下载到的是 HTML 而非正文 | URL 过期、站点返回错误页 | 用浏览器打开该 URL 确认后再下载 |
| 文件大小为 0 或网络报错 | 网络中断或代理拦截 | 检查网络后重试,或改用 PowerShell 命令 |
| `manifest.csv` 找不到 | 在错误目录执行了命令 | 固定在项目根 `data/manifest.csv`,不移动 |
| 同一 `source_id` 出现两行 | 重复下载登记 | 保留最早记录并在备注合并 |

## 4. 总结

| 产物 | 用途 |
|---|---|
| 来源风险对照表 | 动手前判断每一类来源的授权边界 |
| manifest.csv | 把每个数据源的来源、许可与状态固定为机器可读工件 |
| 原始只读文件 | 保证清洗可追溯、可重跑 |

- 原始数据不可覆盖;清洗后的数据必须能追溯到原始版本;
- 许可证与使用目的一并记录,变更用途(如从教学转向商用)时重新评估。

**思考题**:① 数据集标注为开放许可,为什么仍要查看原始内容的来源与你的使用场景?② 为什么原始数据要保存为只读副本?③ 某网站条款写明「仅限个人学习使用」,能否把抓取内容用于一个将公开发布开源权重的 Mini GPT 训练?

> [!note] 参考答案
> ① 数据集发布者对其汇集内容拥有何种权利、许可证是否覆盖你的训练与再分发计划,需要分别确认;开放下载并不自动解决这些问题。② 保留原件使清洗结果可追溯、规则可重跑,也便于发现上游版本变化。③ 不能:训练成果(权重)会再分发,超出「个人学习」边界;条款不明时按 3.1 停止,换用授权清晰的语料。
