> 上一章训练出自己的 tokenizer,文字与整数 id 之间有了稳定映射;但模型真正消费的不是一段文字,也不是一串整数,而是**形状固定、成批出现的张量**。本章填平这段鸿沟,先回答三个问题——**为什么必须把文本变成 batch?x 与 y 为什么要右移一位?Dataset 与 DataLoader 各管什么?**——再动手把文本编码成 token 文件、写出能吐出 `(x, y)` batch 的 `src/data.py`。

**学习目标**:学完本章,你将能够——

1. 说清训练为什么必须喂 batch,而不是逐字符或整篇文本;
2. 解释输入 `x` 与标签 `y` 的右移一位关系,并说明为什么不能让两者相同;
3. 把清洗、切分后的文本编码为可复用的 token id 文件;
4. 编写返回固定上下文窗口的 `Dataset`,并区分它与 `DataLoader` 各自的职责;
5. 取出 batch 检查形状、dtype 与 id 边界,在训练前完成三道检查。

## 1. 为什么必须把文本变成 batch

- **概念**:数据管道(data pipeline)指「原始文本 → 定型 batch」的完整工序。第 05 章结束时我们有了 tokenizer(文字与 id 的映射);本章把 id 排成**样本**、把样本聚成 **batch**,使 batch 形状与模型的输入约定一致。它是语料与模型之间唯一的接口:管道出错,训练再久也学不到东西。
- **模型吃不了「一段文字」**:神经网络的输入是数值张量,一次前向要处理一批样本。文本必须先经 tokenizer 变为整数,再按固定窗口切成样本,最后堆叠成 `(batch_size, context_length)` 的整型张量,才能送入 embedding 层。
- **为什么不能一次只喂一个样本**:单个样本的梯度只是「这一个窗口」的噪声估计,方向抖动大;一批样本的梯度是多个窗口的平均,更接近真实方向,参数更新更稳。同时 GPU 的并行优势来自同时计算一大批样本——喂 1 个 token 与喂 1000 个 token 的耗时远小于 1000 倍,**把硬件喂饱,训练才划算**。
- **为什么不能喂整篇文本**:文档长度不一,而模型输入必须是定长张量(embedding 与注意力都按固定上下文 `T` 设计)。所以任何语料最终都要切成**等长窗口**;第 01 章配置里的 `context_length: 128` 就是窗口宽度。
- **取舍**:batch 越大,梯度越稳、硬件利用率越高,但显存占用线性增长,每个 epoch 的参数更新次数也变少。`batch_size=16`、`context_length=128` 是教学规模的平衡点,也是实验卡里定下的预算,不要擅自加大到显存撑不住。

## 2. 一个样本长什么样:x 与 y 右移一位

设一段 token 为 `[14, 38, 9, 21, 7]`,上下文长度 `T=4`。模型的任务是「根据前文预测下一个 token」,于是同一段 token 被切成两个错开一位的张量:

| 名称 | 内容 | 模型任务 |
|---|---|---|
| `x`(输入) | `[14, 38, 9, 21]` | 已经看见的 token |
| `y`(标签) | `[38, 9, 21, 7]` | 每个位置的下一个 token |

- **为什么必须右移一位**:监督信号是「下一个 token」——位置 `i` 的标签必须是模型看完 `x[0..i]` 后应预测出的 token,即 `x[i+1]`。切片写法一步到位:`x, y = chunk[:-1], chunk[1:]`,或逐位验证 `y[i] == x[i + 1]`。
- **为什么不能让 `x` 与 `y` 相同**:若输入与标签一模一样,模型只需学会恒等复制(把输入原样输出)就能把 loss 压到接近 0;但复制不是预测,生成时面对从未见过的前文会立刻失效。**标签必须永远比输入晚一步,模型学的才是预测,而不是复读。**
- 模型一次输出 `T` 个位置上的词表概率,交叉熵会**逐位置**把输出与 `y` 比较;因此 `x` 与 `y` 的形状必须完全一致,否则 logits 与标签无法对齐(第 5 节三道检查之一)。
- **文档边界**:语料若由多篇独立文档构成,应在文档之间插入 `<eos>`,让模型学会「一篇内容结束」的位置。训练、验证、测试必须**各自编码,且始终使用同一份 tokenizer**;文档边界与长文本截断策略要写进配置,方便复查。

## 3. 先制作可检查的 token 文件

本课程的简单方案:把第 04 章切分出的每个子集(如 `train.txt`)分别编码成一维 `.pt` 文件。**训练、验证、测试必须各自编码,且始终使用同一份 tokenizer。** 建议目录如下:

```text
data/
  processed/train.txt
  tokenized/train.pt
  tokenized/valid.pt
artifacts/tokenizer.json
src/data.py
```

编码脚本的核心是**保存整数张量,而不是 Python 字符串或 list**:`torch.load` 后直接得到可切片的 `torch.Tensor`,后续 Dataset 只做张量切片,零转换开销。若语料由多篇独立文档构成,应在文档之间插入 `<eos>`,让模型学会一篇内容结束的位置:

```python
from pathlib import Path
import torch
from tokenizers import Tokenizer

tokenizer = Tokenizer.from_file("artifacts/tokenizer.json")
eos_id = tokenizer.token_to_id("<eos>")

def encode_file(source: str, target: str) -> None:
    text = Path(source).read_text(encoding="utf-8")
    ids = tokenizer.encode(text).ids + [eos_id]
    torch.save(torch.tensor(ids, dtype=torch.long), target)

encode_file("data/processed/train.txt", "data/tokenized/train.pt")
```

- 这里的 `torch.long` 很重要:PyTorch 的嵌入层与 `cross_entropy` 都要求类别 id 是整型,浮点 id 会在第一次前向就报 dtype 错误。
- 编码完成后打印 token 总数与前 20 个 id,并把它们 decode 回文字抽查,确认「文字 → id → 文字」没有走样。

## 4. Dataset 与 DataLoader:职责必须分清

- **概念**:`Dataset` 回答「给定一个索引,返回一个样本」;`DataLoader` 回答「把许多样本聚成一个 batch,按什么顺序送出」。前者定义**样本长什么样**,后者定义**批怎么组**:

| 组件 | 职责 | 不负责 |
|---|---|---|
| `Dataset` | `__len__` 报告样本总数;`__getitem__` 按索引切出 `(x, y)` | 打乱、聚批、并行加载 |
| `DataLoader` | 按 `batch_size` 聚批、按 `shuffle` 决定顺序、多进程预取 | 样本内部结构、窗口怎么切 |

- **为什么必须拆成两层**:样本规则与批策略是两类独立的变化方向。改窗口长度、是否插 EOS,只动 `Dataset`;改批量、是否打乱、要不要多进程,只动 `DataLoader`。训练与验证可以复用同一个 `Dataset`,却各自配置 loader(验证集 `shuffle=False`)。
- **shuffle 打乱的是什么**:`shuffle=True` 随机排列的是**窗口的送出顺序**,绝不是重新切分 train/valid/test——那是第 04 章的职责,把两者混为一谈会让验证集「泄题」。相邻两个窗口仍可能来自同一篇文档,这是随机窗口方案的已知特性,教学规模下可接受。
- **样本计数与右移的实现**:`__len__` 返回 `len(ids) - context_length`,即 token 流里所有可能的窗口起点数;窗口彼此重叠是允许且正常的。`__getitem__` 从 `index` 处切出 `context_length + 1` 个 token,再用 `chunk[:-1]` 与 `chunk[1:]` 两个切片一步完成右移:

```python
import torch
from torch.utils.data import Dataset, DataLoader

class NextTokenDataset(Dataset):
    def __init__(self, token_ids: torch.Tensor, context_length: int):
        self.ids = token_ids
        self.context_length = context_length
        if len(self.ids) <= context_length:
            raise ValueError("token 数必须大于 context_length")

    def __len__(self) -> int:
        return len(self.ids) - self.context_length

    def __getitem__(self, index: int):
        chunk = self.ids[index:index + self.context_length + 1]
        return chunk[:-1], chunk[1:]

ids = torch.load("data/tokenized/train.pt", weights_only=True)
dataset = NextTokenDataset(ids, context_length=128)
loader = DataLoader(dataset, batch_size=16, shuffle=True, drop_last=True)
x, y = next(iter(loader))
print(x.shape, y.shape, x.dtype)  # torch.Size([16, 128]) 两者均为 long
```

- `drop_last=True`:样本总数未必整除 `batch_size`,丢弃末尾不满一组的部分,保证每个 batch 形状严格是 `[16, 128]`。
- 验证集的 loader 一般设 `shuffle=False`,让每次评估看到同一批窗口,验证 loss 才可稳定对比。
- **本章不需要 padding 与 attention mask**:每个窗口等长,天然是规则的矩形张量。等以后遇到长度不一的样本才需要 padding,且损失函数必须忽略 pad token(第 08 章训练循环再处理)。

### 4.1 创建本项目真正使用的 `src/data.py`

前一节的片段请整理为下面这个完整文件。它同时负责「文本编码」与「取窗口」,下一章的训练脚本会直接导入它:

```python
from pathlib import Path
import torch
from tokenizers import Tokenizer
from torch.utils.data import Dataset, DataLoader

class NextTokenDataset(Dataset):
    def __init__(self, token_ids: torch.Tensor, context_length: int):
        if token_ids.dtype != torch.long:
            raise TypeError("token ids 必须是 torch.long")
        if len(token_ids) <= context_length:
            raise ValueError("token 数必须大于 context_length")
        self.ids = token_ids
        self.context_length = context_length
    def __len__(self):
        return len(self.ids) - self.context_length
    def __getitem__(self, index):
        chunk = self.ids[index:index + self.context_length + 1]
        return chunk[:-1], chunk[1:]

def encode_split(split: str, tokenizer_path="artifacts/tokenizer.json"):
    tokenizer = Tokenizer.from_file(tokenizer_path)
    text = Path(f"data/processed/{split}.txt").read_text(encoding="utf-8")
    eos_id = tokenizer.token_to_id("<eos>")
    ids = tokenizer.encode(text).ids + [eos_id]
    output = Path(f"data/tokenized/{split}.pt")
    output.parent.mkdir(parents=True, exist_ok=True)
    torch.save(torch.tensor(ids, dtype=torch.long), output)
    print(split, "tokens=", len(ids), "saved=", output)

if __name__ == "__main__":
    encode_split("train")
    encode_split("valid")
    train_ids = torch.load("data/tokenized/train.pt", weights_only=True)
    loader = DataLoader(NextTokenDataset(train_ids, 128), batch_size=16, shuffle=True, drop_last=True)
    x, y = next(iter(loader))
    print("x", x.shape, x.dtype, "y", y.shape, y.dtype)
```

从项目根目录执行 `python src/data.py`:预期依次出现 train、valid 的 token 数和 `torch.Size([16, 128])`。若报 `token 数必须大于 context_length`,说明数据量不足:先把 `context_length` 暂改为 64,并在实验记录里写明这个决定;**不要凭空重复训练数据**。

## 5. 在模型前建立三道检查

「直接开始训练」会把管道错误与模型错误混在一起,难以排查;先把以下三项跑通,能比训练更早发现问题:

1. `x.min() >= 0` 且 `x.max() < vocab_size`,否则 embedding 查表会越界;
2. `x.shape == y.shape == (batch_size, context_length)`,否则 logits 与标签无法对齐;
3. decode 几条窗口,确认没有乱码、整段重复或意外混入验证集文本。

若总 token 数很少,`context_length=128` 可能使可用窗口不足——这是**数据量不足的信号**,不应用复制同一行文本来「补数据」。可以先降低上下文长度完成教学实验,并在实验记录中说明限制。

| 现象 | 先检查 | 通常原因 |
|---|---|---|
| `token 数必须大于 context_length` | 打印 token 总数 | 语料太小或窗口太长;降 `context_length` 并记录 |
| `x.max()` 大于等于词表大小 | 检查编码与词表 | 编码用了旧 tokenizer,或 id 未重新映射 |
| decode 出现乱码 | 抽查原始文本 | 编码与解码路径不一致,或文件编码不是 UTF-8 |
| 最后一个 batch 形状不是 `[16, 128]` | 检查 loader 参数 | 忘了 `drop_last=True` |

## 6. 总结

| 产物 | 用途 | 必查项 |
|---|---|---|
| `train.pt` / `valid.pt` | 已编码的 token 流 | `long`、来源切分正确 |
| `NextTokenDataset` | 产生输入/下一词标签 | 右移一位 |
| `DataLoader` | 产生 batch | shape、id 范围、样本抽查 |

常见误区:因果语言模型的 mask 不是在 `Dataset` 里把未来 token 删掉;训练样本中的 `y` 本来就包含「答案」,真正防止模型偷看未来的,是下一章注意力层里的 causal mask——**管道负责把样本喂对,防泄漏由模型结构负责**。

**思考题**:为什么验证集也要经过 tokenizer,却不能参与 tokenizer 训练?如果把 `<eos>` 完全省略,生成多篇独立文本时可能发生什么?

> [!note] 参考答案
> tokenizer 必须对所有输入使用同一套 id 语义;但若用验证文本学习子词合并规则,验证信息会泄漏进 tokenizer,验证分数虚高。没有 EOS 时,模型更难学会「自然结束」,可能把相邻文档当成一篇连续生成。
