> 上一章我们认识了神经网络:它是一台从数据里学出来的「函数机器」,吃进去的是数字,吐出来的是预测。但用户给模型的是中文、英文、代码、表情——**文字不会自己变成数字**。本章回答这条流水线的第一公里:文字如何被切成 token,又如何变成携带语义的向量(embedding)。这是理解上下文窗口、API 计费与 RAG 检索的必备基础。

**学习目标**:学完本章,你将能够——

1. 解释为什么神经网络读不了原始文字,以及 one-hot 方案为什么行不通;
2. 描述 token 与 tokenization,用 BPE 的「合并」思路说明「常见词一个 token、罕见词被拆分」;
3. 估算同一段中文、英文、代码、表情的 token 数差异,并解释 token 数如何影响上下文窗口、计费、延迟与截断;
4. 说清 embedding 是什么、从哪里来,区分 token embedding 与文本 embedding,并指出「位置信息缺失」这个关键问题;
5. 用余弦相似度解释向量检索,说明向量数据库与 RAG 各自解决什么问题。

## 1. 概念:模型为什么读不了文字

### 1.1 神经网络的输入只能是数字

- 神经网络内部全是矩阵乘法与激活函数(见 03 章),**只能对浮点数做运算**;而文字是离散符号,没有天然的数值大小。因此任何 NLP 模型的第一件事都是**数值化**:把文字变成数字再送入网络——这串数字的质量,直接决定后面所有层能学到什么。

### 1.2 最朴素的方案:one-hot 编码,以及它为什么失败

- 给词表里每个词一个编号,再把编号展开成「只有一个位置是 1、其余全是 0」的向量,就是 **one-hot 编码**:词表为 ["猫","狗","飞机"] 时,猫 → `[1,0,0]`、狗 → `[0,1,0]`、飞机 → `[0,0,1]`。
- 它有两个致命问题,也正是本章两个主角(Token 与 Embedding)要解决的:
  1. **维度爆炸**:词表 10 万词就要 10 万维向量,存储和计算都不可接受;
  2. **无语义距离**:任意两个 one-hot 向量的夹角都一样——「猫」与「狗」的距离,竟然和「猫」与「飞机」完全相同,模型无从知道谁和谁更像。

## 2. Token 与 Tokenization:把文字切成子词

### 2.1 概念:什么是 token

- **Tokenization(分词)**是把原始文本切成一个个小单元的过程,切出的每个单元叫一个 **token**。下游一切环节(上下文窗口、计费、延迟)都以 token 为单位。
- 切多细合适?三种粒度各有代价:

| 切分粒度 | 做法 | 优点 | 致命缺点 |
|---|---|---|---|
| 按词 | 按空格/标点切整词 | 语义完整、token 少 | 词表爆炸;中文没有空格;新词(如 `ipod`)无解 |
| 按字符/字节 | 每个字符一个 token | 词表极小、永无生词 | token 数暴涨,信息被切碎,模型难以学习 |
| **子词(Subword)** | 常见词整块保留、罕见词拆碎 | 词表有限且无生词 | 需要额外学习合并规则 |

- 今天所有主流模型(GPT、Llama、BERT)都采用**子词方案**。它同时解决了「词表爆炸」与「生词无处安放」这对矛盾。

### 2.2 详细介绍:BPE 与 WordPiece 的「合并」思想

- **BPE(Byte-Pair Encoding)**源自 2016 年机器翻译论文《Neural Machine Translation of Rare Words with Subword Units》,核心思想就一个字:**合并**。
  1. 先把语料拆到字符级:`l o w e r`;
  2. 统计所有相邻字符对的出现频率,把最高频的一对合并成新单元(如 `l+o→lo`);
  3. 反复合并,直到词表达到预设大小(如 3 万~13 万)。
- 训练完成后,切词规则也固定了:**能整块匹配词表就整块,匹配不到就递归拆小**。例如 `lower → [lower]`(常见词 1 个 token)、`lowest → [low, est]`(罕见词拆两块)、`ipod → [i, pod]`(没见过的词也能拼出来,没有 [UNK])。

- **WordPiece**(BERT 使用)与 BPE 思路类似,只是合并时按「能带来多少信息增益」打分;GPT 系列用的是 **byte-level BPE**:先按 UTF-8 把文本变成字节再合并,因此任何文字、符号、emoji 都能被表示,彻底消灭「未登录词」。词表规模参考:GPT-4 约 10 万(cl100k_base),Llama 3 约 12.8 万,BERT 约 3 万。
- 一句话总结:**Tokenization 解决的是「词表无限但模型词表有限」的矛盾——把语言的无限可能性,压进一个有限大小的词表里。**

### 2.3 为什么中文、代码、表情的 token 数和直觉不同

- 英文:空格天然分词,高频词与常用后缀(如 `fast`、`er`)常被合并成整块,平均 **1 个词 ≈ 1~2 个 token**(OpenAI 经验值:100 token ≈ 75 个英文单词)。
- 中文:没有空格,汉字组合接近无限,BPE 只能把高频相邻字对(如「我们」「模型」)合并成词;实测 **1 个汉字 ≈ 1~2 个 token**(生僻字更多)。所以同样 8K 的窗口,大约只能装下 4000~5000 个汉字。
- 代码与表情:代码的空格、缩进、运算符、换行全部计入 token,超长标识符会被拆碎;一个 emoji 由多个字节/码点复合而成,动辄占 **2~3 个甚至更多 token**,一串 🎉🎉🎉 可能比整句话还贵。

## 3. 作用:token 数决定成本与能力边界

- **为什么工程上必须盯紧 token 数?** 因为它同时决定四个指标:

| 影响项 | 机制 |
|---|---|
| 上下文窗口 | 窗口以 token 计数,超长即放不下(回忆 01 章:模型无真实记忆,全靠窗口) |
| 计费 | 各家 API 按「输入 token + 输出 token」计价,省 token 就是省钱 |
| 延迟 | 生成速度约等于「每秒吐多少 token」,输入越长首字越慢 |
| 截断 | 超过窗口的内容被静默丢弃,可能导致回答遗漏关键信息 |

- 实操建议:**先用 tokenizer 实测再优化**。各模型都有官方计数工具(如 OpenAI 的 Tokenizer 页面与 tiktoken 库),别凭「字数」猜,中文尤其容易低估。经验换算口诀:100 token ≈ 75 个英文单词 ≈ 50~60 个汉字——提示词与文档越精炼,留给模型思考与回答的空间越大。

## 4. 概念:Embedding,给 token 一个语义坐标

### 4.1 概念:token → 向量,语义相近则向量相近

- **Embedding(嵌入)**把每个 token 映射成一个**固定维度的稠密向量**(例如 4096 维的浮点数组),作为神经网络的第一层输入:`文本 → Tokenizer → [token, …] → 查表 → [向量₁, 向量₂, …]`。
- 它的核心性质:**语义相近的 token,向量在空间里也相邻**。「猫」的向量离「狗」近、离「飞机」远。经典例子来自 word2vec(2013):`国王 − 男人 + 女人 ≈ 女王`——词向量之间居然能做语义加减法。
- 生活化类比:把向量空间想成一张「语义地图」,每个词是一个坐标点——同义词是邻居,反义词隔着马路,无关词天各一方;「猫追狗」这句话,就是地图上一串依次点亮的路标。

### 4.2 为什么需要它:one-hot 的两个缺陷被同时修复

- 维度爆炸被压缩(词表 10 万 → 每个 token 只需 4096 维),**无语义距离**被修复(向量夹角可算相似度,模型从第一层起就「知道」猫狗相近);
- 更深一层:向量不是人设计的,**是训练中学出来的表示**——这正是 03 章「表示学习」的形态:神经网络在调整参数的同时,也在调整每个词的坐标。

### 4.3 详细介绍:embedding 从哪里来

- 训练开始时,模型会初始化一张 **token embedding 矩阵**,形状为 `[词表大小 × 隐藏维度]`;前向计算时,把 token 的整数 ID 当作**行号**,取出对应那一行向量,就是查表(查表不可训练,训练的是矩阵里的数值)。
- 矩阵随机初始化后,随反向传播被梯度下降不断更新(03 章的四步循环):一句话让模型预测错了,就把这句话里所有词的坐标往「更对」的方向微调一点。**所谓语义,是模型在海量语料上「撞」出来的统计规律。**
- 关键参数:词表大小与隐藏维度。维度并非越大越好——维度翻倍,参数量翻倍,训练与推理成本同步上升。举例:

| 模型(举例) | 词表大小 | 隐藏维度 | embedding 矩阵参数量 |
|---|---|---|---|
| GPT-2 small | 50,257 | 768 | ≈ 3860 万 |
| Llama 3 8B | 128,256 | 4096 | ≈ 5.25 亿(约占 8B 参数的 6%) |

- 值得记住:embedding 层往往是**最大的单层参数块**之一,但它只做「查表」,真正的智能来自它之上的那些层。

### 4.4 token embedding 与文本 embedding

| 对比项 | token embedding | 文本 embedding(句子/段落向量) |
|---|---|---|
| 对象 | 词表里的单个 token | 一段完整的文本 |
| 怎么得到 | LLM 内部的 embedding 层查表 | 专用模型编码后池化,或调 API(如 OpenAI text-embedding-3-small,1536 维) |
| 典型用途 | 作为 LLM 每一层计算的起点 | 语义检索、聚类、去重、推荐 |
| 谁来训练 | 随 LLM 预训练一起 | 专门的对比学习目标(让相似句子靠近) |

- 一句话:**token embedding 在模型「里面」当输入;文本 embedding 在模型「外面」当工具。**

### 4.5 位置信息缺失:一个必须预告的问题

- 查表的结果与顺序无关:「猫追狗」与「狗追猫」的 token 集合完全相同,逐 token 查表得到的向量也一模一样——但两句意思相反。**embedding 只回答了「有哪些词」,没回答「词以什么顺序出现」**;模型必须额外注入位置信息(位置编码),并让词与词之间能按需交换信息——这正是下一章**注意力机制**登场的理由。

## 5. 作用:向量检索、向量数据库与 RAG

### 5.1 余弦相似度:怎么度量「语义近不近」

- 两个向量的相似度,常用**余弦相似度**度量——只看方向夹角,不看长度:`cos(θ) = (a·b) / (|a||b|)`。
- 夹角越小,余弦值越接近 1,语义越相近。为什么不用欧氏距离?因为向量长度往往只反映「文本长度/语气强度」这类无关信息;且主流 API 返回的向量已归一化(长度为 1),此时余弦相似度退化为一次点积,计算极快。
- 有了相似度,「找意思相近的文本」就变成了「找夹角最小的向量」——这是一个纯数学问题,机器可以毫秒级完成。

### 5.2 向量数据库与 RAG 基础

- 当文本量达到百万级,逐一计算余弦相似度太慢,于是有了**向量数据库**(如 Milvus、pgvector、Chroma):用近似最近邻算法(ANN)建索引,在毫秒级返回 Top-K 最相似向量。
- 这直接支撑了 **RAG(检索增强生成)**——01 章提到的「用检索给模型补事实」的落地方式:
  1. 离线建库:文档 → 切块 → 文本 embedding → 存入向量数据库;
  2. 用户提问 → 同样转成 embedding → 余弦检索 Top-K 片段;
  3. 把检索片段与问题一起拼进提示词;
  4. LLM 依据片段生成答案。
- RAG 解决的是 LLM 的三个先天短板:**事实易错**(幻觉)、**知识过时**(训练截止日)、**没有私有知识**(内部文档、实时数据)。Embedding 质量直接决定检索质量,进而决定答案上限。

### 5.3 场景与提醒

- 典型场景:语义搜索(搜「怎么退款」能命中「取消订单政策」)、文档去重、客服知识库、代码检索、推荐系统。但需清醒:**相似 ≠ 事实相关**——「冷」与「热」向量可能很近,相似度只是「可替换性」的近似,不是逻辑判断;embedding 模型要按语言与领域选型,中文场景须验证多语效果并做真实查询评测。

## 6. 总结

### 6.1 本章一览

| 概念 | 一句话 |
|---|---|
| 数值化 | 神经网络只吃数字,文字必须先转成数值 |
| Token | 文本切分出的最小单元;子词方案兼顾词表大小与生词问题 |
| BPE | 从字符开始、反复合并高频相邻对的子词算法 |
| token 数 | 决定窗口、计费、延迟、截断;中文/代码/emoji 与直觉不同 |
| Embedding | token 的稠密向量坐标;语义相近则向量相近;训练中查表学出 |
| 向量检索 | 余弦相似度 + 向量数据库 = 毫秒级语义搜索,是 RAG 的地基 |
| 位置缺失 | 查表与顺序无关,词序信息要靠位置编码与注意力补上 |

### 6.2 思考题

1. 为什么说 one-hot 编码下「猫」与「狗」的距离和「猫」与「飞机」一样?这个缺陷会造成什么后果?
2. 若 BPE 已把 `low`、`er` 合并进词表,推测 `lower` 会被切成几个 token?`lowest` 呢?为什么「永远没有生词」?
3. 你的提示词约 2000 个汉字,模型上下文窗口为 8K token,按 1 汉字 ≈ 1.5 token 估算,还留多少空间给回答?这解释了中文用户的什么日常痛点?
4. 「猫追狗」与「狗追猫」token 完全相同。若模型只看 embedding 不看位置,会发生什么?工程上由哪些机制解决?
5. 为什么 RAG 用「语义相似」而不是「关键词匹配」?举一个关键词匹配会失败的查询例子。

> [!note] 参考答案
> 1. one-hot 任意两词夹角都相同(正交),模型没有任何先验知识区分相关与无关词;学习「猫吃鱼」的规律无法迁移到「狗吃骨头」。
> 2. `lower → [lower]`(1 个);`lowest → [low, est]` 或 `[low, e, st]`(2~3 个)。子词方案能把任意新词拼出来,最多拆到字符/字节级,所以没有 [UNK]。
> 3. 2000 × 1.5 = 3000 token 输入,剩约 5000 token ≈ 3300 个汉字;同容量下中文能表达的内容远少于英文,长文档场景需切块与摘要。
> 4. 模型分不清施事与受事,可能把两句话当一回事;需要位置编码标记先后 + 注意力机制按需关联,详见 05、06 章。
> 5. 关键词匹配对同义表达失效,如搜「怎么退货」难以命中只写了「退款流程」的文档;语义检索靠向量相似度能跨词面找到意思相近的内容。
