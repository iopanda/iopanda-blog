# 自动化指标

> 上一章人工审核出了 15~20 条黄金样本,但人审很贵、很慢——每改一次 prompt、每训一版 adapter 都重新找人来判,工程上不可行。本章把「判定对错」交给代码:只要任务能变成「判对错、比词面、查格式」,程序化指标就能自动打分,让评测从偶尔一次的人工评审,变成每次改动都自动跑的回归测试。

**学习目标**:学完本章,你将能够——

1. 说出程序化指标适合的三类任务(分类、生成、结构化)及各自的默认指标;
2. 用混淆矩阵讲清精确率、召回率、F1,并指出准确率在类别不平衡时的欺骗性;
3. 解释 ROUGE 系列的直觉(词面重叠、最长公共子序列),知道它对合法改写会误判;
4. 说明 BLEU 与 BERTScore 的适用场景,以及「相似不等于正确」的盲点;
5. 写出 `eval_metrics.py`:对黄金集输出 accuracy、F1、ROUGE-L、JSON 通过率,并附一段「指标盲点说明」。

## 0. 本章为什么存在

黄金集只解决了「拿什么当标准答案」。真正要回答的问题是:模型每次改动后,谁来判它变好还是变坏?人工逐条审太慢,靠感觉更不可靠;程序化指标用代码做确定性的自动判分,把评测嵌进开发循环——每次提交都重跑一遍,分数下降就拦下。它是 01 章分层评测的最底层:往上依次是 LLM 裁判(04 章,判语义)与人工审核(最终仲裁);层越往下跑得越勤、越便宜,判不了的问题逐级上抛。

## 1. 概念:什么是程序化指标

程序化指标是一个**确定性函数**:输入是「模型输出 + 黄金集参考答案 + 任务定义」,输出是一个或一组分数。同一输入永远得到同一分数,不依赖任何人或模型的心情。按黄金集的任务类型,它分成三类:

| 任务类型 | 黄金集例子 | 判什么 | 默认指标 |
|---|---|---|---|
| 分类题 | 「主键的性质」选择题、拒答判定 | 判得对不对 | 准确率、F1 |
| 生成题 | 「用一句话解释外键」 | 答得像不像参考答案 | ROUGE / BLEU / BERTScore |
| 结构化题 | 「用 JSON 输出三个要点」 | 结构、字段、类型对不对 | JSON 校验通过率 |

## 2. 为什么需要:便宜、即时、可复现

**便宜**:跑一次只是几行代码的 CPU 开销; **即时**:毫秒级出分,不用排队等人工; **可复现**:确定性函数,昨天的分数今天还能一比。这三个特性支撑起**回归工作流**:每次改动提交后,CI 自动重跑 `eval_metrics.py` 并与基线对比,分数下降就拦下这次改动——没有它,「上一版好还是这一版好」只能靠记忆和感觉。评测数字随之沉淀成可追踪的记录(呼应 01.02 第 10 章的实验追踪纪律)。

## 3. 分类题:从混淆矩阵到 F1

以课程助教最有价值的二分类为例:「这条消息该不该拒答?」模型的判定与事实构成四种情况;四个公式是本章的地基:

|  | 事实上该拒(敏感/泄题) | 事实上该正常回答 |
|---|---|---|
| 模型拒了 | TP:正确地拒了敏感题 | FP:误伤——把「什么是外键」也拒了 |
| 模型答了 | FN:漏拒——把泄题也答了(最危险) | TN:正常作答 |

- 准确率 = (TP + TN) / 总数——全部判定里对的比例;
- 精确率 P = TP / (TP + FP)——模型说「拒」的里面,真正该拒的比例;
- 召回率 R = TP / (TP + FN)——所有该拒的里面,真被拒掉的比例;
- F1 = 2PR / (P + R)——P 与 R 的调和平均,想要单一数字时用。

**何时用哪个**:类别均衡、只看总正确率用 accuracy;「答出来就要靠谱」、误伤代价高时盯精确率;「漏掉比误伤更严重」(泄题、危险内容)时盯召回率;类别不平衡、想要单一数字,用 macro-F1 或拒答类 F1。**盲点**:假设黄金集 20 条里 18 条常规题、2 条拒答题,常规题全对、拒答题全漏——accuracy 是 0.90,看起来很好,最危险的一类却一条没守住:accuracy 被多数类「灌满」了,必须按类别看 P/R/F1。这就是「F1 只适合均衡分类」的真正含义:不平衡时,单看总分没有意义。

## 4. 生成题:ROUGE、BLEU、BERTScore 与各自盲点

生成题没有唯一答案,只能拿模型输出与黄金集的参考答案「比」;三个指标的区别在于**比什么**:

**ROUGE**(Lin, 2004):数词面 n-gram 重叠,偏召回。常用 ROUGE-1(单词)、ROUGE-2(双词)、ROUGE-L;其中 ROUGE-L 用**最长公共子序列(LCS)**,输出语序被打乱时分数会掉,适合「要点有没有覆盖到」的题目。盲点:它只认词面——模型把「外键是引用另一张表主键的字段」说得完全正确,只是用词和参考答案不同,分数照样低;反过来,「主键允许重复」这种事实错误因为词面相似,分数反而可能很高。

**BLEU**(Papineni 等, 2002):n-gram 精确率加长度惩罚,偏精确,出身是机器翻译。盲点:合法改写会被罚分;输出比参考短直接扣分;句子一短,漏一个词就可能归零。如今它主要留在机器翻译基准(系统级与人工判断仍有 0.78~0.91 的相关性),用来评开放式问答意义不大。

**BERTScore**(Zhang 等, 2019):用 BERT 把输出与参考编码成向量,逐 token 算余弦相似度后汇总,能认出同义改写。盲点:**它是相似度,不是事实核查**——「主键唯一」与「主键可重复」在向量上很接近,照样拿高分;一段流畅但纯属编造的内容,只要词面「像话」也可能拿中高分。另外每次要跑一个编码器,离线环境需先下载模型。

结论:任何单一指标都能被「用词技巧」骗过,所以评测报告从不只报一个分数——动手环节的「指标盲点说明」就是为此而写。

## 5. 结构化题:JSON 校验

课程助教要求「以 JSON 输出」的格式题,判分不是比词面而是查结构,分三关:一、能解析(`json.loads` 不抛异常);二、必需字段齐全(如要有 `points`);三、值类型正确(要求字符串数组,给 `[1, 2, 3]` 就不算过)。「能解析」只是第一关——很多模型能输出合法 JSON,却把字符串数组填成数字或对象。这类检查最机械也最易手滑,应单独做成函数(见第 6 节 `run_json`),逐关返回通过与不通过。

## 6. 动手:创建并运行 eval_metrics.py

在项目根目录创建 `eval_metrics.py`,复制如下内容;随后依次执行 `pip install rouge-score jieba` 与 `python eval_metrics.py`:

```python
# eval_metrics.py — 黄金集自动化指标:accuracy/F1 + ROUGE-L + JSON 校验。
import json
from pathlib import Path
from rouge_score import rouge_scorer
from rouge_score.tokenizers import Tokenizer

GOLDEN = "data/golden.jsonl"  # 02 章产物;路径不同改这一行,缺文件时退回演示样本
DEMO = [
    {"id": "q1", "type": "mcq", "expected": "唯一标识一行", "predicted": "唯一标识一行"},
    {"id": "q2", "type": "mcq", "expected": "另一张表的主键", "predicted": "任意字段"},
    {"id": "q3", "type": "mcq", "expected": "先处理子表再删父表", "predicted": "先处理子表再删父表"},
    {"id": "q4", "type": "refusal", "should_refuse": True, "refused": True},
    {"id": "q5", "type": "refusal", "should_refuse": True, "refused": False},  # 漏拒
    {"id": "q6", "type": "refusal", "should_refuse": False, "refused": False},
    {"id": "q7", "type": "refusal", "should_refuse": False, "refused": True},  # 误伤
    {"id": "s1", "type": "short", "expected": "外键是子表中引用父表主键的字段",
     "predicted": "外键是引用另一张表主键的字段"},
    {"id": "j1", "type": "json", "expected": "points: 非空字符串数组",
     "predicted": '{"points": [1, 2, 3]}'},  # 类型错:元素是数字不是字符串
]

def load_rows():
    if Path(GOLDEN).exists():
        return [json.loads(x) for x in Path(GOLDEN).read_text().splitlines() if x.strip()]
    print(f"[提示] 未找到 {GOLDEN},改用内置演示样本(9 条)。")
    return DEMO

def zh_tokens(text):  # 中文先分词,否则 ROUGE 把整句当一个词
    try:
        import jieba
        return " ".join(jieba.cut(text))
    except ImportError:
        return " ".join(text)  # 无 jieba 时按字切分,仅作演示

class ZhTokenizer(Tokenizer):
    # rouge-score 默认分词只保留 a-z0-9,中文会被全部丢弃,须自定义
    def tokenize(self, text):
        return text.split()

def run_classification(rows):
    mcq = [r for r in rows if r["type"] == "mcq"]
    ref = [r for r in rows if r["type"] == "refusal"]
    if mcq:
        acc = sum(r["predicted"] == r["expected"] for r in mcq) / len(mcq)
        print(f"分类题 accuracy = {acc:.2f} ({len(mcq)} 条)")
    if not ref:
        print("无拒答题,跳过 P/R/F1。")
        return
    tp = sum(r["should_refuse"] and r["refused"] for r in ref)
    fp = sum(not r["should_refuse"] and r["refused"] for r in ref)
    fn = sum(r["should_refuse"] and not r["refused"] for r in ref)
    p = tp / (tp + fp) if tp + fp else 0.0
    r = tp / (tp + fn) if tp + fn else 0.0
    f1 = 2 * p * r / (p + r) if p + r else 0.0
    print(f"拒答 P = {p:.2f}  R = {r:.2f}  F1 = {f1:.2f} (TP={tp} FP={fp} FN={fn})")

def run_rouge(rows):
    scorer = rouge_scorer.RougeScorer(["rougeL"], tokenizer=ZhTokenizer())
    for r in [x for x in rows if x["type"] == "short"]:
        rs = scorer.score(zh_tokens(r["expected"]), zh_tokens(r["predicted"]))
        print(f"{r['id']} ROUGE-L = {rs['rougeL'].fmeasure:.2f}")

def run_json(rows):
    ok = total = 0
    for r in [x for x in rows if x["type"] == "json"]:
        total += 1
        try:
            points = json.loads(r["predicted"]).get("points")
            if isinstance(points, list) and points and all(isinstance(x, str) for x in points):
                ok += 1
        except json.JSONDecodeError:
            pass
    print(f"JSON 格式题通过率 = {ok}/{total}")

BLIND_SPOTS = """指标盲点说明:
1. accuracy 会被多数类淹没:拒答题只占少数时,它们全错准确率也可能很高;
2. ROUGE/BLEU 只量词面:s1 语义正确,改写后分数仍被低估;
3. 相似不等于正确:流畅但编造的回答可能拿到高分,勿只报单一分数。"""

if __name__ == "__main__":
    rows = load_rows()
    run_classification(rows)
    run_rouge(rows)
    run_json(rows)
    print(BLIND_SPOTS)
```

> [!example] 动手活动:程序化指标回归
>
> **目标**:提交一份可重复的自动化指标输出与「指标盲点说明」。
>
> **步骤**:先跑通内置演示样本(9 条);再把 `GOLDEN` 指向 02 章的 `golden.jsonl`,对真实黄金集重跑;逐行解释四个数字(accuracy、拒答 F1、ROUGE-L、JSON 通过率)各自在说什么;把输出追加到评测记录文件(如 `reports/metrics-回归-1.txt`)。
>
> **完成标准**:脚本能对黄金集输出全部四类结果;学生能说明为什么「拒答 F1」比 accuracy 更能代表安全表现;能举例说出 ROUGE-L 在哪些输出上会误判;盲点说明里包含本章提到的三类盲点(不平衡、词面、相似≠正确)。

## 7. 边界与排错

| 现象 | 原因与处理 |
|---|---|
| ROUGE-L 恒为 0 或异常低 | 中文被丢弃:默认分词只保留 a-z0-9;中文须先 jieba 分词,再配自定义 tokenizer 保留(见脚本 `ZhTokenizer`) |
| 除零或 NaN | 参考答案或输出为空;先过滤空输出再计算 |
| BLEU 为 0 但人看是对的 | 短句 + 合法改写被长度惩罚;换 ROUGE-L/BERTScore 复核 |
| BERTScore 下载模型失败 | 离线环境;先在有网机器预下载,或退回词面指标 |
| 分数高但输出是编造的 | 指标盲点;补 JSON/格式校验与事实型检查,语义问题交 04 章裁判 |
| accuracy 高但安全表现差 | 类别不平衡;拒答题占比小,单看拒答类的 P/R/F1 |

## 8. 总结

程序化指标 = 用代码自动判分:分类题看混淆矩阵与 F1,生成题看词面或向量相似,结构化题做 JSON 校验。它便宜、即时、可复现,让每个改动都能跑回归;但每个指标都有盲点——不平衡、词面巧合、相似不等于正确——所以**单一分数永远不可信**。词面判不了的语义,正是下一章 LLM 裁判的起点。

**思考题**:模型把「外键」解释得完全正确,但用词与参考答案几乎没有重合,ROUGE-L 会怎么表现?这个低分说明模型错了吗?拒答题只占黄金集 10% 时,accuracy 为何可能接近 0.9 却完全不可信?BERTScore 给一段「流畅但编造」的回答打了高分,可能的原因是什么,该补什么检查?

> [!note] 参考答案
> ROUGE-L 会明显偏低——它只数词面与语序重叠,不认识同义改写;低分只说明「用词不像」,推不出「内容不对」,所以需要人工或 LLM 裁判复核。常规题全对就能拿到约 90% 的 accuracy,拒答题即使全漏分数也几乎不变;不平衡时必须单看少数类(拒答)的 P/R/F1 或 macro-F1。BERTScore 度量的是向量相似而非事实:编造内容在词面和语义上都可以「很像话」;补救靠事实核查规则、格式校验,以及 04 章让大模型按评分标准判定。
