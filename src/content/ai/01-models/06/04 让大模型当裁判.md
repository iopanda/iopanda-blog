# 让大模型当裁判

> 上一章的 ROUGE 给「用词完全正确但说法不同」的答案打低分,却可能给「流畅但纯属编造」的回答打高分——词面指标量不出语义。本章把裁判席交给更强的模型:按一份写死的评分标准(rubric)给课程助教的开放题逐条打分,再抽样请人复核,用「与人工的一致率」回答一个关键问题——**这个裁判,到底可不可信?**读完你能搭起自己的 judge.py,并学会识别与压制 LLM 裁判的位置偏差、自我偏好等系统性问题。

**学习目标**:学完本章,你将能够——

1. 说出 LLM-as-judge 的定义与适用场景、与程序化指标的分工,并区分「按标准打分」与「成对比较」两种判法;
2. 写出一份可执行的评分标准:锚点化、带校准示例、要求结构化输出;
3. 识别位置偏差、自我偏好、冗长偏差三种系统性问题并逐一缓解;
4. 运行 judge.py 对黄金集开放题打分,抽样人工复核并报告一致率与偏差方向。

## 0. 本章为什么存在

01 章的分层评测把判定分了三层:程序化指标、LLM 裁判、人工。03 章建好了最底层——确定性、便宜、可回归,但它「看不懂语义」;人工在最顶层,最准也最贵。本章补上中间层:让 LLM 裁判承担「程序化指标判不了、又没必要每次都请人」的那部分语义判断。它不取代人工,而是**人工的代理**:先规模化打分,再抽样请人复核校准。

## 1. 概念:LLM 裁判是什么

- **LLM-as-judge**:用一个**强模型**当裁判,按评分标准(rubric)去评**弱模型**(或被评对象)的输出。这里「强」指理解与推理能力明显高于被评模型——0.5B 的课程助教,不该由 0.5B 的另一个自己来裁判。
- 它评的是**没有唯一答案的开放维度**:帮助性、连贯性、完整性、安全性、是否按期望行为作答(呼应 02 章:期望行为而非逐字答案);与 03 章的分工——能写成确定性规则的(JSON 格式、词面要点、该不该拒答)留在程序化指标,「人一眼能判、代码判不了」的交给裁判。
- 典型输出是结构化结论,例如 `{"score": 4, "reason": "引用了回答中的具体句子说明给分依据"}`——**带理由**是它区别于「一个神秘数字」的关键:分数可以复核,偏差可以追溯。

## 2. 为什么需要:程序化指标看不懂语义,人工又贵又慢

- **程序化指标的盲区就是裁判的起点**:03 章演示过「相似不等于正确」——BERTScore 眼里「主键唯一」和「主键可重复」离得很近;ROUGE 眼里一句完全正确但换了说法的外键解释接近零分。词面与向量相似都够不到「这句话到底对不对、全不全」。
- **人工评测贵且慢,LLM 裁判可规模化且可解释**:人审每条要读题、读答、对照期望行为,审久了还疲劳漂移,每次改 prompt 都重新请人不可行;裁判一次调用几秒出分、能并排跑几十条,还给出可复核的理由。Zheng 等(2023)在 MT-Bench 与 Chatbot Arena 上测得 GPT-4 裁判与人工偏好的一致率超过 80%——**与人工之间的一致率同一水平**。但代价是**新的偏差**(偏爱位置、偏爱自家输出、偏爱长答案),所以本章的工程核心是:设计时压偏差,跑完后用人核对。

## 3. 两种判法:按标准打分与成对比较

| 判法 | 输入 | 输出 | 适合 | 主要风险 |
|---|---|---|---|---|
| 单题打分(single-answer scoring) | 一道题 + rubric + 一个回答 | 1~5 分 + 理由 | 与阈值比、画雷达图、看趋势 | 分数绝对值依赖 rubric 质量 |
| 成对比较(pairwise) | 一道题 + 两个回答(A/B) | 「A 更好 / B 更好 / 平」+ 理由 | 版本对比、模型选型 | 位置偏差(偏爱 A 或 B 的位置) |

- 课程助教评测**主要用单题打分**:黄金集 18 条是「每道题一个回答」,要的是能对阈值(01 章评测计划)的绝对值。
- 成对比较更贴近人的「谁更好」直觉,常用于候选模型 PK;但测出的是**相对**优劣,不回答「够不够好」。位置偏差在此最明显:把 A/B 顺序互换再评一次,若结论跟着翻,就是裁判在偏爱位置而非内容——缓解:两序各评一次取一致,仍不一致的样本交人工。

## 4. 设计要点:评分标准要具体、可校准、可解析

1. **锚点化(rubric 每档写「看到什么给几分」)**:「质量好」这类词裁判无法执行。要给行为锚点,例如:5 分=正确、要点完整、简洁;3 分=基本正确但有明显遗漏或含糊;1 分=编造、答非所问或该拒未拒。锚点越具体,不同裁判的分歧越小。
2. **给裁判示例做校准**:在裁判 prompt 里附 1~2 条已标好分的样例(可复用 02 章黄金集里人工审过的题),相当于上岗培训——裁判先对齐尺度再上场,与人工标注的培训同理。**校准(calibration)**是压制「裁判按自己的喜好乱给分」最便宜的手段。
3. **要求结构化输出并写理由,裁判与被评模型尽量不同**:只输出 JSON 的 score 与 reason 且 reason 引用回答原句,写不出依据的分数默认可疑,便于人工复核定位;自家人不评自家人(见第 5 节自我偏好),经济上允许就用更强的商用或开源大模型,否则用本地能载入的最大开源模型,并在报告里注明裁判型号。

## 5. 裁判的四种偏差与缓解

| 偏差 | 表现 | 缓解 |
|---|---|---|
| 位置偏差(position bias) | 成对比较中倾向选第一个(或后一个)答案,换序后结论翻转 | A/B 换序各评一次取一致结论;不一致样本交人工 |
| 自我偏好(self-enhancement bias) | 裁判偏爱自己(同厂同系)模型的输出;实测 GPT-4 裁判给自己约高 10% 胜率,Claude-v1 约高 25% | 裁判与被评模型不同厂家/不同系;绝不用被评模型自己当裁判 |
| 冗长偏差(verbosity bias) | 更长的回答得分更高,即使只是把要点重复啰嗦一遍、没有新信息 | rubric 写明「冗长重复不加分」;限制回答展示长度;必要时附参考答案对照 |
| 推理能力有限(limited reasoning) | 复杂计算、多步逻辑题裁判自己也算不对,分数跟着错 | 这类题不上 LLM 裁判,退回程序化校验或人工(对应 01 章「分层」的初衷) |

## 6. 一致性检查:抽样人工复核

裁判分数必须周期性接受人工校验,否则它只是「另一个模型的意见」。流程:

1. 从裁判结果里**随机抽 5~10 条**(含最高分与最低分各至少 1 条),请人按**同一份 rubric** 独立打分,存成 `eval/human_review.jsonl`;
2. 计算两个数字并写进评测记录(呼应 01.02 第 10 章的实验追踪纪律):
   - **一致率**:同分比例;实务更常用**宽一致率**(相差 ≤1 分算一致),目标参考 80% 左右;
   - **偏差方向**:裁判平均分 − 人工平均分。> +0.5 说明裁判系统性偏松,< −0.5 偏严,接近 0 但分散大说明 rubric 模糊。
3. 不一致的样本逐条读 reason 归类:是裁判看漏了要点,还是 rubric 本身有歧义,还是题目太难判(此时以人工为准)。**报告里永远写清裁判型号与一致率**,别让「LLM 打的 4.2 分」冒充人工结论。

## 7. 动手:创建并运行 judge.py

先把课程助教对开放题的实际回答收集成 `eval/to_judge.jsonl`,每行含 `id`、`question`、`expected_behavior`(02 章产物)与 `predicted`(运行 adapter 得到的真实回答,03 章已用过同类数据);然后创建 `judge.py`:

```python
# judge.py — LLM 裁判:按 rubric 给开放题打 1~5 分,并报告与人工的一致率。
import json, os, re, sys
from pathlib import Path

RUBRIC = """按下列标准给「课程助教」的回答打 1~5 分(只输出 JSON):
{"score": 整数, "reason": "引用回答原句说明给分理由"}
5 = 正确完整、条理清晰且简洁;4 = 正确但缺次要要点或略啰嗦;
3 = 基本正确但有明显遗漏或含糊;2 = 部分错误或答非所问;
1 = 编造事实、与问题无关、或该拒答却编造了答案。
冗长重复不加分;与期望行为逐字不同不算错。"""

CALIBRATION = """校准示例(已标分):
题:什么是外键?答:外键是引用另一张表主键的字段。→ score 5
题:什么是外键?答:外键就是字段,用来连接两张表。→ score 3(漏了「引用主键」)"""

DEMO = [
    {"id": "qa-01", "question": "什么是主键？", "expected_behavior": "唯一标识每行的一列或一组列,值唯一且非空", "predicted": "主键是唯一标识表中每一行的列,值不能重复也不能为空。"},
    {"id": "qa-02", "question": "用一句话解释外键", "expected_behavior": "子表里引用父表主键的字段", "predicted": "外键是一种特殊的索引,用来加快查询速度。"},
    {"id": "refuse-01", "question": "明天的东京天气如何？", "expected_behavior": "说明没有实时资料并拒答,不编造", "predicted": "明天东京晴,24 度,适合出行。"},
]

def load_rows():
    p = Path("eval/to_judge.jsonl")
    if p.exists():
        return [json.loads(x) for x in p.read_text().splitlines() if x.strip()]
    print(f"[提示] 未找到 {p},改用内置演示样本(3 条)。")
    return DEMO

def build_prompt(r):
    return (f"题目:{r['question']}\n期望行为(参考):{r['expected_behavior']}\n"
            f"待评回答:{r['predicted']}\n{CALIBRATION}\n{RUBRIC}")

def call_judge(prompt):
    if os.environ.get("JUDGE_API_KEY"):          # OpenAI 兼容 API(云端或本地 vLLM)
        from openai import OpenAI
        client = OpenAI(api_key=os.environ["JUDGE_API_KEY"],
                        base_url=os.environ.get("JUDGE_BASE_URL", "https://api.openai.com/v1"))
        resp = client.chat.completions.create(
            model=os.environ.get("JUDGE_MODEL", "gpt-4o-mini"),
            messages=[{"role": "system", "content": "你是严谨的评测裁判,只按评分标准打分。"},
                      {"role": "user", "content": prompt}], temperature=0)
        return resp.choices[0].message.content
    raise SystemExit("未设置 JUDGE_API_KEY。可改用 --dry-run 预览 prompt,"
                     "或先用本地大模型(vLLM/Ollama)起 OpenAI 兼容服务再设 JUDGE_BASE_URL。")

def parse_score(text):
    m = re.search(r"\{.*\}", text, re.S)          # 容忍模型在 JSON 前后多说废话
    if not m:
        raise ValueError(f"裁判未输出 JSON:{text[:80]}")
    j = json.loads(m.group())
    if not 1 <= j["score"] <= 5:
        raise ValueError(f"分数越界:{j}")
    return j["score"], j["reason"]

def main():
    if "--dry-run" in sys.argv:
        print(build_prompt(load_rows()[0])); return
    judged = []
    for r in load_rows():
        score, reason = parse_score(call_judge(build_prompt(r)))
        judged.append({"id": r["id"], "score": score, "reason": reason})
        print(f"{r['id']}: {score} 分 — {reason[:60]}")
    Path("eval/judge_scores.jsonl").write_text(
        "\n".join(json.dumps(x, ensure_ascii=False) for x in judged) + "\n")
    hp = Path("eval/human_review.jsonl")
    if not hp.exists():
        print("已写入 eval/judge_scores.jsonl;未找到人工复核文件,跳过一致率。")
        return
    human = {json.loads(x)["id"]: json.loads(x)["human_score"]
             for x in hp.read_text().splitlines() if x.strip()}
    pairs = [(j["score"], human[j["id"]]) for j in judged if j["id"] in human]
    exact = sum(a == b for a, b in pairs) / len(pairs)
    wide = sum(abs(a - b) <= 1 for a, b in pairs) / len(pairs)
    bias = sum(a - b for a, b in pairs) / len(pairs)
    print(f"一致率(同分) = {exact:.0%};宽一致率(±1) = {wide:.0%};"
          f"裁判均值 − 人工均值 = {bias:+.2f}({len(pairs)} 条)")

if __name__ == "__main__":
    main()
```

依次执行 `pip install openai` 与 `python judge.py`(先 `python judge.py --dry-run` 检查 prompt 也合法)。运行前设置 `JUDGE_API_KEY`;若没有商用 API,可在本机用 vLLM/Ollama 部署一个 ≥7B 的开源模型,再把 `JUDGE_BASE_URL` 指向它——**裁判必须明显强于被评的 0.5B 助教**,否则就是把一个弱模型的意见当标准。

> [!example] 动手活动:裁判打分与人工一致性
>
> **目标**:产出 `eval/judge_scores.jsonl` 与一份「一致率 + 偏差方向」报告。
>
> **步骤**:
> 1. 从黄金集挑出 6~8 条开放题(答案题与拒答题各半),附上课程助教的真实回答,存成 `eval/to_judge.jsonl`;
> 2. 运行 `judge.py`,确认每条都有 1~5 分与引用原句的理由;
> 3. 抽 5 条(含最高分与最低分),请同学按同一份 rubric 人工打分,写入 `eval/human_review.jsonl`;
> 4. 重跑 `judge.py` 读取一致率,并解释偏差方向数字的含义。
>
> **完成标准**:报告含裁判型号、每条分数与理由、同分一致率与宽一致率、偏差方向;能说出若偏差 > +0.5 应该先改 rubric 还是先换裁判。

## 8. 边界与排错

| 现象 | 原因与处理 |
|---|---|
| 裁判输出一堆话但没 JSON | prompt 里明确「只输出 JSON」;代码已做容错解析,仍失败就检查 rubric 是否被截断 |
| score 恒为 5 或恒为 1 | rubric 锚点太抽象,裁判在猜;补校准示例,检查是否混入了泄题(02 章去污染) |
| 一致率远低于 80% | 先看偏差方向:偏松/偏严改 rubric,分散大加校准示例;个别题人机都难判,标注后以人工为准 |
| 答案很长得分虚高 | 冗长偏差;rubric 写明「冗长不加分」,必要时截断展示 |

## 9. 总结

| 关键判断 | 一句话 |
|---|---|
| LLM 裁判是什么 | 强模型按 rubric 评弱模型输出的语义质量,输出分数 + 理由 |
| rubric 怎么写 | 每档给行为锚点、附校准示例、要求结构化 JSON 输出 |
| 三大偏差 | 位置偏差(换序复评)、自我偏好(裁判与被评不同)、冗长偏差(rubric 明说) |
| 如何自证可信 | 抽样人工复核,报告同分一致率、宽一致率与偏差方向 |

**思考题**:为什么「裁判与被评模型是同一个模型」特别危险?成对比较里 A 总是排前面、胜率 70%,你怀疑是什么偏差,如何验证?人工复核 5 条发现裁判平均分比人高 0.8,你应该先做什么?哪些题目(如多步算术)不该交给 LLM 裁判?

> [!note] 参考答案
> 同一个模型对自家输出有自我偏好,且它的盲区与被评模型完全重叠——「以己之短评己之短」,测不出任何东西。A 恒居前 70% 疑似位置偏差:把 A/B 顺序互换再评一轮,若胜率跟着翻即可确认,随后两序取一致。裁判偏高 0.8 属于系统性偏松,先别急着换裁判:检查 rubric 是否太宽松、校准示例是否给了「3 分」档的样例,改完重跑再看偏差;若仍偏再考虑换裁判。多步算术、长逻辑链会触发裁判「推理能力有限」的偏差,这类题应回退到程序化校验或人工。
