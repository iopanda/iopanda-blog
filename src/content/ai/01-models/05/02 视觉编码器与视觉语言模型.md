> 上一章你看到了「LLM 后端融合」这条主流路线,但图像究竟如何变成 LLM 能读的表示,还没有回答。本章拆开 VLM 的三件套——**视觉编码器、投影器、LLM**——讲透两个关键问题:CLIP 为什么能用对比学习训出适合当底座的视觉编码器;LLaVA 的投影器怎样把图像向量「翻译」进文本 embedding 空间。读完你会亲手跑通 CLIP 图文检索,并能对着任意开源 VLM 画出它的数据流。

**学习目标**:学完本章,你将能够——

1. 说出 VLM 三件套的职责,画出「像素 → LLM 输出」的完整数据流;
2. 解释 ViT 如何把图像切成 patch、变成 vision token;
3. 讲清 CLIP 对比学习的目标——拉近配对、推远不配对,以及它为什么需要超大 batch;
4. 解释投影器的维度映射作用,以及 LLaVA 两阶段训练各自的冻结范围;
5. 用 transformers 或 open_clip 加载 CLIP,跑通 top-k 图文检索并解释相似度含义;
6. 指出常见 VLM 中视觉编码器、投影器、LLM 分别对应哪些模块与参数。

## 1. 概念:VLM 的三件套与数据流

视觉语言模型(Vision-Language Model,VLM)不是「会看图的 LLM」这么简单,它几乎总是三件预训练好的零件拼装而成:

- **视觉编码器(Vision Encoder)**:把图像变成向量。常见为 CLIP 的 ViT 变体或 SigLIP(如 Qwen2.5-VL 视觉塔即基于 SigLIP)。
- **投影器(Projector)**:把视觉向量的维度与语义「翻译」到文本 embedding 空间,常见为线性层或 MLP。
- **LLM**:负责融合与生成,如 Llama、Qwen2.5、Vicuna。

| 组件 | 输入 | 输出 | 训练状态 |
|---|---|---|---|
| 视觉编码器 | 图像(如 336×336×3 像素) | 逐 patch 的 vision feature + 整图 embedding | 通常冻结 |
| 投影器 | vision feature(如 1024 维) | vision token(与文本 embedding 同维) | 可训练 |
| LLM | 文本 embedding + vision token 拼接序列 | 文本 token 概率 | 冻结或用 LoRA 微调 |

整条数据流为:

1. 图像切成 patch,视觉编码器产出 576 个(24×24)vision feature;
2. 投影器把每个 feature 映射成与文本 embedding 同维的向量,即 vision token;
3. 文本经分词与 embedding 查表得到文本 token;
4. 两类 token 拼成一条序列,一起送入 LLM 的各层做自注意力;
5. LLM 只对文本部分计算「下一个词」损失,自回归生成回答。

## 2. 为什么需要:LLM 只懂文本 token

LLM 的输入层本质是一张「离散 token → embedding」的查表:词表里每个符号对应一个可学习向量。图像不是离散符号——一张 336×336 的彩色照片有 336×336×3≈33.9 万个数值,直接塞给 LLM 有三个问题:

- **不是 token**:图像没有分词器,像素之间也没有「词」的边界;
- **维度爆炸**:33.9 万个数值当序列送进去,注意力的计算量无法承受;
- **语义断层**:像素值与文本 embedding 不在同一个语义空间,LLM 学不会「第 100 行第 50 列的亮度」和「猫」有什么关系。

因此必须先有一个编码器把图像**压缩**成少量、有语义的向量,再通过投影把向量放进 LLM 认识的空间。视觉编码器与投影器就是为这两步而生的。

## 3. 概念:视觉编码器——把图像变成向量

以 CLIP 常用的 ViT-L/14 为例,视觉编码器的工作分三步:

- **切 patch**:把图像(如 336×336)切成 14×14 的小块,共 24×24=576 个 patch;
- **嵌入**:每个 patch 展平后经一个线性层投影成向量,加上位置编码,成为一条「视觉序列」;
- **编码**:整条序列送入 Transformer 编码器做自注意力,输出逐 patch 的特征;序列开头加一个 `[CLS]` 记号,其输出经投影得到整图 embedding。

| 编码器 | patch 尺寸 | 输入分辨率 | vision token 数 | 特征维度 |
|---|---|---|---|---|
| CLIP ViT-B/32 | 32×32 | 224×224 | 49 | 768 |
| CLIP ViT-L/14 | 14×14 | 336×336 | 576 | 1024 |
| SigLIP-So400m | 14×14 | 384 级(实现而异) | 数百级(实现而异) | 1152 |

注意两点:**整图 embedding(1 个向量)与逐 patch 特征(576 个向量)是两种产物**——图文检索用前者,喂给 VLM 的是后者;编码器本身不理解内容,向量的语义完全由第 4 节的训练目标塑造。

## 4. 概念:CLIP 是怎么训出来的——对比学习

CLIP(Contrastive Language-Image Pre-training,OpenAI,2021)用约 **4 亿条网络图文对**训练,文本在这里扮演「免费标注」:网页上一张图配的 alt 文本或说明,就是它的标签。训练采用**双塔 + 对比学习**:

- **双塔**:图像塔(ViT 或 ResNet)与文本塔(Transformer)各自独立编码,两个编码器只在损失函数处相遇;
- **正样本**:batch 内第 i 张图与第 i 句文本是配对;其余 N−1 对全是「随机撞到一起」的负样本;
- **目标**:算 N×N 的余弦相似度矩阵,让对角线(配对)的分数高、非对角线低。等价于做两次对称交叉熵——每行回答「这张图配哪句话」,每列回答「这句话配哪张图」。

```python
def clip_loss(image_emb, text_emb, tau=0.07):   # 示意:完整实现见 transformers
    logits = image_emb @ text_emb.T / tau       # N×N 相似度,τ 可学习
    labels = torch.arange(len(image_emb))
    return (F.cross_entropy(logits, labels)
          + F.cross_entropy(logits.T, labels)) / 2   # 对称:图→文、文→图
```

- **为什么 batch 必须巨大**:负样本来自 batch 内其它图文对。batch=32768 时每张图要在一万多个干扰项里认出自己的文本,负样本越多、判别越难,学到的表征越有区分度——这是 CLIP 原版需要 256 张 V100 的原因。
- **SigLIP 的改进**(Google,2023):把 softmax 换成逐对的 sigmoid 损失,不再依赖整张 N×N 矩阵与小 batch 的矛盾;Qwen2.5-VL 等新模型的视觉塔正是 SigLIP。温度 τ 影响分数分布的锐利程度,训练中可学习。

### 4.1 为什么 CLIP 特征适合做 VLM 底座

- **与文本同空间**:对比学习已把图像与文本拉到同一语义空间,投影器只需做「小修」而非从零对齐;
- **语义化表征**:自然语言监督让表征按语义而非像素相似度组织,CLIP 不训练就能在 ImageNet 达到约 76% 的 zero-shot 精度,是表征质量的佐证;
- **可冻结复用**:LLaVA 证明冻住 CLIP ViT 也能做出好 VLM,省下巨额视觉预训练成本;
- **生态成熟**:权重与预处理在 transformers、open_clip 中开箱即用。

## 5. 概念:投影器与 LLaVA 两阶段训练

维度对不上是第一道坎:CLIP ViT-L/14 输出的每个 vision feature 是 1024 维,而 Vicuna-7B 的 embedding 是 4096 维;更本质的是两者处于不同语义空间。**投影器**就是夹在中间的若干层可训练网络,把每个 vision feature 独立映射过去:线性层写作 `W·v`(1024→4096),LLaVA-1.5 起改用两层 MLP,效果更好。

为什么不自训一个视觉编码器?视觉预训练要几十亿图文对与数千 GPU 卡时,普通团队承担不起;而预训练 LLM 与 CLIP 权重都是现成的,「两头冻结、中间加一个小可训练件」是性价比最高的组装方式。LLaVA(Liu et al.,2023)的两阶段正是围绕投影器设计的:

| 阶段 | 数据 | 冻结 | 训练 |
|---|---|---|---|
| 一:特征对齐 | 图文描述对(CC3M/CC595K 子集) | 视觉编码器 + LLM | 只训投影器 |
| 二:端到端指令微调 | (图像, 指令, 回答) | 视觉编码器 | 投影器 + LLM(或 LoRA) |

- **阶段一为何冻 LLM**:视觉 token 尚未对齐时,LLM 收到的是「乱码」,直接端到端训练容易把语言能力带偏;先把投影器训到视觉 token「读起来像文本」,再进入下一阶段;
- **阶段二才解锁 LLM**:用指令数据端到端微调,让 LLM 学会「看着图回答问题」,损失仍只算文本部分(呼应 01 章的下一个词预测);
- **现代变体不改变原理**:Qwen2.5-VL、SmolVLM 的「连接器」可能是 perceiver 或带 QK-Norm 的更深模块,但「编码器把图变向量、连接器翻译进文本空间、LLM 融合生成」的骨架不变。

## 6. 动手:用 CLIP 跑通图文检索

准备 3~5 张本地图片(自己拍的或 CC0 图片均可),用 transformers 写一个「文本查询 → 最相似的 top-k 张图」:

```python
from transformers import CLIPProcessor, CLIPModel
import torch
from PIL import Image

model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
proc = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")

paths = ["cat.jpg", "street.jpg", "beach.jpg"]
imgs = [Image.open(p) for p in paths]
texts = ["一只橘猫趴在窗台上", "雨夜霓虹街道", "沙滩上的冲浪板"]
inp = proc(text=texts, images=imgs, return_tensors="pt", padding=True)
with torch.no_grad():
    logits = model(**inp).logits_per_text    # 形状 (查询数, 图像数)
    for i, t in enumerate(texts):
        topk = logits[i].topk(2).indices.tolist()
        print(t, "→", [paths[j] for j in topk])
```

预期:每句查询都能把最匹配的图排到第一。注意 `logits_per_text` 是文本塔视角的相似度对数(已乘温度缩放因子,softmax 只改数值大小、不改变排序,直接 topk 即可),它正是第 4 节损失里那张 N×N 相似度矩阵的推理版。

## 7. 动手:观察 embedding 的相似度

若想脱离封装、直接看相似度数值,改用 open_clip(需 `pip install open_clip_torch`):

```python
import torch, open_clip
from PIL import Image
model, _, preproc = open_clip.create_model_and_transforms(
    "ViT-B-32", pretrained="laion2b_s34b_b79k")
tok = open_clip.get_tokenizer("ViT-B-32")
img = preproc(Image.open("beach.jpg")).unsqueeze(0)
with torch.no_grad():
    feats = model.encode_image(img)              # (1, 512)
    txts = model.encode_text(tok(["海滩", "会议室", "晚餐"]))   # (3, 512)
    sim = (feats @ txts.T).softmax(dim=-1)
print(sim)   # 图像与三类文本的匹配分布
```

关键观察:`encode_image` 与 `encode_text` 输出维度相同(512),这是能直接点积的前提——维度相同来自设计,语义可比来自第 4 节的对比训练。若把文本换成完全不相关的词,分数分布会趋于平坦,这也是有价值的诊断信息。

## 9. 常见错误与结论

| 现象 | 处理 | 原因 |
|---|---|---|
| 所有相似度都接近、无区分度 | 检查文本是否与图像内容域差异过大;尝试更具体的查询 | 域完全不相关时,softmax 分布趋于平坦 |
| top-1 总是不对 | 核对图像是否经 processor/preproc 缩放;换语义更直接的查询 | 预处理尺寸必须匹配模型训练分辨率 |
| 显存不足或下载过慢 | 换 `openai/clip-vit-base-patch32` 或 open_clip 的 ViT-B-32 | ViT-L/14@336 分辨率更高、参数更多 |
| 想定位图中物体却失败 | 改用检测/分割类模型 | CLIP 做全局语义匹配,不做空间定位 |

一句话结论:**视觉编码器负责「看懂」,投影器负责「翻译」,对比学习是让编码器「按语义看懂」的训练目标**;VLM 的一切能力都建立在这三件事之上。

## 10. 总结

| 关键问题 | 一句话 |
|---|---|
| 图像如何变成 token | ViT 切 patch 编码成向量,投影器再映射进文本 embedding 空间 |
| VLM 是哪三件套 | 视觉编码器 + 投影器 + LLM,前两者常冻结、LLM 常用 LoRA 微调 |
| CLIP 在学什么 | 4 亿图文对上的对比学习:拉近对角线正对、推远 batch 内负对 |
| 为什么 CLIP 特征适合做底座 | 与文本同空间、语义化、开源可冻结复用 |
| 投影器解决什么问题 | 维度与语义空间的映射;LLaVA 阶段一只训它 |
| LLaVA 为什么分两阶段 | 先冻两端对齐视觉 token,再端到端学「看图回答」 |

**思考题**:CLIP 为什么需要三万以上的大 batch,而 SigLIP 不需要?若把视觉编码器换成随机初始化的 ViT 直接接 LLM,可能出现什么现象?LLaVA 阶段一为什么必须冻住 LLM,不冻会怎样?

> [!note] 参考答案
> CLIP 的 softmax 损失把 batch 内其它图文对当负样本,batch 越大负样本越多、判别越难,表征越有区分度;SigLIP 改为逐对 sigmoid 二分类,不再依赖 batch 提供负样本。随机初始化的编码器产出的向量与文本语义毫无对齐,LLM 相当于在读乱码,即便勉强训动也需要海量图文数据且极易灾难性遗忘;先冻 LLM 只训投影器,正是用廉价方式完成「对齐」这一步。
