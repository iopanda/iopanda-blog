> 本章是 01.05 的收官:前面四章分别产出看图问答的能力(01)、视觉编码器与投影器的原理(02)、可审计的图文数据(03)与微调后的 VLM(04)——但这些工件本身不等于「可以交付的多模态原型」。本章沿用 01.03/08 收官章的同一套验收纪律(冻结验收集、基线与微调后同条件对比、失败案例原样保留、一页模型卡),把输入从纯文本换成**图像**:冻结一组从未参与训练的测试图,让 base 与微调模型逐张作答,逐条评分、分类失败原因,最终交付一个「课程截图问答」原型与它的模型卡。

**学习目标**:学完本章,你将能够——

1. 说出多模态收官项目的验收标准,解释为什么它与纯文本收官(01.03/08)同纪律、但多出图像相关的评测变量;
2. 解释图文验收集为什么必须在训练开始前冻结,「图被看过」与「题被看过」一样致命;
3. 构造一张 10 张测试图、四类别的 golden 清单,让 base 与微调后模型在同一预处理条件下逐张评测;
4. 按 0/1 规则逐条评分,并把失败例归类为幻觉、OCR 误读、分辨率限制或过度拒答;
5. 写出一页 `model-card.md`,说明用途边界、已知风险与回滚方式;
6. 基于证据给出「该原型是否可交付」的结论,并把评测方法平滑交给下一单元(01.06)。

## 1. 概念:收官项目交付什么

- 本单元 01~04 各是一条「单点能力」:会看图问答的模型(01)、懂图像如何变成 token 的原理(02)、一份带数据卡的图文数据(03)、一个在领域截图上变好的微调模型(04)。**收官项目 = 把它们串成一个端到端原型**:用户丢进一张课程 PPT 截图,服务返回「图中讲什么、关键结论是什么」的准确回答。
- 交付物不是「能跑通的 demo」,而是四件套:**可审查的评测**、**失败的证据**、**一页模型卡**、**一个可复现的入口(demo 脚本/API)**。谁拿到仓库,谁就能复现全部数字——这与 01.03/08 的验收口径完全一致,只是输入从文字变成图。
- 验收要回答四问(比 08 多一问图像):**改善可测吗**(微调后在 golden 图上是否比 base 更准)、**证据完整吗**(全部输出可查看,失败例没被挑掉)、**代价与风险已知吗**(显存、训练时长、数据许可,外加幻觉/OCR/分辨率风险)、**边界说清了吗**(模型卡上「能做什么、不能做什么」一眼可知)。

## 2. 为什么需要:验证整条链路,而不是单点 demo

- 单点 demo 会骗人:04 章训练结束时 loss 下降、随手挑两张图答得漂亮——这只能证明「训练跑通了」,不能证明「交付可用」。数据配错、图像泄漏、微调后更爱幻觉,这些缺陷只有把**数据 → 微调 → 服务**整条链路端到端走一遍验收才会暴露。
- 图文链路比纯文本多了三道脆弱环节:①数据侧——图像是否与问题真匹配(03 章的六维检查);②训练侧——微调后模型是否只是记住了训练图,换一张陌生截图就露馅;③服务侧——线上截图分辨率、压缩噪声与训练图不一致时表现如何。收官章逐一给证据。
- 与 01.03/08 的关系:同一份验收纪律(golden 先冻结、基线与 adapter 同条件对比、0/1 评分、失败例保留),新增两类图文特有变量:输入是**像素而非字符串**、模型可能**幻觉出图里没有的内容**。08 章验证的是「微调让模型更懂领域文本」,本章验证「微调让模型更懂领域截图」,且要证明它不是背图。

## 3. 验收纪律:验收集先冻结,评测变量先锁死

- **冻结验收集**:和 08 章同理——任何测试图一旦进入「看分数 → 改数据 → 再看分数」的循环就不再是测试。图文记忆比文本记忆更强:训练时见过某张图,模型可能直接背出与它绑定的问答。因此 10 张测试图必须在 03/04 章任何实验之前选定、与 train/valid 图集**既不同题也不同图**,记录时间戳后锁死。
- **图文特有的评测变量**(08 章没有,必须显式固定,否则分数不可比):
  - 图像预处理:`processor` 的 `min_pixels`/`max_pixels`——同一张图,分辨率上限调大一倍,OCR 结果可能从错变对,等于换了一道更简单的题;
  - 提问模板与 system prompt:两轮评测必须逐字相同;
  - 生成参数:`do_sample=False`、相同 `max_new_tokens`,唯一变量是模型本身。
- 先定结论:微调后若只在「与训练图相似的截图」上变好、却在陌生截图或模糊图上更爱编造,不能宣布成功——回到 03 章补数据或调 04 章超参,而不是挑图重测。

## 4. 动手:冻结 10 张图的验收集

沿用 03 章的 `vlmdemo/` 项目目录(若你在 04 章换过路径,替换为实际路径)。创建 `vlmdemo/eval/golden.jsonl`,图片放在 `eval/golden_img/`,10 张共四类:

| 类别 | 张数 | 用意 |
|---|---|---|
| 领域截图问答 | 5 | 课程 PPT/文档截图,验证微调目标场景 |
| 细密文字或表格 | 3 | 考验 OCR 与小字分辨率上限 |
| 图外题目 | 1 | 图上没有答案,应明确拒答不编造 |
| 模糊/低分辨率 | 1 | 记录边界失败,用作已知风险证据 |

每行 schema(呼应 03 章:`image` 顶层引用 + 明文期望行为,**不写训练答案**):

```json
{"id": "g01", "image": "eval/golden_img/g01.png", "category": "domain",
 "question": "这张 PPT 提出了什么问题?给出的方案是什么?",
 "expected_behavior": "依据图中可见文字作答;出现图外内容即为幻觉"}
```

选图纪律:截图内容必须与训练集来自**不同**的课程文档(避免同图不同题的隐性泄漏);图外题选一张与课程无关的照片;模糊图可以是刻意缩小保存的截图。用 `shasum eval/golden_img/*.png > eval/golden_img.sha256` 留档,之后不再增删改任何一张。

## 5. 动手:同一条件跑 base 与微调模型

创建 `vlmdemo/src/eval_golden.py`(加载与生成方式对齐 01 章的 `vlm_ask.py`):

```python
# eval_golden.py —— 冻结验收集评测:base 与微调后各跑一遍,结果追加存档
import json, torch
from transformers import AutoProcessor, Qwen2_5_VLForConditionalGeneration

BASE = "Qwen/Qwen2.5-VL-3B-Instruct"
MODEL_ID = BASE          # 跑微调后版本时,改为 04 章产物路径(以你 04 章实际为准)
SYS = "你是课程助教,只依据图中可见内容回答;图上没有依据就明说看不到,不要编造。"
TMPL = "请看这张截图,回答:{q}"

model = Qwen2_5_VLForConditionalGeneration.from_pretrained(
    MODEL_ID, torch_dtype=torch.bfloat16, device_map="auto")
processor = AutoProcessor.from_pretrained(          # processor 两轮必须同一份
    BASE, min_pixels=256 * 28 * 28, max_pixels=1280 * 28 * 28)

with open("eval/golden.jsonl", encoding="utf-8") as f:
    items = [json.loads(line) for line in f]
for it in items:
    messages = [{"role": "system", "content": SYS}, {"role": "user", "content": [
        {"type": "image", "image": it["image"]},
        {"type": "text", "text": TMPL.format(q=it["question"])}]}]
    inputs = processor.apply_chat_template(
        messages, tokenize=True, add_generation_prompt=True,
        return_dict=True, return_tensors="pt").to(model.device)
    with torch.no_grad():
        out = model.generate(**inputs, max_new_tokens=256, do_sample=False)
    ans = processor.batch_decode(out[:, inputs.input_ids.shape[1]:],
                                 skip_special_tokens=True)[0]
    print(json.dumps({"id": it["id"], "model": MODEL_ID,
                      "category": it["category"], "output": ans},
                     ensure_ascii=False))
```

先不改 `MODEL_ID` 跑一遍 base,把输出追加到 `reports/golden-results.jsonl`;再把 `MODEL_ID` 换成 04 章微调产物(adapter 需先合并进 base 或直接指向完整权重目录)跑第二遍。**两遍共用同一 processor 参数与同一 prompt**,输出行用 `model` 字段区分来源。

## 6. 人工评分与失败案例分析

逐条按 0/1 打分,同时满足才算 1:回答与图中内容一致(可对着原图核对)、按需正确拒答、无幻觉细节(图外数字/结论即 0)、无明显有害或私密信息。**10 条全评,禁止只挑能得分的**,失败例原样贴进报告:

| 模型 | 得分 | 拒答正确 | 幻觉类失败 | 其他失败 | 是否推荐 |
|---|---:|---:|---:|---|---|
| base | /10 | /1 | 原样链接 | 原样链接 | 否/有条件 |
| 微调后 | /10 | /1 | 原样链接 | 原样链接 | 有条件 |

把失败输出归类到四类,写进 `reports/failures.md`(每类给现象、原始输出、对策):

| 失败类型 | 现象 | 典型对策 |
|---|---|---|
| 幻觉 | 答出图上没有的数字/结论 | 回 03 章补「看不到就拒答」样本,或降低 04 章学习率 |
| OCR 误读 | 相似字符认错(6/8、O/0),表格数字错位 | 截图分辨率不足时重截大图;仍错则记入已知失败 |
| 分辨率限制 | 小字糊成一团无法辨认 | 模型卡注明「小字需放大图」,产品侧做预处理放大 |
| 过度拒答 | 图上明明有内容却说看不到 | 回 04 章检查微调数据中拒答样本是否过多,失衡则回 03 章调比例 |

**判定规则**:若微调后 5 张领域截图明显变好、图外题正确拒答、幻觉次数不增,可判「有条件推荐」;若它只是背住了训练图(陌生截图答不出)或幻觉变多,必须回到数据与训练环节,而不是宣布成功。

## 7. 交付目录与模型卡

最终交付结构(03 章的数据与许可记录、04 章的超参数留在原位):

```text
vlmdemo/
  data/                 # 03 章:train/valid 图集、数据卡与许可记录
  runs/<adapter>/       # 04 章:微调产物与训练日志
  eval/golden.jsonl     # 本章冻结的验收集
  eval/golden_img/      # 10 张测试图(附 golden_img.sha256)
  src/eval_golden.py
  app/demo.py           # 交付入口:单张图问答 CLI,可再包成 API
  reports/golden-results.jsonl
  reports/failures.md   # 失败案例分析
  reports/model-card.md
```

`app/demo.py` 只做一件事:接收图片路径与问题,按第 5 节同款 processor 参数调用微调模型并打印回答——它就是「原型」的服务入口,后续包 HTTP API 时(01.04 的做法)换壳不换核。`reports/model-card.md` 至少写:训练目的与建议用途、允许/禁止用途(如「不用于医学影像判读」)、数据来源与许可、图像输入限制(分辨率、截图类型)、golden 得分与失败例链接、幻觉/OCR/隐私风险、复现命令、回滚方式(删除 adapter 回到 base)。切勿上传训练数据、密钥或含个人信息的截图——评测图本身也要过一遍 03 章的 PII 检查。

## 8. 动手活动:结业验收

> [!example] 动手活动:多模态收官验收
>
> **目标**:提交上述目录与一页 `model-card.md`,给出可审查的「是否可交付」结论。
>
> **步骤**:1. 按第 4 节冻结 10 张测试图(课程 PPT/文档截图 5 张、细密文字 3 张、图外 1 张、模糊 1 张),记录 sha256;2. 用 `eval_golden.py` 以同一 processor 参数分别跑 base 与微调模型,全部输出追加存档;3. 对照原图逐条 0/1 评分,把失败例归类写入 `failures.md`,填好汇总表;4. 写 `model-card.md`,给出「有条件推荐 / 需回炉」的结论与依据。
>
> **完成标准**:第三方拿到仓库后,能复现两轮评测、对着 golden_img 核对每一条输出、在失败案例与模型卡中看到完整风险说明,并据此同意或否决交付——而不是只听一句「效果不错」。

## 9. 总结

| 关键问题 | 一句话 |
|---|---|
| 收官项目是什么 | 把 01~04 串成「课程截图问答」原型:评测、失败证据、模型卡、demo 入口四件套 |
| 为什么需要 | 单点 demo 只证明训练跑通;只有端到端验收能暴露数据、记忆与服务侧的缺陷 |
| 与 01.03/08 的关系 | 同验收纪律,新增图文变量:图像预处理、幻觉、图像记忆性泄漏 |
| 验收集纪律 | 10 张测试图训练前冻结、与 train/valid 不同图不同题、sha256 留档 |
| 评测变量 | 同一 processor 的 min/max_pixels、同一 prompt、`do_sample=False`,唯一变量是模型 |
| 失败四类 | 幻觉、OCR 误读、分辨率限制、过度拒答——每类写现象与对策 |
| 模型卡的意义 | 用途边界、图像限制、已知风险、回滚方式,使用者一眼可知 |

**思考题**:golden 的 10 张图「微调后全部答对」能证明收官成功吗?如果评测时把某张模糊图放大重截后模型从错变对,这算模型能力还是评测作弊?验收报告该如何处理图像预处理这个变量?

> [!note] 参考答案
> 不能:全对可能意味着测试图与训练分布过于接近,甚至某张图曾在 04 章调试中被看过——图文记忆极强,「图被看过」等于「题被看过」,应视为污染并替换重测;验收还要看与 base 的差异、拒答与失败案例。调大 `max_pixels` 或放大重截相当于换了一道更简单的题,属于改了评测变量:两轮评测必须锁死同一 processor 参数与同一图像文件,预处理差异要在报告里写明;若产品侧确实会做放大预处理,应把它写进「交付时的输入管线」并同样用于两轮评测——这正是下一单元(01.06)评测设计要解决的「评测管线与交付管线一致」问题。
