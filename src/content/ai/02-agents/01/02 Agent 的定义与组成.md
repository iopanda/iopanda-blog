# Agent 的定义与组成

> 01 Models 系列让你从零训练、微调、评测并部署了「会回答」的模型:课程助教能解释主键、能按三点结构作答、有评测报告证明达标。但「会回答」和「会办事」之间隔着一条河——回答是生成一段文字,办事是完成一串动作:查资料、算结果、写文件、发消息。本章是 02 Agents 系列的第一课,回答 Agent 系列的地基问题:**什么是 AI Agent?它和聊天机器人差在哪?它由哪些部分组成?** 读完你能给「课程助教 Agent」画出第一版组成图,并知道为什么它比 01 里那个只会回答的模型多了四个新部件。

**学习目标**:学完本章,你将能够——

1. 用自己的话定义 AI Agent,并区分 Agent 与聊天机器人;
2. 说出 Agent 组成的五要素(模型/上下文/规划/工具/记忆)及各自职责;
3. 用「自主度光谱」判断一个系统是 Copilot 还是 Agent;
4. 解释为什么 LLM 出现前也有 Agent,但形态完全不同;
5. 为课程助教画出第一版 Agent 组成图并说明每要素的作用。

## 1. 概念:什么是 AI Agent

- **AI Agent(智能体)**:一个能**自主规划并采取行动**去完成目标的 AI 系统。它不止「说」,还会「做」——并且在做的过程中根据结果调整下一步。
- 它不是单一模型,而是**以模型为大脑的完整系统**。模型负责理解和推理,系统负责行动和记忆。

### 1.1 Agent vs 聊天机器人

| 对比维度 | 聊天机器人(Chatbot) | AI Agent |
|---|---|---|
| 核心动作 | 对话:一问一答 | 行动:规划→执行→观察→再规划 |
| 是否调用外部 | 通常不调用 | 调用工具(检索/计算/写文件/API) |
| 状态 | 基本无状态 | 有上下文与记忆 |
| 目标 | 答好当前问题 | 完成一个多步任务 |
| 失败处理 | 换个说法再答 | 换条路径重试/求助/放弃 |

- 关键区别:**聊天机器人答完了事,Agent 要对「事办成了没有」负责**。

## 2. 为什么需要 Agent

- 很多真实任务无法用一次问答完成:「根据课程资料写一份数据库复习提纲,再按学员进度分成三份,分别存成 md 文件」——这需要检索、规划、写作、写文件四个动作,且后一步依赖前一步的结果。
- **例子多、步骤多、需要外部信息**的任务,正是 Agent 的用武之地——类似 01.01 里「例子多、规则难」催生了模型,这里「步骤多、要动手」催生了 Agent。

## 3. 组成:Agent 的五要素

一个最小 Agent 由五部分组成(缺一不可):

```
┌─────────────────────────────────────────────┐
│                  用户目标                     │
├─────────────────────────────────────────────┤
│  ① 模型(大脑)    —— 理解与推理               │
│  ② 上下文(工作台) —— 当前任务的所有信息        │
│  ③ 规划(拆解)    —— 目标 → 步骤              │
│  ④ 工具(手)      —— 检索/计算/写文件/API      │
│  ⑤ 记忆(便签)    —— 前几步做过什么、学到什么   │
├─────────────────────────────────────────────┤
│        循环:规划 → 行动 → 观察 → 再规划       │
└─────────────────────────────────────────────┘
```

| 要素 | 职责 | 类比 | 如果没有会怎样 |
|---|---|---|---|
| ① 模型 | 理解输入、产生推理与决策 | 大脑 | 无法理解任务 |
| ② 上下文 | 承载 system 规则、历史、工具结果 | 工作台 | 忘记上一步做了什么 |
| ③ 规划 | 把目标拆成可执行步骤 | 项目经理 | 只能做一步,做不了多步任务 |
| ④ 工具 | 与外部世界交互 | 手 | 只能空谈,无法查证/执行 |
| ⑤ 记忆 | 跨步、跨会话保存状态 | 便签本 | 每步从零开始,无法积累 |

- **呼应 01**:你训练和部署的模型(01.01~.4)就是这里的①;上下文工程的技法(02.02)管②;规划(02.03)、工具(02.04)、记忆(02.05)是接下来的三章。

### 3.1 五要素的关系:不是并列,是围绕循环组织

- 五要素不是五个独立模块随便堆叠,而是**围绕「规划→行动→观察→再规划」这个循环**组织起来的:上下文(②)是循环读写的工作台,规划(③)决定下一步,工具(④)执行,记忆(⑤)把循环的中间状态沉淀下来,模型(①)每轮重新读上下文做决策。
- 一个容易犯的错误是把 Agent 当成「模型 + 一堆功能」。功能(工具)只有被循环调度、被上下文约束、被记忆沉淀,才成为 Agent 的一部分。
- 判断一个系统是否「真的用上了五要素」:追问它每轮决策依据什么、行动结果去哪了、跨轮信息靠什么保留。答不上来的,多半只是「套了 Agent 外壳的单轮调用」。

### 3.2 常见误解澄清

| 误解 | 事实 |
|---|---|
| Agent = 一个更聪明的模型 | Agent 是系统;模型只是大脑,换模型不换系统也能叫 Agent |
| Agent = 一定自主 | 自主度是光谱,大多数生产 Agent 在关键步骤等人确认 |
| Agent = 一定多轮对话 | 多轮对话只是上下文的一种来源;Agent 的核心是行动闭环 |
| 没有工具也能叫 Agent | 纯对话系统没有外部行动,更像 Chatbot(除非任务是纯推理) |

## 4. 详细介绍:自主度光谱——Copilot 还是 Agent

- 「Agent 不 Agent」不是非黑即白,而是**自主度光谱**:

| 自主度 | 形态 | 谁做决定 | 例子 |
|---|---|---|---|
| 低 | Copilot/补全 | 人主导,AI 建议 | 代码补全、翻译助手 |
| 中 | 工作流(Workflow) | 人定流程,AI 执行片段 | 自动摘要管道 |
| 高 | Agent | AI 规划并行动 | 自主调研并写报告 |
| 更高 | 多 Agent | 多个 AI 分工协作 | 02.06 展开 |

- **判断方法**:问「如果我中途不干预,它能自己把事办完并停下来吗?」能 → 偏 Agent。
- **工程含义**:自主度越高,越需要护栏(呼应 01.07):权限边界、预算上限、人工确认点。

### 4.1 判断练习:三个系统分别是什么

| 系统 | 行为 | 自主度判断 |
|---|---|---|
| 天气问答机器人 | 收到「上海明天天气」→ 调天气 API → 返回结果 | 单步工具调用,仍是 Chatbot 增强版:没有多步规划,一次问答即结束 |
| 周报生成器 | 每天自动读 Git 记录 → 汇总 → 生成周报 → 发到群 | 工作流偏 Agent:步骤固定但跨多步、有外部动作,自主度中等 |
| 自主调研 Agent | 给定主题 → 自己决定搜什么 → 读多页 → 起草 → 自我检查 → 改稿 | 高自主 Agent:规划开放、结果不确定、需要停止条件 |

- 同一个底层模型,套上不同编排,就落在光谱的不同位置——**差别在系统设计,不在模型选型**。这解释了为什么 02 系列把重点放在循环、上下文、工具与记忆这些系统能力上,而不是再换一个更大的模型。

## 6. 总结

| 概念 | 一句话 |
|---|---|
| AI Agent | 能自主规划并行动、对「事办成没有」负责的系统 |
| Agent vs Chatbot | 一个行动、一个对话 |
| 五要素 | 模型/上下文/规划/工具/记忆 |
| 自主度光谱 | Copilot → 工作流 → Agent → 多 Agent |
| 判断法 | 不干预,它能办完并停下吗? |

**思考题**:课程助教「只回答课程问题」是 Chatbot 还是 Agent?把它改成「先查学员进度再决定讲多深」后呢?

> [!note] 参考答案
> 前者是 Chatbot——只生成回答,不采取外部行动。后者引入了「读取进度」这一工具动作并据此规划回答,变成 Agent(至少是带工具的增强对话系统)。区别不在「像不像人」,而在「是否为了目标采取多步行动」。
