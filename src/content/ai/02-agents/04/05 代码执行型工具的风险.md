# 代码执行型工具的风险

> 03 章把 `run_python` 钉在了高风险档:它要做的事是「让模型写代码,然后让这段代码真的跑起来」——能力最强,也最接近把整台机器交给一次模型输出。本章拆开三个问题:模型生成的代码到底能造成什么破坏、为什么进程内的各种「限制」都拦不住它、以及隔离、超时、禁网、截断、确认这五道缓解怎么落成代码。读完你会为课程助教搭一个能安全执行 pandas 代码的沙箱执行器,理解「数据分析 Agent」这类产品安全的基石。

**学习目标**:学完本章,你将能够——

1. 说出代码执行工具与其他工具的本质区别(代码即权限,整段代码由模型生成);
2. 列举模型生成代码的典型危害:删文件、网络外联、资源耗尽、持久化后门;
3. 解释为什么 exec 参数限制与 AST 白名单不是沙箱(进程内限制可被绕过);
4. 落地五道缓解措施:隔离容器、超时、禁网、输出截断、人工确认;
5. 让课程助教在沙箱里跑通一次「成绩分布 pandas 分析」,并验证一次恶意尝试被拦。

## 1. 概念:让模型写代码再执行它

- **形态**:工具接收模型生成的代码字符串,在 Python REPL、沙箱或容器里执行,再把 stdout 与错误信息回填给模型。OpenAI 的 Code Interpreter、Anthropic 生态的代码执行工具都是这个形态,课程助教要加的 `run_python` 也一样。
- **与其他工具的本质区别**:`search_course` 是「你写好的函数 + 模型填参数」;`run_python` 是「模型写整段代码,你负责执行」。**代码 = 权限**:一旦执行,它能做什么不取决于你注册工具时声明了什么,而取决于运行它的那个进程拥有什么权限。
- 位置:03 章谱系的最右端(高副作用),但也是数据分析、数学推导、文件处理类任务的最优解——威胁与价值同源,所以问题不是「禁用它」,而是「怎么安全地用它」。

## 2. 为什么需要沙箱:模型生成的代码能做什么

| 代码形态(模型可能生成的) | 后果 | 类别 |
|---|---|---|
| `os.remove("grade.db")`、`shutil.rmtree(...)` | 删除数据与文件 | 破坏完整性 |
| `socket` 连接外部主机、`requests.get(...)` | 数据外泄、被当跳板 | 泄露与横向移动 |
| `while True: pass`、申请超大数组 | CPU/内存耗尽,拖垮主机 | 拒绝服务 |
| 改写 `~/.bashrc`、`/etc/cron.d/` | 留下持久后门,重启仍生效 | 持久化 |
| 读 `~/.ssh`、环境变量里的密钥 | 窃取凭证 | 泄露 |

- **为什么模型生成的代码风险尤其高**:① 训练语料里就有恶意代码模式,模型可能「有样学样」;② 03 章的间接注入可以指挥它生成特定破坏代码;③ 就算没有恶意,幻觉出的 API 调用、写错的路径也可能覆盖文件——威胁不只有「坏人」,还有「写错的代码」。
- **为什么进程内限制不算沙箱**:`exec(code, {"__builtins__": {}})` 看着安全,但 Python 对象模型提供了太多逃逸口:通过 `object.__subclasses__()` 一路摸到任意类,再经 `__globals__` 找回被没收的 builtins。**进程内没有安全边界**——要拦「删文件」必须在文件系统层拦,要拦「外联」必须在网络层拦。所以沙箱必须是进程/系统边界(容器、微 VM),而不是改几个解释器参数。

## 3. 作用:沙箱在调用链中的位置

```
① 模型输出 run_python(code) → 参数校验(代码长度、字符集)
        │
        ▼
② 预检:可选的导入白名单;写入路径必须落在工作区内
        │
        ▼
③ 隔离执行:容器/子进程 + 非 root + 只读根文件系统
        │
        ▼
④ 资源闸:CPU 与内存上限 + 硬超时,超时即 kill
        │
        ▼
⑤ 网络闸:默认禁网,确需出网时走显式白名单代理
        │
        ▼
⑥ 输出闸:stdout/stderr 截断 → 按不可信内容回填(呼应 03 章)
```

- 沙箱是一道**信任边界**:边界内是模型生成的不可信代码,边界外是课程数据与主机。五道缓解的作用是让这道边界变厚——任何一层被绕过,后面还有一层,这就是纵深防御。

## 4. 详细介绍:五道缓解措施

| 缓解 | 防什么 | 工程手段 |
|---|---|---|
| ① 隔离容器 | 系统破坏、持久化 | Docker/微 VM,只读根文件系统,非 root 用户,只挂载一个临时写目录 |
| ② 超时与资源上限 | 死循环、内存爆炸 | 硬超时(如 30 秒)、内存上限、进程数上限,超时强杀 |
| ③ 禁止网络 | 数据外泄、SSRF、横向移动 | 默认无网卡、无 DNS;确需外联走显式代理白名单 |
| ④ 输出截断 | 回填爆炸、上下文污染 | stdout/stderr 各限 4~8KB,超出部分提示「已截断」 |
| ⑤ 人工确认 | 越权动作 | 写出工作区、装包、出网等高危动作需人工批准(06 章权限层) |

### 4.1 案例:数据分析 Agent 的安全执行器(本机演示版)

```python
# safe_runner.py —— 带工作区、超时、截断的代码执行器(演示版)
import subprocess
import tempfile
from pathlib import Path

MAX_OUT = 4096        # 输出截断上限(字节)
TIMEOUT_SEC = 20      # 硬超时(秒)


def run_code(code: str, data_dir: Path) -> dict:
    """在临时工作区执行模型生成的代码,返回截断后的 stdout/stderr。"""
    with tempfile.TemporaryDirectory(prefix="sandbox_") as tmp:
        work = Path(tmp)
        (work / "data").symlink_to(data_dir.resolve())   # 数据以只读链接暴露
        script = work / "task.py"
        script.write_text(code, encoding="utf-8")
        try:
            proc = subprocess.run(
                ["python3", str(script)],
                cwd=work, capture_output=True, text=True,
                timeout=TIMEOUT_SEC,
            )
        except subprocess.TimeoutExpired:
            return {"ok": False, "error": f"超过 {TIMEOUT_SEC} 秒被终止", "stdout": ""}
        return {
            "ok": proc.returncode == 0,
            "stdout": proc.stdout[:MAX_OUT],
            "stderr": proc.stderr[:MAX_OUT],
        }
```

- 这段演示版实现了「工作区 + 超时 + 截断」三道,足够观察超时与回填控制;真实部署还缺容器隔离与禁网,见 4.2。
- 课程助教生成的分析代码就这样跑:读写都发生在临时工作区,超时即杀,输出截断后回填。注意「数据只读链接」只能防代码误改原数据,**防不了恶意代码读走后外传**——所以生产环境必须禁网,这就是 4.2 的事。

### 4.2 生产形态:容器化沙箱

- OpenAI Code Interpreter 的公开说明是行业样板:代码在隔离容器里执行,默认无网络,会话结束环境即销毁,有运行时长与内存限制——把「一次性、无网、限资源」三条写死。
- 本地自建的最小方案:Docker 跑一个瘦镜像,`--network none` 禁网、`--memory`/`--cpus` 限资源、非 root 用户、只读根文件系统,只挂载只读数据卷与一个临时写目录;模型生成的代码进容器跑,结果只经 stdout 出来。
- 宁可功能少:沙箱镜像里不装 ssh、curl、gcc 等与任务无关的工具,缩小被利用面(呼应 03 章的「功能过多」)。

## 6. 边界与排错

- **沙箱不是保险箱**:历史上出现过多次容器逃逸与解释器逃逸,沙箱的承诺是「把风险压到可接受」而不是「归零」;敏感数据要么不进沙箱,要么先进沙箱前先脱敏;别把全部希望押在禁网一层,纵深防御。
- **超时误杀长任务**:真实分析可能超过 30 秒。缓解:合理调大超时上限;限制的是「单次运行」而非「总轮次」;让代码把中间结果写文件、分多次执行(呼应 02.03 的任务分解)。
- **输出截断丢结果**:截断只影响回填文本,不影响文件——让代码把完整结果写入工作区文件,再由只读工具取回,又一次「只读优先」(呼应 03 章)。
- **错误信息也是输入**:回填的 stderr 可能含有来自数据的恶意文本,同样按不可信内容处理。
- 排错:① 超时频繁——先确认不是死循环,再看数据量是否超预算;② 代码没写文件却报权限错——确认容器内是非 root、根文件系统只读;③ 模型生成的代码总写绝对路径——把工作区路径通过环境变量传进去,并在 system prompt 里明确「所有路径都基于工作区」。

## 7. 总结

| 概念 | 一句话 |
|---|---|
| 代码执行工具 | 模型生成整段代码并执行,代码 = 权限 |
| 典型危害 | 删文件 / 网络外联 / 资源耗尽 / 持久化后门 |
| 进程内限制 | 可被对象模型逃逸,不是沙箱 |
| 五道缓解 | 隔离容器 / 超时 / 禁网 / 输出截断 / 人工确认 |
| 生产形态 | 容器 + 非 root + 只读根文件系统 + 默认无网 |

**思考题**:为什么「把模型生成的代码放进 docker 再执行」只是开始,还要做禁网与非 root?演示版的 `run_code()` 拦得住死循环,为什么拦不住代码里的 `Path("/etc/passwd").read_text()`?

> [!note] 参考答案
> Docker 提供进程与文件系统边界,但容器默认与宿主共享内核与网络——不设 `--network none`,代码照样外联;不以非 root 运行,一旦逃逸就是 root。`run_code()` 的隔离只是「换了个工作目录 + 超时」,Python 进程本身的权限与宿主一致,绝对路径读取照样生效;要拦它,必须让文件系统本身限制可见范围(只读根文件系统 + 唯一可写卷),这只有容器/VM 层做得到。
