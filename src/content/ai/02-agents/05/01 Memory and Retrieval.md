# Memory and Retrieval

> 模块定位：LLM 是无状态的——每次请求都「失忆」。Agent 要跨轮、跨会话工作，必须自己管理记忆。本模块覆盖记忆的分类、短期（会话内）与长期（跨会话）记忆的实现、检索增强（RAG）在 Agent 中的角色，以及记忆的隐私与一致性问题。

**学习目标**：完成本模块后，你将能够——

1. 说清 Agent 记忆的四种形态（工作记忆/情景记忆/语义记忆/程序记忆的通俗对应）；
2. 用 SQLite 或 JSON 实现短期对话记忆与会话压缩；
3. 用向量检索实现长期语义记忆；
4. 把 RAG 集成进 Agent 工具链，理解检索在规划中的位置；
5. 识别记忆污染、遗忘与 PII 风险，设计记忆清理策略。

## 子主题清单（每章讲义要点）

### 01 记忆的分类与需求
- 概念：工作记忆（上下文窗口内）、情景记忆（本会话发生的事）、语义记忆（跨会话事实）、程序记忆（技能/工具用法）
- 为什么 LLM 需要外部记忆：模型权重是「慢知识」，上下文是「快记忆」，都不持久
- 记忆要解决的三问：记什么、存多久、怎么取
- 对照人类记忆的隐喻：便签 vs 笔记本 vs 图书馆

### 02 会话记忆与会话压缩
- 概念：多轮对话把历史塞回上下文；但历史无限增长 → 压缩
- 取舍：完整历史（保真/费 token）vs 摘要历史（省 token/丢细节）
- 技术：滑动窗口、滚动摘要、关键事实抽取
- 动手：实现一个带「摘要+最近 N 轮」的记忆类，观察长对话下的行为差异

### 03 长期记忆：外部存储
- 概念：跨会话记住用户偏好、项目状态 → 存到 SQLite/JSON/向量库
- 为什么需要：真实 Agent 要记住「学员上次学到第几章」
- 读写时机：何时写入（任务结束/关键事实出现）、何时读取（任务开始）
- 动手：课程助教记住「学员进度」的长期记忆模块

### 04 向量检索与语义记忆
- 概念：把文本变向量，按语义相似度取回（复用 01.04 的 embedding 知识）
- 为什么需要语义检索：精确匹配找不到「意思一样说法不同」的内容
- 流程：切块 → embedding → 入库 → 查询 top-k → 拼入上下文
- 动手：给课程助教加一个课程资料向量库，验证查得准/查不准的情形
- 局限：相关性≠正确性，检索片段仍要当不可信内容处理

### 05 RAG 在 Agent 中的角色
- 概念：RAG 是 Agent 的一个工具（检索工具），不是 Agent 本身
- 什么时候先检索：知识密集任务、需引用来源的任务
- 检索-规划联动：先检索再规划 vs 边规划边检索（Agentic RAG 思路）
- 与 01.05 图文检索、01.02 数据质量纪律的呼应
- 评测：检索命中率、引用正确性（02.07 展开）

### 06 记忆的隐私、污染与遗忘
- 概念：记忆可能存了不该存的（PII）、记了错的（污染）、忘了该忘的
- 风险：跨用户记忆串扰、注入内容污染长期记忆、隐私泄漏
- 设计：记忆最小化、按用户隔离、删除流程、审计（呼应 01.07 数据治理）
- 动手：为记忆模块写 data-governance 附录：存了什么、留多久、如何删
