# Evaluation and Observability

> 模块定位：普通 LLM 评测（01.06）评「一句话答得好不好」；Agent 评测评「一串行动是否达成目标」。本模块覆盖轨迹级与任务级指标、Agent 专用评测方法、tracing 可观测性，以及怎么把评测接进开发循环。

**学习目标**：完成本模块后，你将能够——

1. 说出 Agent 评测与普通 LLM 评测的三个本质差异；
2. 定义轨迹级指标（步数/工具选择正确率/无效步）与任务级指标（完成率）；
3. 用黄金任务集 + LLM-as-judge 评测 Agent 轨迹；
4. 用 tracing（Langfuse 或自建 JSON 日志）定位失败发生在哪一步；
5. 把评测与回归测试接进开发循环（每次改动跑一遍）。

## 子主题清单（每章讲义要点）

### 01 Agent 评测的特殊性
- 概念：评测对象从「单输出」变成「多步轨迹 + 最终结果 + 副作用」
- 三个差异：结果开放（无唯一答案）、过程重要（走错路也算错）、副作用要测（工具调用副作用）
- 为什么难：一次失败可能源于模型/提示/工具/记忆/编排任一环（呼应 02.06 级联错误）
- 评测分层：单步层 → 轨迹层 → 任务层 → 系统层（成本/安全）

### 02 轨迹级指标
- 概念：评价 Agent 每一步走得对不对：工具选择正确率、参数正确率、无效步占比、死循环率
- 为什么需要：任务成功了但绕远路/瞎试，说明规划与工具选择有问题
- 指标定义表：每指标怎么算、什么信号是异常
- 动手：给课程助教 Agent 的 10 条轨迹逐条标「步类型」，统计无效步占比

### 03 任务级指标与黄金任务集
- 概念：只看最终目标达没达成：完成率、成功率、部分完成度
- 黄金任务集：人工审核过的「任务 → 期望行动路径 → 期望结果」（呼应 01.06 黄金集纪律）
- 去污染：评测任务不得出现在模型的训练/微调数据里
- 动手：为课程助教建 golden-tasks.jsonl（10 条含边界与失败任务）

### 04 LLM-as-judge 评轨迹
- 概念：用强模型按 rubric 评 Agent 轨迹（呼应 01.06 LLM-as-judge）
- 评什么：任务达成度、工具选择合理性、是否高效、是否安全
- 防偏差：给裁判示例、结构化输出、人工抽检一致率
- 动手：写 judge 提示词评 5 条轨迹，与人工评分对比报告一致率

### 05 Tracing：看得见 Agent 内部
- 概念：tracing = 记录每次调用的完整链路（输入/工具调用/中间思考/耗时/成本）
- 为什么需要：Agent 是黑盒循环，不追踪就无法定位失败步
- 记录字段：step、类型（thought/action/observation）、工具名、参数、结果摘要、token、耗时
- 工具：Langfuse / LangSmith / 自建 JSONL 日志（呼应 01.04 的运维日志纪律）
- 动手：给 Agent 加结构化日志，重放一次失败任务并指出失败步

### 06 回归评测与开发循环
- 概念：每次改提示/工具/记忆都重跑评测集，防「修好一个坏十个」
- 流程：改代码 → 跑单测 → 跑轨迹评测 → 人工抽检 → 记录
- CI 化：pytest 包装评测任务，作为提交门禁
- 成本控制：全量评测贵 → 先小集快速回归，再全量
- 动手：把课程助教评测写成 pytest，跑通「改一行提示后评测仍通过」的闭环

## 交付物与验收标准

| 章 | 交付物 | 验收 |
|---|---|---|
| 02 | 轨迹标注 + 无效步统计 | 能指出轨迹哪步无效、为什么 |
| 03 | golden-tasks.jsonl | 覆盖成功/边界/失败三类任务 |
| 05 | 结构化 trace | 从日志重放出失败链路 |
| 06 | pytest 评测闭环 | 一次代码改动后自动评测出报告 |
