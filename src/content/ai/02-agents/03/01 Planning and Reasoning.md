# Planning and Reasoning

> 模块定位：单步工具调用只能做「一问一工具」的任务。真实任务（写一份调研报告、修一个 bug）需要先想清楚步骤、执行中根据观察调整、失败时重试。本模块覆盖从 CoT 到 ReAct 再到 Plan-and-Execute 的规划能力谱系。

**学习目标**：完成本模块后，你将能够——

1. 区分单步推理与多步规划，说清各自适用场景；
2. 实现 ReAct（推理与行动交错）并解释为什么比纯推理好；
3. 实现 Plan-and-Execute（先计划后执行）并对比 ReAct 的取舍；
4. 给 Agent 加自我修正与重试，处理失败而不死循环；
5. 设定步数/成本预算，让 Agent 在失控前停下。

## 子主题清单（每章讲义要点）

### 01 为什么 Agent 需要规划
- 概念：规划 = 把目标分解为子目标与步骤序列
- 为什么需要：复杂任务无法一步生成答案；中间结果依赖外部观察
- 无规划的形态：单步问答 / 简单工具调用（什么时候够用）
- 规划的代价：更多 token、更多失败点、更难评测 → 何时不必规划

### 02 Chain-of-Thought 与单步推理
- 概念：CoT——让模型先「想」再答，中间推理可见
- 为什么有效：推理链让模型逐步利用上下文（呼应 02.02）
- 形式：zero-shot CoT（「请逐步思考」）、few-shot CoT
- 局限：CoT 是一次生成，不能真正调用外部信息 → 需要 ReAct

### 03 ReAct：推理与行动交错
- 概念：Thought → Action → Observation 循环；推理穿插在行动之间
- 为什么有效：想一步做一步，观察结果修正下一步（对照 CoT 的纯脑内推理）
- 原始论文思想（Yao et al., 2022）与现在 function calling 的实现关系
- 动手：在 02.01 的最小 ReAct 上加「规划感」：多步工具调用

### 04 Plan-and-Execute 与任务分解
- 概念：先让模型产出完整计划，再逐项执行；对比 ReAct 的边想边做
- 为什么需要：任务可预分解时（如报告=搜集+大纲+撰写+校对）计划先行更省
- 两种模式对比表：ReAct（灵活/贵/易漂移）vs Plan-and-Execute（省/僵/计划过期）
- 变体：计划可修订、子任务可嵌套、并行子任务（LLMCompiler 思路）

### 05 失败处理与自我修正
- 概念：Agent 执行会失败：工具报错、结果不符、计划过时
- 失败分类：可重试（瞬时错误）/ 需换法（工具不对）/ 需放弃（任务不可达）
- 自我修正模式：Reflexion 思想——把失败反馈写回上下文再试
- 防死循环：最大步数、重复动作检测、成本上限（呼应 02.07 评测）

### 06 规划评测与预算
- 概念：怎么判断「规划得好」：任务完成率、步数、无效步占比、成本
- 轨迹级 vs 任务级指标预告（02.07 展开）
- 动手：同一任务分别用 ReAct / Plan-and-Execute 跑 3 次，记录步数/token/成功率
- 结论：没有免费午餐——规划能力要用评测与预算约束
