# 结构化输出约束

> 03 章用少样本示例教会模型「照葫芦画瓢」,可「像」不等于「能用」:课程助教出的题要存进题库,批改结果要写回成绩表,决定检索时要把参数交给工具——这些下游全是确定性代码,只认机器可读的数据。本章讲**结构化输出约束**:让模型的输出不是自由文本,而是受 schema 约束的 JSON。你会看到三种约束手段(提示要求、response_format、function calling)谁强谁弱,搭起「解析→校验→重试」的闭环,并亲手写一个遇到非法 JSON 不崩溃的解析器。

**学习目标**:学完本章,你将能够——

1. 说出结构化输出的两层含义:语法合法(valid JSON)与形状合规(符合 schema);
2. 解释为什么「Agent 的下游是代码」意味着自由文本输出不可接受;
3. 对比提示要求 JSON、response_format、function calling 三种手段的约束强度与适用场景;
4. 搭出「解析→schema 校验→失败重试→耗尽降级」的校验闭环;
5. 用代码处理模型输出的围栏、散文、类型错等污染,验证解析器不崩溃。

## 1. 概念:结构化输出是什么

- **结构化输出(structured output)**:与模型约定——不要散文,给我一份「代码能直接消费的数据」。实践中几乎总是 JSON,再用 **schema**(JSON Schema)把字段名、类型、取值集合一并固定。
- 「结构化」有两层,任何一层失败都不算数:**语法层**——是合法 JSON,能通过 `json.loads`;**形状层**——键齐全、类型正确、枚举取值合法。
- 课程助教「出一道题」的结构化约定:

```json
{
  "topic": "外键", "difficulty": "easy",
  "question": "外键的作用是?",
  "options": ["保证引用完整性", "加速查询"], "answer": 0
}
```
- `answer` 是正确选项的下标,代码拿到它才能自动判分——字段语义、取值含义都是协议的一部分,这正是「下游是代码」的含义;**模型说「我是 JSON」不算数**,它是概率采样器,不是格式化输出设备,只是「大多数时候恰好输出合法 JSON」。

## 2. 为什么需要:下游是代码

| 不约束输出的后果 | 课程助教实例 |
|---|---|
| 散文裹着 JSON | 「好的!题目如下:{…} 这题难吗?」→ `json.loads` 直接抛异常 |
| 字段名漂移 | 今天叫 `answer`,明天叫 `correct_index`,入库与判分代码全部对不上 |
| 类型漂移 | `answer` 给了 `"1"`(字符串),判分代码按整数比较就出错 |
| 概率性失约 | 只保证语法的 JSON mode 实测合规率约 95~98%,百万请求里仍有数万份坏的 |

- 自由文本是给人读的:人能容忍「嗯、那个、大概」,代码不能——让代码解析自由文本,等于为每种输出另写一套 NLP。
- 02.01 早有伏笔:运行循环从模型文本里「解析出 Action 再调用工具」靠的就是约定格式,那是最早的伪结构化输出;本章把它升级为 schema 级硬约束,因为**结构化输出不是格式偏好,而是模型与代码之间的接口协议**——协议不定义清楚,模型写得再漂亮,下游也接不住。

## 3. 作用:结构化输出在 Agent 里的位置

| Agent 环节 | 结构化输出的用途 | 课程助教实例 |
|---|---|---|
| 入口:意图理解 | 把用户问题解析成「意图+参数」,决定路由 | 「出个索引的题」→ `{"intent": "quiz", "topic": "索引"}` |
| 行动:工具调用 | 工具参数按 schema 生成,代码可直接执行 | `search_course(topic="索引", count=3)` |
| 内部:状态转移 | 每步产出机器可读动作,循环才能判定与终止 | ReAct 轨迹里的动作字段 |
| 出口:数据交付 | 结果直接入库、渲染,无需人肉转录 | 出题对象存题库、批改结果记成绩 |

## 4. 详细介绍:三种手段与校验闭环

### 4.1 手段一:提示里要求 JSON(最软)

- 写法:system prompt 加一句「只输出 JSON 对象,不要任何解释,不要 markdown 围栏」。
- 优点:零成本、任何模型都吃;弱点:**语法不保证**(可能裹散文、加围栏、用单引号),**形状不保证**(键名、类型、取值全看模型心情)。
- 适用:快速原型、非关键路径;它产出的文本正是 4.5 校验闭环要重点兜底的输入。

### 4.2 手段二:response_format(平台级保证)

- **JSON mode**:`response_format={"type": "json_object"}`。平台保证输出「语法合法的 JSON」但**不保证形状**;且提示里需出现 json 字样。
- **Structured Outputs**(OpenAI 2024-08 起):`response_format` 改用 json_schema 并开 strict,平台把 schema 编译进解码器、逐 token 屏蔽非法输出,官方称支持模型上形状符合率 100%。代价:strict 要求每个对象 `additionalProperties: false`、所有键都列入 required;返回后要先检查 `message.refusal`(模型拒答时 content 为空)。

```python
response_format = {   # chat.completions.create 的参数(openai 库,需 API key)
    "type": "json_schema",
    "json_schema": {"name": "quiz", "strict": True, "schema": QUIZ_SCHEMA},
}
```

### 4.3 手段三:function calling 参数约束(行动级)

- 请求里声明 tools,每个工具的 `parameters` 就是一份 JSON Schema;模型「决定调用工具」时,工具名只能从声明里选,参数按 schema 约束生成,返回结构化的 `tool_calls`(参数在 `function.arguments`,仍是字符串,要再 json.loads)。
- 与手段二的区别:手段二约束**回话内容**,手段三约束**行动参数**。OpenAI 官方指引:模型要「调用工具」用 function calling,要「交付数据」用 structured outputs。
- 课程助教实例:声明 `search_course(topic, level)` 工具,参数 schema 只允许这两个键——模型想传 `course_name` 都「生成不出来」,非法 token 在采样时就被屏蔽。
- 呼应 02.01:运行循环里 Action 的参数从此由平台背书,不再靠正则从散文里抠。

### 4.4 三种手段对比

| 手段 | 约束发生在 | 语法保证 | 形状保证 | 适用场景 |
|---|---|---|---|---|
| 提示要求 JSON | 提示词 | 无 | 无 | 原型、非关键路径 |
| JSON mode(json_object) | 平台解码 | 有 | 无 | 只要「合法 JSON」即可 |
| Structured Outputs(json_schema) | 平台解码 | 有 | 有 | 模型交付结构化数据 |
| function calling | 平台解码+行动声明 | 有 | 有(参数级) | 模型要调用工具 |

- 手段从软到硬,但都改变不了一件事:返回给你的仍是文本/对象,**代码侧的校验一步都不能省**。

### 4.5 校验闭环:不能只信「模型说它是 JSON」

- 平台保证不等于万无一失,还有三类失败它管不到:**拒答**(refusal,content 为空)、**截断**(finish_reason 为 length,JSON 只生成一半)、**语义错**(enum 值合法但内容不对,如把难题标成 easy)。
- 闭环五步:① 调用后先查 `message.refusal` 与 `finish_reason`;② 清理污染(围栏/散文)后 `json.loads`;③ 按 schema 校验键、类型、枚举;④ 失败就把错误原文拼回提示、限次重试;⑤ 重试耗尽显式降级(交人工或换问法),**绝不把坏数据喂给下游**。
- 心智模型:**模型输出与用户输入、网页抓取同级,都是不可信内容**——信任靠代码校验,不靠模型承诺(呼应 01.07,06 章展开提示注入)。

## 5. 动手活动:写解析器处理非法 JSON 并重试

> [!example] 动手活动:robust_quiz_parser.py——非法 JSON 检出、修复与重试
>
> **目标**:运行下方解析器,模拟出题模型连续三次输出(语法非法→违反 schema→完全合法),验证前两次被检出并触发重试、第三次成功,全程不崩溃。真实接入时把 `simulate_model` 换成 `client.chat.completions.create(...)`,并把重试错误拼进 messages 再调用。
>
> **运行方式**:保存为 `robust_quiz_parser.py` 后执行 `python3 robust_quiz_parser.py`(纯 Python 3,无第三方依赖)。
>
> ```python
> # robust_quiz_parser.py:课程助教出题解析器——检出非法 JSON 并重试(运行:python3 robust_quiz_parser.py,纯 Python 3 无依赖)
> import json
> SCHEMA = {   # 期望的出题对象形状(JSON Schema 的简化手写版)
>     "required": ["topic", "difficulty", "question", "options", "answer"],
>     "types": {"topic": str, "difficulty": str, "question": str, "options": list, "answer": int},
>     "enum": {"difficulty": ["easy", "medium", "hard"]},
> }
> def simulate_model(attempt):   # 模拟「收到反馈后越改越好」的三次输出
>     if attempt == 1:   # ① 语法非法:用了单引号,还裹着 ```json 围栏
>         return "```json\n{'topic': '外键', 'difficulty': 'easy', 'question': '外键的作用是?', 'options': ['保证引用完整性', '加速查询'], 'answer': 0}\n```"
>     if attempt == 2:   # ② 形状违规:difficulty 不在枚举里,answer 是字符串
>         return '{"topic": "索引", "difficulty": "very-hard", "question": "以下哪列适合建索引?", "options": ["性别列", "频繁查询的列"], "answer": "1"}'
>     return '{"topic": "事务", "difficulty": "medium", "question": "ACID 中的 C 指什么?", "options": ["一致性", "并发", "缓存"], "answer": 0}'   # ③ 完全合法
> def extract_json(text):   # 按首尾花括号截取,围栏与前后散文被天然排除
>     start, end = text.find("{"), text.rfind("}")
>     if start == -1 or end <= start:
>         raise ValueError("文本中找不到 JSON 对象")
>     return text[start:end + 1]
> def validate(obj):   # 简化版 schema 校验;生产环境请用 jsonschema 库
>     problems = []
>     if not isinstance(obj, dict):
>         return ["根节点不是 JSON 对象"]
>     for key in SCHEMA["required"]:
>         if key not in obj:
>             problems.append("缺少必填字段:%s" % key)
>         elif not isinstance(obj[key], SCHEMA["types"][key]) or (SCHEMA["types"][key] is int and isinstance(obj[key], bool)):   # bool 是 int 的子类,要排除
>             problems.append("%s 类型错误,期望 %s" % (key, SCHEMA["types"][key].__name__))
>     if "difficulty" in obj and obj["difficulty"] not in SCHEMA["enum"]["difficulty"]:
>         problems.append("difficulty 取值不在 %s 中" % SCHEMA["enum"]["difficulty"])
>     if "options" in obj and isinstance(obj["options"], list) and len(obj["options"]) < 2:
>         problems.append("options 至少要有 2 个选项")
>     return problems
> def parse_and_validate(text):
>     try:
>         obj = json.loads(extract_json(text))
>     except (ValueError, json.JSONDecodeError) as exc:
>         return None, "JSON 解析失败:%s" % exc
>     problems = validate(obj)
>     if problems:
>         return None, "schema 校验失败:" + "; ".join(problems)
>     return obj, None
> def main():
>     for attempt in range(1, 4):   # 初始 1 次 + 最多重试 2 次
>         obj, error = parse_and_validate(simulate_model(attempt))
>         if obj is not None:
>             print("第 %d 次尝试成功,题目:%s[%s],选项:%s" % (attempt, obj["question"], obj["difficulty"], obj["options"]))
>             return
>         print("第 %d 次尝试失败:%s,错误已拼回提示让模型重出" % (attempt, error))
>     print("重试耗尽,降级:把模型原始文本交给人工处理")
>     raise SystemExit(1)   # 显式失败,不把坏数据喂给下游
> if __name__ == "__main__":
>     main()
> ```
>
> **完成标准**:输出能区分两类失败(JSON 解析失败、schema 校验失败)并各重试一次,第三次打印题目与选项;把 `simulate_model` 改为返回空字符串,程序应打印「重试耗尽」并以退出码 1 结束,而不是抛异常或把坏数据传下去。

## 6. 边界与排错

| 症状 | 原因 | 处理 |
|---|---|---|
| schema 报「不支持」 | strict 模式限制多(additionalProperties、required 全列) | 按平台约束改写 schema,字段能少则少 |
| 解析器频繁重试 | 提示与 schema 不一致(示例没对齐格式) | 检查示例与 schema 是否同构(呼应 03 章) |
| 模型拒答、content 为空 | 安全策略触发 | 先查 refusal 再解析,按产品策略处理 |
| 重试成本失控 | 每次重试都真调一次模型 | 限 2~3 次并退避;耗尽即降级 |

- 边界提醒:enum 能挡住「取值范围」,挡不住「值合法但语义错」——难题标成 easy,只有业务校验(难度抽检)能发现;不同供应商与自部署模型的 json_schema 支持不一致,有的只支持 json_object,把「平台保证」当优化、把「本地校验」当底线。

## 7. 总结

| 概念 | 一句话 |
|---|---|
| 结构化输出 | 输出为代码可消费的 JSON,并由 schema 固定形状与语义 |
| 为什么需要 | Agent 下游是代码:入库、判分、路由都需要机器可读 |
| 三种手段 | 提示要求(软)→ response_format(平台硬)→ function calling(行动硬) |
| 校验闭环 | 解析→schema 校验→失败重试→耗尽降级 |
| 铁律 | 模型输出是不可信内容,信任靠代码校验,不靠模型承诺 |

**思考题**:为什么「模型 95% 的时候输出合法 JSON」依然不够?如果供应商只支持 JSON mode(不保证形状),你的校验闭环要额外增加哪一步?

> [!note] 参考答案
> 概率性失约:95% 合规意味着百万级请求里有数万份坏输出,而入库、判分、路由全是确定性代码,一次坏输入就可能中断整条链路;且那 5% 的失败模式不可预测,无法在提示里穷举。只支持 JSON mode 时形状无人背书:必须自己声明期望的键集,补上「必需键齐全、类型正确、枚举合法」的形状校验,失败即重试。
