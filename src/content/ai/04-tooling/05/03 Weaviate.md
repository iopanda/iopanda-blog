# Weaviate

> 模块定位：从「对象与向量并存、偏 schema / module 生态的路线」这条路线理解 Vector Databases and Retrieval。这一目录先不急着写成产品手册，而是先抓住它的设计中心——objects + vectors、modules、cloud-native。

**本目录计划关注**：
1. Weaviate 为什么会出现，它优先解决什么问题；
2. 它的核心抽象、部署形态与集成方式；
3. 它与同组其他产品相比的设计中心差异；
4. 它在课程助教或企业内部 AI 系统中的自然落点；
5. 什么时候适合用它，什么时候不该先用它。

## 建议拆分主题

1. 它把哪类 retrieval 复杂度当作一等问题
2. 数据模型、过滤与更新语义
3. 规模化与运维形态
4. 与其他后端相比的边界
5. 课程助教知识库中最自然的使用方式

## 适合谁

- 重视对象建模与可扩展生态的团队
- 学习重点不是 API 清单，而是它默认把什么复杂度提前结构化了。
