# FiftyOne

> 模块定位：从「以样本浏览、可视化与数据集精炼为核心」这条路线理解 Data Curation and Annotation。这一目录先不急着写成产品手册，而是先抓住它的设计中心——dataset visualization、slicing、error analysis。

**本目录计划关注**：
1. FiftyOne 为什么会出现，它优先解决什么问题；
2. 它的核心抽象、部署形态与集成方式；
3. 它与同组其他产品相比的设计中心差异；
4. 它在课程助教或企业内部 AI 系统中的自然落点；
5. 什么时候适合用它，什么时候不该先用它。

## 建议拆分主题

1. 它更偏标注台、反馈台、质检工具还是可视化工作台
2. 核心数据对象是什么
3. 如何支撑训练/评测/RAG 的数据循环
4. 与同类产品相比适合什么团队
5. 课程助教数据集如何落地

## 适合谁

- 多模态或需要强可视化探索的团队
- 学习重点不是 API 清单，而是它默认把什么复杂度提前结构化了。
