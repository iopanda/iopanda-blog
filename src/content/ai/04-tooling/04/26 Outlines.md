# Outlines

> 模块定位：从「把结构化输出与约束生成做成默认能力」这条路线理解 Prompt Management。这一目录先不急着写成产品手册，而是先抓住它的设计中心——JSON/schema/CFG style constraints。

**本目录计划关注**：
1. Outlines 为什么会出现，它优先解决什么问题；
2. 它的核心抽象、部署形态与集成方式；
3. 它与同组其他产品相比的设计中心差异；
4. 它在课程助教或企业内部 AI 系统中的自然落点；
5. 什么时候适合用它，什么时候不该先用它。

## 建议拆分主题

1. 它把 prompt 看成模板、测试对象还是程序对象
2. 核心抽象与工作流
3. 如何验证 prompt 变更
4. 与结构化输出/约束生成的关系
5. 在课程助教 system prompt 上如何落地

## 适合谁

- 首先关心结构稳定性的团队
- 学习重点不是 API 清单，而是它默认把什么复杂度提前结构化了。
