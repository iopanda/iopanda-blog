# 质量、价格与采用边界

> Promptfoo 的优势在于：MIT 开源、开发者 adoption 强、可以本地运行 prompt 测试、还能走 Enterprise 与 On-Prem 路线。但真正做选型时，要看清它的强项在哪：它更像验证层而不是资产层，价格和价值也围绕“测试与安全门禁”展开。[2][3][4][7][8]

**学习目标**：学完本章，你将能够——

1. 从社区规模和更新节奏判断 Promptfoo 的成熟度；
2. 理解其 Community、Enterprise、On-Prem 的边界；
3. 判断 Promptfoo 在 prompt management 里的最佳位置；
4. 区分软件便宜与流程 adoption 成本；
5. 做出更现实的采用判断。

## 1. 社区规模与活跃度

GitHub API 显示 Promptfoo 大约有 24k+ stars、2k+ forks，并保持很高更新频率。[3]

这说明：
- 它不是边缘工具；
- 社区足够大；
- 提示词测试与 red teaming 已是主流需求的一部分。

## 2. 价格结构

Pricing 页面明确写到：
- Community / Free Forever；
- Enterprise；
- Enterprise On-Prem；
- 并且社区版已包含核心本地 testing、evaluation、vulnerability scanning。[7]

这意味着 Promptfoo 在 prompt management 里的进入门槛很低：团队不需要先买平台，就能开始做 prompt 测试和回归。

## 3. 真实成本在哪里

Promptfoo 的真实成本主要不在 license，而在：
- 你是否愿意维护 test cases；
- 你是否愿意给 prompt 写 assertions；
- 你是否把它接进 CI/CD；
- 团队是否愿意把 prompt 改动纳入发布门禁。

也就是说，它的 adoption 成本是“纪律成本”，不是“安装成本”。

## 4. 采用边界

最适合：
- prompt 频繁变化；
- 有 PR / CI 流程；
- 需要在不同模型间比较 prompt；
- 想和 Langfuse 之类资产层协同的团队。

不一定适合：
- 只想存 prompt；
- 不打算建立测试样本；
- 几乎没有正式发布流程的团队。

## 5. 为什么它能与 Langfuse Prompts 共存

Promptfoo 不一定要取代资产层。Langfuse integration 文档已经说明，它完全可以站在 Langfuse Prompt labels / versions 下游做验证。[6]

所以它的边界很清晰：
- Langfuse Prompts：管理 prompt 资产；
- Promptfoo：验证 prompt 变更是否可放行。

## 6. 总结

| 关键问题 | 一句话 |
|---|---|
| 成熟度如何 | 主流开源 prompt 测试工具 [3] |
| 价格如何 | 社区版进入门槛低，企业版面向协作与治理 [7] |
| 最大优势是什么 | 低成本把 prompt 变更纳入回归与门禁 |
| 最大边界是什么 | 不是资产层，不负责完整 prompt 生命周期 |
| 最适合谁 | 有测试与发布纪律的团队 |

**思考题**：为什么 Promptfoo 在 prompt management 里的价值，很大程度上取决于团队是否愿意建立测试纪律？

> [!note] 参考答案
> 因为 Promptfoo 提供的是验证能力，不自动替团队写出测试样本、断言和发布流程。若团队没有把 prompt 当生产变更来管理，工具本身再好，也难以发挥最大价值。
