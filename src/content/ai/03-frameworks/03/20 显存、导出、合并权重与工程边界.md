# 显存、导出、合并权重与工程边界

> PEFT README 里最有工程味的部分，是它不只讲“怎么训练”，还讲：消费级硬件上的显存收益、checkpoint 只有几 MB、可以 merge adapter、可以与量化一起使用、可以多个 adapter 共存。[17][18][19][23] 这说明 PEFT 真正解决的，不只是训练方法问题，还包括“训练后怎样存、怎样切、怎样切换、怎样部署”。

**学习目标**：学完本章，你将能够——

1. 理解为什么 PEFT 的工程价值一半在训练，一半在工件管理；
2. 说出 merge、adapter 切换、多 adapter、量化协作的意义；
3. 判断什么时候该保留 adapter 独立存在，什么时候该 merge；
4. 理解显存、磁盘、推理时延之间的真实权衡；
5. 为项目写出 adapter 工件策略卡。

## 1. 显存收益为什么重要

README 直接用表格展示：LoRA 在大模型上能显著降低 GPU/CPU 内存需求。[17]

这说明 PEFT 的价值不只是“参数少”，而是让某些本来 OOM 的训练方案变成可行。

## 2. adapter 工件为什么是独立设计对象

Quicktour 里明确指出：保存后的 adapter 往往只有 `adapter_config.json` 和 `adapter_model.safetensors` 两个小文件。[18]

这意味着 adapter 不只是训练副产品，而是正式工件：
- 可存储；
- 可传输；
- 可叠加；
- 可复用；
- 可按任务切换。

## 3. merge 为什么重要

LoRA 文档和 PeftModel 文档都强调：
- 可以把 adapter merge 进 base model；
- merge 后可消除额外推理开销。[19][23]

所以 adapter 不是一定永远独立存在。是否 merge，取决于：
- 你要不要动态切换任务；
- 你要不要最小推理延迟；
- 你要不要保留灵活组合。

## 4. 多 adapter 为什么是 PEFT 的工程亮点之一

Quicktour 里明确支持：
- 同一个 base model 上加多个 adapters；
- `set_adapter` 动态切换。[18]

这对产品和平台很重要：
- 同底座多任务；
- 按租户或按场景切换；
- 降低模型复制成本。

## 5. 总结

| 关键问题 | 一句话 |
|---|---|
| 显存收益意味着什么 | 很多本来训不了的方案变得可行 |
| adapter 工件为什么重要 | 它是可存储、可切换、可部署的正式工件 |
| merge 的意义 | 在灵活性和推理时延之间做取舍 |
| 多 adapter 的意义 | 一个 base model 服务多任务 |
