# 训练稳定性、评测与工程边界

> 一旦进入 TRL 世界，训练的难点就不再只是 loss 降不降，而是 rollout 是否稳定、reward 是否可靠、reference drift 是否可控、train-inference mismatch 是否被放大。[21][22][23][24] 也就是说，alignment training 的真正难点往往是工程边界，而不是公式本身。

**学习目标**：学完本章，你将能够——
1. 说出为什么 alignment training 比普通 SFT 更容易不稳定；
2. 理解 DPO、Reward、PPO、GRPO 分别会出现哪些工程风险；
3. 认识 rollout、reward hacking、KL、clip ratio、judge 这些指标为什么重要；
4. 判断何时该停留在离线偏好优化，何时值得进入在线 RL；
5. 为系统写一张 alignment 风险卡。

## 1. DPO 的稳定，不等于没有边界

DPO 文档强调它比 PPO-based RLHF 更简单稳定，[21] 但它仍然有自己的边界：
- 偏好数据本身是否干净；
- chosen/rejected 是否真的代表稳定偏好；
- `beta` 和 loss type 是否合理；
- reference model 是否设置得当。

所以 DPO 是“更稳”，不是“自动正确”。

## 2. Reward model 的核心风险是好坏标准漂移

RewardTrainer 文档本质上是在训练一个排序器。[24]
这意味着一旦奖励标准学偏，后续 PPO/GRPO 都会把偏差放大。
所以 reward model 的难点不是能不能训练，而是：
- 奖励信号是不是可信；
- 是否出现 reward hacking；
- 是否只会奖励表面模式。

## 3. PPO / GRPO 的难点是 rollout 与策略稳定性

PPO 文档里大量指标都在围绕策略更新稳定性：[22]
- KL
- entropy
- clipfrac
- ratio
- eos penalty

GRPO 文档则进一步暴露了更复杂的工程边界：[23]
- reward std
- clipped ratio
- vLLM train-inference mismatch
- importance sampling correction
- server/colocate 模式权衡

这说明 online RL 的复杂度远高于“再跑一个 trainer”。

## 4. 评测不是单点评分，而是证据链

在 TRL 里，真正靠谱的评测不是只看一个 reward 曲线，而是要同时看：
- offline eval
- reward / accuracy / margin
- sample completions
- judge-based preference rate
- 安全与拒答行为是否退化

也就是说，对齐训练的评测必须是证据链，而不是单指标崇拜。

## 5. 动手活动

> [!example] 输出 `trl-risk-card.md`
>
> 为你的 alignment 项目列 5 个风险：偏好数据噪声、reward 偏差、KL 漂移、train-inference mismatch、judge 不可靠。写一句结论：你要怎么证明模型是真的变好，而不是只在某个指标上更好看。

## 6. 总结

| 风险 | 一句话 |
|---|---|
| DPO 风险 | 偏好数据与 reference 设定不当 |
| Reward 风险 | 奖励学歪并被策略放大 |
| PPO / GRPO 风险 | rollout、KL、clip、reward hacking 带来不稳定 |
| 评测风险 | 单指标容易误导 |
| 正确做法 | 建立可审计、可追溯的评测证据链 |
