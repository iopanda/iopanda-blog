# 显存、分布式、评测与工程边界

> 统一训练工厂如果只会“组织配置”，价值还不够大。LLaMA-Factory 真正有分量的地方，是它把许多原本散落在底层训练栈里的能力往上抬成了工厂可选项：DeepSpeed、FSDP、FlashAttention、QLoRA、多种量化、vLLM/SGLang 推理、MMLU/C-Eval/CMMLU 等评测实践。[86][90][92] 这说明它并不只想做一个“好用的命令行”，而是想成为资源约束、方法约束和交付约束之间的协调层。

**学习目标**：学完本章，你将能够——

1. 理解为什么显存、分布式、评测、导出在训练系统里必须一起考虑；
2. 说出 LLaMA-Factory 怎样把 DeepSpeed/FSDP/QLoRA 等能力纳入统一入口；
3. 判断什么时候该用全参、什么时候该用 LoRA/QLoRA；
4. 理解训练工厂与底层 infra 的边界；
5. 为一个受资源约束的项目写训练工程边界卡。

## 1. 显存不是优化问题，而是训练可行性边界

快速开始文档已经直接建议：
- 内存不足时用 LoRA 或 QLoRA；
- 减 batch；
- 开 gradient checkpointing；
- 用 DeepSpeed ZeRO-2/3。[90]

这说明显存从来不是“后续优化项”，而是你能不能训练、训练多大模型、如何选方法的第一道门。

## 2. README 暴露出的资源协调能力

README 明确支持：
- full-tuning
- freeze-tuning
- LoRA / QLoRA
- 多种量化
- DeepSpeed
- FSDP
- 多种加速技巧。[86]

这说明它真正的作用之一，是帮团队把“训练方法选择”和“资源现实约束”统一起来。

## 3. examples 目录为什么是工程边界教材

examples 里不仅有 LoRA / QLoRA / full tuning，还有：
- DeepSpeed ZeRO-3
- 多机 torchrun
- Ray
- FSDP+QLoRA
- merge LoRA
- vLLM 推理评估。[92]

所以 examples 在这里不只是 recipe catalogue，还是工程边界 catalogue：
- 你用什么硬件，应该挑什么 recipe；
- 你最终怎么推理，训练时就要想好导出形态。

## 4. 训练工厂和底层 infra 的边界

LLaMA-Factory 不是要替代 DeepSpeed、FSDP、Transformers、PEFT；
它更像把这些能力组织起来，变成上层更可用的训练工厂语言。

也就是说：
- 底层 infra 负责真正执行和优化；
- 工厂层负责把它们变成可选、可组合、可复用的 training recipe。

## 5. 动手活动

> [!example] 输出 `llamafactory-resource-boundary.md`
>
> 为一个 7B/14B/70B 模型项目分别写一张资源边界卡：硬件、训练方法、分布式后端、导出目标、评测方式。写一句结论：为什么资源约束和训练方法不能分开讨论。

## 6. 总结

| 关键问题 | 一句话 |
|---|---|
| 显存决定什么 | 决定你能训什么、怎么训 |
| 工厂层在做什么 | 把底层 infra 能力组织成更高层训练语言 |
| examples 的价值 | 它们既是 recipe，也是工程边界教材 |
| 真正的边界 | 工厂不替代 infra，但负责把 infra 收编成统一入口 |
