# 典型业务场景对比

> 上一篇的矩阵是“框架视角”，这一篇换成“场景视角”：把五个框架各自最擅长的场景抽出来，形成五类典型业务场景，并直接链接到各系列已经写过的案例篇（各自的 05）。这一篇也顺带讲清楚最容易踩的四类选型错配——它们本质上都是“场景判断错了”的具体表现。

**学习目标**：学完本章，你将能够——
1. 把“我的系统属于哪类典型场景”作为选型的第一道筛选；
2. 理解五类场景各自的核心特征和最合适的框架；
3. 识别四类常见错配，并知道每一类错配对应哪个判断环节出了问题；
4. 判断一个场景同时具备多类特征时该怎么拆解；
5. 为下一篇的课程助教综合选型卡打好基础。

## 1. 文档/知识库主导场景：对象组织是主矛盾

**典型特征**：知识来源以文档为主，元数据丰富，团队希望高度可编程地组织知识对象和查询对象。

**最合适**：[LlamaIndex](/ai/03-frameworks/02/02/)。对应案例：[课程助教 Agent 的 LlamaIndex 架构案例](/ai/03-frameworks/02/07/)。

## 2. 生产化检索链路场景：管道透明与评测是主矛盾

**典型特征**：需要显式控制 retrieval、rerank、filter、route、generation 每一步，需要稳定的 pipeline 评测机制，团队希望换组件、调链路都可控可测。

**最合适**：[Haystack](/ai/03-frameworks/02/09/)。对应案例：[课程助教 Agent 的 Haystack 架构案例](/ai/03-frameworks/02/14/)。

## 3. 完整知识平台场景：治理与协作是主矛盾

**典型特征**：异构文档很多，需要 dataset 管理、citation、权限、团队共享、testing 一体化，希望快速拿到完整平台而不是自己拼零件。

**最合适**：[RAGFlow](/ai/03-frameworks/02/16/)。对应案例：[课程助教 Agent 的 RAGFlow 架构案例](/ai/03-frameworks/02/21/)。

## 4. 关系驱动问答场景：图检索是主矛盾

**典型特征**：实体关系密集，跨文档、跨章节的概念关系和结构关系是回答质量的关键，简单向量召回难以覆盖“谁依赖谁、谁和谁相关”这类查询。

**最合适**：[LightRAG](/ai/03-frameworks/02/23/)。对应案例：[课程助教 Agent 的 LightRAG 架构案例](/ai/03-frameworks/02/28/)。

## 5. 实时知识流场景：新鲜度是主矛盾

**典型特征**：数据本身在持续变化（公告、FAQ、外部资料高频更新），更新语义比一次性构建精美索引更重要，静态离线索引会持续过期。

**最合适**：[Pathway](/ai/03-frameworks/02/30/)。对应案例：[课程助教 Agent 的 Pathway 架构案例](/ai/03-frameworks/02/35/)。

## 7. 常见错配：最容易踩的四类坑

这四类坑，本质上都是“场景判断错了”的具体表现：

### 7.1 把静态文档系统当成实时流系统
症状：一开始就上 Pathway，但数据其实很少变。
后果：心智和运维负担过重。

### 7.2 把复杂检索系统当成单索引问答
症状：所有知识域都丢进一个向量库。
后果：route、rerank、权限、引用全变糊。

### 7.3 把图检索当默认答案
症状：还没确认实体关系密度和图价值，就直接上 LightRAG。
后果：图抽取成本大于收益。

### 7.4 把平台当库，或把库当平台
症状：
- 想直接拿平台能力却选了高度可编程框架，结果自己拼平台；
- 想高度定制却直接上整机平台，结果被平台边界卡住。

## 8. 一个系统可能同时覆盖多类场景

课程助教就是最直接的例子：课程正文资料是文档主导场景，答疑链路需要生产化评测，跨章节概念关系是关系驱动场景，课程公告/FAQ 是实时知识流场景。下一篇会把这些子问题在同一个系统里拼成一张完整的选型卡。

## 9. 动手活动

> [!example] 动手活动：更新 `retrieval-framework-selection-card.md`
>
> 把你的系统拆成子系统，逐个对照第 6 节的速查表，标出每个子系统属于哪类场景、对应哪个框架；再检查一遍第 7 节的四类错配，看看有没有已经踩进去的信号。

## 10. 总结

| 关键问题 | 一句话 |
|---|---|
| 场景视角的价值 | 把“选框架”变成“先认场景”，降低误判概率 |
| 五类场景 | 文档主导 / 生产化链路 / 完整平台 / 关系驱动 / 实时知识流 |
| 四类常见错配 | 静态当流系统、单索引硬扛复杂检索、图检索当默认答案、平台与库错配 |
| 系统覆盖多场景怎么办 | 按子系统边界组合框架，而不是强求一个框架通吃 |
