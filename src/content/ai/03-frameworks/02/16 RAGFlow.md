# RAGFlow

> 模块定位：从“端到端 RAG engine”这条路线理解 RAG。RAGFlow 适合回答：如果团队不想先自己拼 ingestion、parsing、indexing、retrieval、agent context layer，而想先拿到一套完整 RAG 平台，系统应该怎么想？[43]

**本目录计划关注**：
1. RAGFlow 为什么把自己定义成 RAG engine，而不只是 library；
2. parsing、chunking、indexing、retrieval、agent context layer 的平台化思路；
3. 知识更新、平台工作流、权限与多用户场景；
4. 课程助教 / 企业知识平台案例；
5. 与 LlamaIndex、Haystack、LightRAG、Pathway 的对比。
