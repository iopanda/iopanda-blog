          diagram-design

          定位：一个面向 Claude Code、Codex、Pi 等 AI 助手的图示设计仓库，主打 38 种 editorial diagram types，用 HTML + SVG 直接出图。[2]

          为什么它排在第 2

          • GitHub Trending 月榜检索时，cathrynlavery/diagram-design 显示本月新增 30,797 stars，在本次 AI 相关项目筛选里排第二。[1]
          • 它踩中的不是“模型能力”本身，而是 AI 交付物审美升级：从能生成图，到要生成“能看、能讲、能演示”的图。[1][2]

          它是什么

          仓库自我描述是：38 editorial diagram types for Claude Code, Codex, and Pi，强调 self-contained HTML + SVG，以及 “No Mermaid slop”。这说明它在产品定位上非常鲜明：反对廉价感图示，强调视觉质量和表达质量。[2]

          为什么现在热

          随着 agent 被越来越多地用于写文档、写方案、写分析材料，图示不再只是工程师内部草图，而是面向团队协作和汇报的最终产物。diagram-design 的爆发，本质上是“AI 生成内容开始卷审美和表达”的信号。[1][2]

          我对它的判断

          它和 archify 一样，不是底层基础设施，但它代表的趋势非常重要：AI coding assistant 正在向“设计感交付”扩张。

          风险与边界

          如果你要的是通用 agent framework 或 model stack，这个项目不会直接解决底层问题；它解决的是输出表现层与图示质量问题。[2]
