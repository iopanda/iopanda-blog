          01.04.03

          模型量化

          2026-09-02 · iopanda

          • course
          • model-inference
          • quantization

          本章在同一任务上比较原精度与量化推理,目标是选出一个可用的配置,而不是盲目追求最小显存。你会先弄清权重为什么非得是小数、降低精度到底牺牲了什么,再动手跑原精度与 4-bit 两组对比,用任务结果做决定——量化是否成功,由评测说了算,不由「加载成功」说了算。

          学习目标:学完本章,你将能够——

          1. 解释为什么权重必须用浮点、为什么推理时又能容忍更低精度;
          2. 说出 FP32/FP16/BF16/INT8/4-bit 的含义、字节数与典型用途;
          3. 解释量化误差通过什么路径影响输出,为什么必须用固定任务评测;
          4. 区分训练后量化(PTQ)与训练中量化(QAT)两种时机与取舍;
          5. 检查硬件与依赖兼容性,判断某格式在本机是否可用;
          6. 测量显存、速度与输出质量,以任务证据选择配置。

          1. 概念:为什么权重是浮点

          • 神经网络权重是连续实数:预训练用梯度下降更新参数,每次更新的增量是任意小数,因此权重必须能表达连续取值,无法用整数硬存。浮点(float)用「符号位 + 指数位 + 尾数位」表示一个数,位数固定却能覆盖极大的动态范围——这正是训练与推理的默认格式。
          • 但推理阶段可以降精度:推理只做前向计算,不再需要梯度,权重不必保留完整精度。语言模型的输出由最后一层 logits 的相对排名决定,而 logits 是数亿个权重的平均贡献——单个权重错一点,往往不足以翻盘。这就是量化(quantization)能成立的根本原因:把每个权重从 32 位压缩到 16、8 甚至 4 位,换取显存与下载体积的大幅下降。
          • 一句话:训练需要高精度是因为要算梯度;推理只需要足够好的近似,因为要的是相对排名,不是精确数值。量化解决的是「资源不够」——显存装不下、带宽撑不住、下载太慢;它不保证更快、更准,也不保证在任何电脑上都能跑。
          • 收益核算:把每参数字节降下来,同时撬动三处成本——显存(装得下更大的模型或更长的上下文)、下载(模型文件体积同步缩小:0.5B 的 FP32 权重约 2 GB,4-bit 约 0.25 GB)、带宽(逐层读取更快)。但它不改变参数量,也不改变 KV cache 的占用——后者由序列长度决定,见 01 推理基础。

          2. 概念:精度格式一览:每一位都是钱

          先把常见格式的「位数 → 字节 → 结构 → 用途」对齐:

          格式 位数 每参数字节 结构(符号/指数/尾数) 含义与典型用途
          FP32 32 bit 4 B 1/8/23 单精度浮点,训练基准与 CPU 默认;0.5B 模型权重约 2 GB
          FP16 16 bit 2 B 1/5/10 半精度,指数范围窄(最大约 65504),消费级 GPU 训练/推理主格式
          BF16 16 bit 2 B 1/8/7 与 FP32 相同指数范围、尾数更粗;训练友好,无需 loss scaling
          INT8 8 bit 1 B 整数档位 + 缩放因子 把浮点范围映射到 256 个整数档;GPU 常带 INT8 加速单元
          4-bit 4 bit 0.5 B 16 个档位(NF4/FP4) 极低比特,几乎总配合「反量化回高精度计算」;显存最省
          • 字节换算:权重显存下限 ≈ 参数量 × 每参数字节。Qwen2.5-0.5B 约 5 亿参数:FP32 约 2 GB、FP16/BF16 约 1 GB、INT8 约 0.5 GB、4-bit 约 0.25 GB——位数每减半,存储成本就减半。但这只是权重的账:实际占用还要加 KV cache、激活值与运行时开销,所以不能只拿参数量乘以字节就宣布「装得下」。
          • INT8/4-bit 不是截断小数:整数格式只能表达离散档位,量化的实质是映射——先按权重分布算出缩放因子(必要时再加零点),把连续值归到最近的整数档,用时再乘回缩放因子。档位怎么放有讲究:4-bit 的 NF4(normal float 4)按正态分布形状放置 16 个档位,比均匀放置更贴合真实权重分布,是 QLoRA 论文(01.03)带入主流的方案。
          • FP16 与 BF16 的差异值得记住:两者都是 2 字节,但 FP16 把位数让给尾数、牺牲指数范围(小数值易下溢),BF16 反过来保住指数范围、牺牲尾数。训练中 BF16 更省心;推理加速上 FP16 的硬件支持更普遍。
          • **FP8(8 位浮点)**是 2023 年后进入部署视野的格式(如 1/4/3 分配),自 Hopper 起有原生加速,精度介于 BF16 与 INT8 之间;生态仍在收敛,本章不展开,知道「位数相同,浮点与整数的取舍不同」即可。

          3. 概念:量化误差如何影响输出

          • 量化对每个权重引入舍入误差:档位越少,误差越大。误差不会停在那一层——它随前向计算逐层传播、累积,最终使 logits 发生微小漂移。若漂移小到不足以改变 token 的排名,输出与原文逐字相同;一旦某个候选 token 的排名被翻转,输出就从那里开始不同,并随自回归逐 token 放大。
          • 所以量化失败很少表现为「模型完全不能用」,而更像:大多数回答照旧,个别长句走样、格式破损、数字出错,或概率性乱码。任务对误差的容忍度差异很大:
          任务类型 敏感度 原因
          闲聊、摘要、风格改写 低 等价表达多,个别 token 偏差可被容忍
          JSON/格式受限输出 中 结构由少量 token 决定,一处走样整段不可用
          数学、代码、日期计算 高 精确 token 序列敏感,排名一翻即错
          • 因此任务越依赖精确数值,低比特的风险越高;语言风格类任务通常最皮实。选 4-bit 之前,先想清楚你的 10 问里有多少属于高敏感列。
          • 推论是评测纪律:比较 FP16 与 4-bit 必须同一批问题、同一生成参数(含 do_sample=False),否则输出差异可能来自采样随机性而非量化误差。显存变小、加载成功、tokens/s 变高都不是成功证据——唯一证据是任务评分没有跌破你预设的阈值。

          4. 概念:量化的两种时机:PTQ 与 QAT

          时机 全称 做法 优点 代价
          PTQ 训练后量化(Post-Training Quantization) 拿已训好的权重直接转低比特,可选少量样本校准缩放因子 无需训练数据与算力,几分钟搞定 精度损失不可控,比特越低越明显
          QAT 训练中量化(Quantization-Aware Training) 在(继续)训练的前向中模拟量化误差,让权重学会容忍 低比特下精度明显更好 需要训练管线、数据与算力
          • 日常部署见到的绝大多数是 PTQ,又有两种落地形态:加载时量化(如本章 bitsandbytes:权重以 4-bit 存入显存,计算前按块反量化回 FP16,零校准数据、即插即用)与校准式量化(如 GPTQ/AWQ:离线用少量代表样本把缩放因子调到最优,再导出可直接高效运行的格式,适合产品化吞吐场景)。
          • QAT 在训练阶段就把「权重要被量化」这件事告诉模型:前向用带误差的量化权重,反向仍走连续梯度,模型在训练中学会自我补偿。效果最好,但要重跑训练,一般留给对精度极其敏感、且要压到 INT4/INT8 的产品。01.03 的 QLoRA 则属于「训练时把基座压成 4-bit」的另一场景,动机与本单元的推理量化不同。
          • 推理部署若发现 4-bit 质量不够,升级路径是:先试 INT8 或校准式 PTQ,还不够再考虑 QAT——不要一上来就用最激进的格式。那为什么不停在 2-bit(每参数 0.25 B,仅 4 个档位)?因为 2-bit 在 PTQ 下质量崩塌几乎必然,通常要靠 QAT 或专门方法才勉强可用——4-bit 是当前「省显存 vs 保质量」的性价比拐点,这也是本章选它做对比的原因。

          5. 概念:硬件兼容:量化不是免费的

          • 格式必须硬件认识才有加速。FP16 张量核心自 NVIDIA Volta(2017)起;BF16 自 Ampere(A100/RTX 30 系)起;INT8 自 Turing(RTX 20 系)起;4-bit 几乎没有 GPU 的原生指令——bitsandbytes 的 4-bit 加载依赖 CUDA,权重低比特存储、计算前反量化回 FP16,省的是显存与访存带宽,不是把计算本身变成 4-bit。
          • 量化省显存是普适的,更快不是。大模型推理常受内存带宽限制,权重变小后逐层搬运更快,tokens/s 可能上升;但小模型上反量化与调度开销可能盖过收益,甚至更慢。CPU 一般没有低比特加速单元,FP16 也未必比 FP32 快;Apple Silicon(MPS)对 FP16 支持较好、低比特支持有限。
          • 先查兼容性再动手:GPU 型号、驱动、CUDA、bitsandbytes 版本都要对得上;无 CUDA 时如实记录「不适用」并继续 FP16/CPU 基线,而不是把报错吞掉假装成功;只用官方渠道安装的依赖,不要使用未知二进制包——这是把「可用」与「看起来可用」分开的第一道防线。典型环境速查:
          环境 常见可用格式 本章做法
          NVIDIA GPU(Volta 起) FP16/BF16/INT8 FP16 基线 + 4-bit 对比
          NVIDIA GPU(Ampere 起) 上述 + 低比特生态更成熟 bitsandbytes 4-bit 首选
          仅 CPU FP32(FP16 未必更快) 记录「不适用」,跑 FP16/CPU 基线
          Apple Silicon FP16 尚可,低比特支持有限 不做 4-bit,在报告里写明原因

          6. 动手:先做兼容性检查,再加载

          在 minigpt-course 根目录(仍激活 .venv)安装并检查:

          pip install bitsandbytes
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'no CUDA')"
          bash

          无 CUDA 时记录「不适用」,继续 FP16/CPU 基线;不要使用未知二进制包。支持环境可创建 finetune/src/load_4bit.py:

          import torch
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
q = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16)
model = AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct",
    quantization_config=q, device_map="auto")
print(model.get_memory_footprint())
          python

          分别运行原模型与 4-bit 脚本,用上一章(01 推理基础)建立的固定 10 问生成,并记录 bytes、TTFT、tokens/s 与全部输出(指标口径见 01 推理基础)。若输出出现乱码或加载失败,保留完整报错与 torch/transformers/bitsandbytes 版本——不要将失败称为「量化成功」;同一份报告里写明失败发生在哪一步,本身就是兼容性结论。

          8. 常见错误与结论

          现象 处理 原因
          安装或导入 bitsandbytes 报错 核对 CUDA 版本与安装来源,回退官方文档安装 依赖与驱动/平台不匹配;未知二进制包风险
          加载成功但输出乱码/重复 保留报错与版本,换 INT8 或 FP16 基线对比 4-bit 量化误差超出该任务容忍度
          显存变小但速度反而变慢 记录并接受:小模型上开销可能盖过收益 量化省带宽,不保证快;计算仍在 FP16
          4-bit 跑不起来 记「不适用」,用 FP16/CPU 或云端/更小模型 硬件或驱动不支持该格式,不是学习失败

          一句话结论:量化是工程取舍——先用兼容性检查圈出「本机能用的格式」,再在同任务、同参数下用显存、速度与任务评分三组数字选型;无法在本机运行 4-bit 是兼容性结论,不是学习失败,云端或更小模型是可审计的替代路径。

          9. 总结

          关键问题 一句话
          权重为什么是浮点 训练需要连续梯度;推理只看 logits 相对排名,故能容忍近似
          各格式多少字节 FP32=4 B、FP16/BF16=2 B、INT8=1 B、4-bit=0.5 B(每参数)
          量化误差如何影响输出 逐层累积使 logits 漂移,排名翻转才改变输出;须固定任务评测
          两种量化时机 PTQ 事后直接转(快、有损);QAT 训练中模拟误差(慢、更准)
          硬件兼容 格式需硬件原生支持才有加速;无 CUDA 如实记录「不适用」
          选型准则 同时满足资源限制与任务阈值,而非只比模型大小

          思考题:为什么「加载成功 + 显存减半」不能作为量化成功的证据?FP16 与 BF16 都是 2 字节,为什么训练界偏爱 BF16?同样的 4-bit 模型,为什么代码生成任务比闲聊更容易出错?

          参考答案

          显存减半只证明权重存进了低比特,不证明输出质量达标——输出可能乱码或错误率上升,必须用同一批问题与生成参数跑任务评分。BF16 保留了 FP32 的指数范围,训练中不易下溢、无需 loss scaling;FP16 尾数多但范围窄。代码与数学任务对精确 token 序列敏感,logits 排名稍被量化误差扰动就可能翻车;闲聊有大量等价表达,容错高。
