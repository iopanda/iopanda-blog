          01.05.04

          微调视觉语言模型

          2026-09-03 · iopanda

          • course
          • multimodal
          • vlm-finetune

          上一章交付了 24+6 对通过六维质检的课程截图问答数据——本章让它们真正改变一个模型。你会在 01.03 学过的 LoRA 之上,把战场从纯文本换成「看图说话」:视觉编码器冻结、LoRA 只注入语言分支的注意力投影、损失只落在回答的文本 token 上。读完你会用 TRL 跑通第一次 VLM 微调小实验,并在同一组「从未见过的图」上对比微调前后,判断模型是学会了看课程截图答领域问题,还是只会复读。

          学习目标:学完本章,你将能够——

          1. 说出 VLM 微调与 01.03 纯文本 SFT 的异同:冻结范围、数据形态、损失位置;
          2. 解释为什么视觉编码器通常冻结、LoRA 注入语言分支就能改变「看图说话」;
          3. 说明图像预处理与损失掩码:像素如何进批次、为什么 loss 只算文本部分;
          4. 用 TRL 在上一章的 24 条图文数据上跑通 LoRA 微调并保存 adapter;
          5. 用留出的 6 条图文对对比微调前后,写出一份不偏袒的结果记录。

          1. 概念:微调 = 教模型「看你的图」

          • 通用 VLM 见过海量自然图片,却没上过你的课:课程 PPT 的版式、术语、圈注、报错截图里的字段,它认得出「这里有东西」,却答不对「这对我意味着什么」。微调就是用第 3 章审核过的(图像、指令、回答)示例,把「看图作答的方式」掰向你的领域。
          • 与纯文本 SFT 同构:仍是「预测下一个 token」,仍只改输出倾向、不改知识库;区别是输入里多了一路视觉 token。上一章说过配错的图会被原样学走——本章让这条链路真的转起来。
          • 与纯文本 LoRA 的差别在「改哪里」。Qwen2.5-VL 这类模型由三件套组成:视觉编码器(把像素变成 patch 特征)、merger 投影器(把视觉特征对齐到文本空间)、语言模型(做推理与生成)。视觉编码器通常冻结——它在通用视觉特征上已经很强,而你的数据只有几十张图,解冻只会让它把这几张图背下来、冲掉通用视觉能力(灾难性遗忘)。LoRA 主要注入语言分支的注意力投影 q_proj、v_proj,让 LLM 学会「依据这些视觉 token 按领域方式作答」。
          对比项 01.03 纯文本 SFT 本章 VLM 微调
          样本形态 问题–回答文本 (图像、指令、回答),user 消息带图像内容块
          损失位置 回答 token 回答的文本 token;图像与 padding 掩码为 -100
          改动范围 语言模型注意力投影 视觉编码器冻结;LoRA 注入语言分支(q/v 投影,可选 merger)
          基座示例 Qwen2.5-0.5B-Instruct Qwen2.5-VL-3B-Instruct
          处理对象 tokenizer processor(分词器 + 图像处理器)
          工具 TRL SFTTrainer TRL SFTTrainer(processing_class=processor)
          • 关于「投影器要不要调」存在两种流派:LLaVA 式两阶段会单独训练投影器对齐视觉与文本空间(第 2 章讲过);TRL 单阶段路线默认冻结一切、只 LoRA 语言侧,靠注意力层的小幅修正完成任务。本章跟官方 cookbook 走单阶段;若你的版式与预训练分布差异很大,可把 merger 加入 target_modules 作为备选实验。

          2. 为什么需要:通用 VLM 不认识你的领域图

          • 领域图是长尾:课程截图、产品主图、内部报表不在通用预训练数据的重心上。模型对它们「能描述、不会用」——问「这张架构图里 merger 的作用」,通用 VLM 会泛泛而谈,因为没人教过它「这类图 + 这类问题 = 这类答案」。
          • 微调改变的是回答方式,不是事实来源:图里没有的信息,微调也变不出来。上一章刻意放进的拒答样本(「截图上没有说明,无法回答」)在这里兑现价值:模型要在你的领域里学会「看不到就说看不到」,否则幻觉照旧。
          • 为什么不换更大的模型:换大模型治标不治本(更大的通用模型同样不懂你的术语),且成本线性上涨;PEFT 让「改行为」的成本降到几十 MB 的 adapter 与一张消费级显卡——这正是 01.03 选 LoRA 的同一理由,只是数据换成了图文对。

          3. 动手前置:核对模型里真实存在的层

          python -c "from transformers import AutoModelForImageTextToText as A; m=A.from_pretrained('Qwen/Qwen2.5-VL-3B-Instruct'); print([n for n,_ in m.named_modules() if n.endswith('q_proj')][:4]); print([n for n,_ in m.named_modules() if n.endswith('qkv')][:2])"
          bash
          • 预期看到两族名字:语言模型每层有 q_proj/k_proj/v_proj/o_proj;视觉编码器里是融合的 qkv。因此 target_modules=["q_proj","v_proj"] 只命中语言分支,视觉塔天然不被触碰——名字对不上就改配置,不要盲抄别的架构。

          4. 训练设置:TRL 替你接好图像管线

          4.1 图像预处理:像素怎么变成批次

          • processor = 分词器 + 图像处理器。图像处理器负责:按模型约束缩放(如 Qwen2.5-VL 的 min/max pixels 动态分辨率,保持宽高比、不暴力拉伸)、ImageNet 式归一化、必要时切 patch/分块——输出 pixel_values 与位置网格,文本则照常 tokenize,图像位置插入 <|vision_start|> 等特殊标记。
          • 上一章 JSONL 里 {"type":"image"} 只是占位声明;训练前必须把真实图像对象填进消息,由 processor 一起处理——「JSONL 里看不到像素」的约定到此为止。

          4.2 损失掩码:为什么只算文本

          • 序列里同时有视觉 token 与文本 token,但监督信号只有文本:图像 token、padding 的位置标签一律置为忽略索引 -100,系统与用户消息按配置(如 completion_only_loss)同样排除。模型永远不会因为「猜对下一个视觉 patch」得到奖励,loss 只衡量「看完图之后,回答续写得像不像标准答案」。

          4.3 训练脚本

          创建 vlmdemo/finetune/train_vlm.py(结构对齐 01.03 的 train_sft.py,只多出图像一环):

          import json
from pathlib import Path
from PIL import Image
from datasets import Dataset
from peft import LoraConfig
from transformers import AutoModelForImageTextToText, AutoProcessor, TrainingArguments
from trl import SFTTrainer

DATA, model_id = Path("vlmdemo/data"), "Qwen/Qwen2.5-VL-3B-Instruct"

def build(name):
    samples = []
    for line in (DATA / f"{name}.jsonl").read_text().splitlines():
        r = json.loads(line)
        img = Image.open(DATA / r["image"]).convert("RGB")     # 03 章:相对路径
        for c in r["messages"]:                                # 占位块换成真图
            if c["role"] == "user":
                c["content"] = [{"type": "image", "image": img}] + \
                               [x for x in c["content"] if x["type"] == "text"]
        samples.append({"messages": r["messages"]})
    return Dataset.from_list(samples)

processor = AutoProcessor.from_pretrained(model_id)
model = AutoModelForImageTextToText.from_pretrained(
    model_id, torch_dtype="bfloat16")          # 显存不足:4-bit 加载走 QLoRA

peft = LoraConfig(r=8, lora_alpha=16, lora_dropout=0.05,
                  target_modules=["q_proj", "v_proj"], task_type="CAUSAL_LM")
args = TrainingArguments(
    output_dir="vlmdemo/runs/vlm-lora-v1", num_train_epochs=3,
    per_device_train_batch_size=1, gradient_accumulation_steps=4,  # 24 条 → 每 epoch 6 步
    learning_rate=2e-4, bf16=True, gradient_checkpointing=True,
    logging_steps=1, eval_strategy="steps", eval_steps=6,
    save_strategy="steps", save_steps=6, report_to="none", seed=42)
trainer = SFTTrainer(model=model, args=args, train_dataset=build("train"),
    eval_dataset=build("valid"), peft_config=peft, processing_class=processor)
trainer.train()
trainer.save_model("vlmdemo/runs/vlm-lora-v1/best-adapter")
          python

          运行 python -m vlmdemo.finetune.train_vlm,确认三件事:train loss 在降;valid loss 同步出现;runs/vlm-lora-v1/ 下有 adapter 与日志。可训练参数应只占极小比例——打印方式与 01.03/05 相同。

          5. 评测:同一考场,微调前后各答一次

          • 考场纪律来自上一章:valid 的 6 张图从未以任何形态进过 train。评测把 base(微调前)与 adapter(微调后)并排放在这 6 张新图上,逐问记录,而不是只挑变好的样例。
          from transformers import AutoModelForImageTextToText, AutoProcessor
from peft import PeftModel

proc = AutoProcessor.from_pretrained(model_id)
base = AutoModelForImageTextToText.from_pretrained(model_id, torch_dtype="bfloat16").to("cuda")
ft   = PeftModel.from_pretrained(base, "vlmdemo/runs/vlm-lora-v1/best-adapter")

def ask(model, row):                                  # row 来自 build("valid")
    msgs = row["messages"][:-1]                       # system + user(含图)
    img  = next(c["image"] for c in msgs[-1]["content"] if c["type"] == "image")
    text = proc.apply_chat_template(msgs, tokenize=False, add_generation_prompt=True)
    inp  = proc(text=[text], images=[img], return_tensors="pt").to("cuda")
    out  = model.generate(**inp, max_new_tokens=128, do_sample=False)  # 冻结采样,可复现
    return proc.decode(out[0][inp["input_ids"].shape[1]:], skip_special_tokens=True)

for i, row in enumerate(build("valid")):
    print(f"[{i}] 微调前:", ask(base, row))
    print(f"[{i}] 微调后:", ask(ft, row))
          python
          • 按「正确 / 错误 / 拒答」三态给每条打分;生成参数冻结(do_sample=False)、题目与图完全一致,才谈得上「差异来自微调」。valid loss 下降与样例变好要同时看:loss 是整体信号,样例回答是你能读懂的局部证据。

          6. 动手活动:跑通并记录第一次 VLM 微调

          动手活动:第一次 VLM 微调

          目标:vlmdemo/reports/vlm-finetune.md,含 loss 曲线与 6 问对比表。

          步骤:先保存 base 在 6 条 valid 图上的回答(基线)→ 跑 train_vlm.py → 用第 5 节脚本生成微调后回答 → 三态打分并逐条写评语(改好了哪句、哪里还在瞎编)。

          完成标准:报告含 train/valid loss 记录、6 问对比表、至少 2 条改善与 1 条失败的定性分析;写明基座 ID、adapter 路径与生成参数,供下一章复用。不能只贴变好的一条。

          7. 常见错误与边界

          现象 处理 原因
          显存不足 换 4-bit QLoRA(BitsAndBytesConfig + 同款 LoRA),或换 SmolVLM 等更小基座 3B 权重 + 激活仍吃显存;adapter 只省可训练参数
          loss 降了,valid 问答却没改善 回查数据:问题是否太散、答案是否只靠文本就能猜出 数据量小(24 条)时,微调学到的是「表面风格」
          loss 异常高或不降 核对 transformers/trl 版本与模型卡要求,检查图像是否成功打开 VLM 支持依赖较新版本;图像加载失败会静默破坏样本
          图上小字仍读错、回答仍幻觉 提高截图分辨率并复查拒答样本占比;微调不消除幻觉 OCR 与分辨率是模型能力边界,不是参数能补的
          换了环境后 adapter 输出异常 报告里固定基座 ID、transformers 版本与 processor adapter 只是 ΔW,必须叠回同一基座(01.03/05)

          一句话结论:视觉编码器冻结 + 语言分支 LoRA + loss 只算文本,就能用几十条图文对把通用 VLM 的输出倾向掰向你的领域;但「看图答对」的真伪,永远要由没见过的图说了算。

          8. 总结

          关键问题 一句话
          VLM 微调改哪里 视觉编码器冻结;LoRA 注入语言分支注意力投影,可选 merger
          与纯文本 SFT 的异同 同构的 next-token 学习;差别在输入含视觉 token、损失只算文本
          图像预处理谁负责 processor:缩放/归一化/特殊标记 + 文本 tokenize,一步完成
          loss 为什么只算文本 视觉 token 与 padding 置 -100;模型学的是「看完图怎么答」
          评测纪律 留出集必须「不同题且不同图」;base 与微调后并排三态打分
          边界 微调改输出倾向;幻觉、OCR 与分辨率限制依然存在

          思考题:为什么 VLM 微调通常冻结视觉编码器,而纯文本微调不存在「冻结哪一半」的问题?如果 valid 里混入一张 train 见过的图,「微调后答对了」还能证明什么?

          参考答案

          视觉编码器提供通用视觉特征,几十张领域图不足以、也不应该改写它——解冻会让它过拟合这几张图并冲掉通用能力(灾难性遗忘);纯文本模型没有「视觉一半」,LoRA 注入语言层即可。valid 混入见过的图属于泄漏:模型可能直接背出训练时的回答,只能证明它记住了图,不能证明它对陌生图泛化——考过的题不算能力,这与 01.03 与第 3 章的考场纪律一致。
