          01.05.03

          图文数据准备

          2026-09-03 · iopanda

          • course
          • multimodal
          • image-text-data

          上一章讲清了「图像怎么变成 LLM 能读的 token」;本章回答「拿什么数据教它」。纯文本数据集一把 JSONL 就能装下,图文数据却要在图像文件、配文质量、许可、泄漏四条线上同时把关——caption 质量决定模型上限,配错、模糊、PII 与版权风险则决定数据集能否合法存在。读完你会交付 20~30 对可审计的图文数据、一份 schema 与许可记录、一个自动检查脚本。

          学习目标:学完本章,你将能够——

          1. 说清 VLM 微调样本是(图像、指令、回答)三元组,并解释 caption 质量为何决定模型能力上限;
          2. 写出与 01.03 一脉相承、图像以特殊 content 块进入消息的 JSONL schema;
          3. 用「图文匹配、分辨率、重复、PII、许可、平衡」六维清单给图文对做质检;
          4. 解释数据泄漏:训练图与评测图重叠为何导致「记忆而非泛化」;
          5. 用检查脚本输出数据集的 schema、数量、图像信息与许可记录,交付数据卡。

          1. 概念:VLM 微调样本是(图像、指令、回答)三元组

          • 沿用上一章的模型结构:图像 → 视觉编码器 → 视觉 token,与文本 token 一起送入 LLM。模型要学的不再是「读完文本作答」,而是「看完这张图、听懂这句话、给出这个回答」——因此一条训练样本天然由三部分组成:(图像, 指令, 回答)。
          • 与 01.03 监督微调共用同一条铁律:损失只算在 assistant 回答上,system 与 user 只作上下文被读取。区别仅在 user 消息里多了一个图像内容块,它被视觉编码器变成视觉 token 后参与整段注意力——下一章会把这整条链路拿去微调,图像侧的配错与低质会像文本错误一样被原样学走。
          • 「caption 质量决定模型上限」:模型看到什么、被要求回答什么、标准答案是什么,全由数据定义。若 caption 把图里的猫写成狗,模型学到的就是「这类图要答狗」;若问题永远只问「这是什么颜色」,模型就不会长出数数能力。数据是模型的天花板,训练只是逼近它。
          数据形态 图像角色 典型样本 用在哪
          图像-文本对 整图配一句描述 (图片,「一只橘猫趴在键盘上」) 对齐阶段,训投影器
          图文指令(本章重点) 图中的内容可被提问 (图片,「图中有几只猫?」,「两只」) 微调:学看图答领域问题
          多轮图文对话 图像贯穿多轮上下文 (图片,追问,再追问,……) 贴近产品形态,数据成本最高
          • LLaVA 的开创性正在第三列:用 GPT-4 围绕 COCO 图像生成约 15 万条「对话、详细描述、复杂推理」三类指令,把「看图说话」从输出描述升级为视觉指令跟随。本单元复刻的正是这条路线的小型版,LLaVA-Instruct-150K 就是它的成品数据。

          2. 数据 schema:图像路径 + 消息数组的 JSONL

          • schema 在 01.03 的 messages 之上只增加两样东西:顶层 image 字段(图像路径或 URL)与 user 消息里的图像 content 块。图像本身不进 JSON,进文件系统;JSON 只存引用——每行因此保持可读、可 diff、可审计。
          {"id":"t-001","image":"images/slide07.png","messages":[{"role":"system","content":"你是课程答疑助手,只能依据截图内容回答;图里没有的信息要明确说看不到。"},{"role":"user","content":[{"type":"image"},{"type":"text","text":"这张架构图里,哪一部分负责把图像变成向量?"}]},{"role":"assistant","content":"图中最左侧的视觉编码器负责把图像编码成向量,再经投影层送入语言模型。"}]}
{"id":"t-002","image":"images/slide07.png","messages":[{"role":"system","content":"你是课程答疑助手,只能依据截图内容回答;图里没有的信息要明确说看不到。"},{"role":"user","content":[{"type":"image"},{"type":"text","text":"训练完成后,投影层还能继续调整吗?"}]},{"role":"assistant","content":"截图上没有说明训练后的调整方式;我只能看到架构图,无法回答这个问题。"}]}
          json
          • 字段约定:image 一律用相对路径(相对数据目录),个人绝对路径会让数据换机器即坏、上传 Hub 即泄漏隐私;用 URL 也可以,但必须记录抓取日期并把图像本地留档,否则许可核验与复现都无从谈起。
          • 训练时,processor 会把 type:image 块替换成特殊标记(如 <image>),再调用视觉编码器把真实像素变成视觉 token——JSONL 里永远看不到像素,它只声明「这里有张图」,与 01.03 里「schema 干净,脏数据在转换时静默变脏信号」同理。
          • 01.03 的 schema 铁律原样继承:最后一条消息必须是 assistant;system 规则全文一致,不写互相矛盾的要求;每行一个完整 JSON 对象、对象内部不换行。

          3. 为什么图文数据比纯文本更难

          纯文本数据的错误大多「看得见」:拼写、事实、格式。图文数据的错误藏在图像与文字的关系里,而且常常要等训练完、模型说出奇怪答案时才发现:

          问题 表现 代价
          配错(misalignment) 文字描述 A 图,配图却是 B 图 模型学到「图与文可以无关」
          模糊 / 低分辨率 小图、强压缩、文字糊掉 OCR 类能力永远学不会
          近似重复 同一事件连拍、同图多处引用 训练集虚胖、评测失真
          PII 人脸、车牌、工牌、聊天记录 隐私事故,训练后难以清除
          许可不明 来源未知或商用受限的图 合法风险,数据集可能被下架
          图文不匹配任务 拿通用 caption 当指令数据 学不到「按问题作答」
          • 许可不是小概率事件,而是真实事故。Hugging Face 上曾广受欢迎的 lambdalabs/pokemon-blip-captions(约 830 张宝可梦图 + BLIP 自动 caption),就因宝可梦公司国际部发出 DMCA 通知被整体下架;教程转而推荐的 naruto 同款数据集,数据集卡上干脆没有 license 元数据(图像抓自同人维基)。两案并读的教训与 01.02 数据许可纪律完全一致:可复现 ≠ 可商用,来源与权利必须逐条记录;「数据集卡上缺失 license 字段」本身就是红旗。
          • 自动 caption 是另一个隐性坑:BLIP 这类模型生成的描述未经人工核验,带着机器的盲区(数错数量、忽略细节),许可再干净也补不了质量问题——机器写的只能当草稿,不能当标准答案。
          • LLaVA-Instruct-150K 是「叠加许可」的典型:数据集本体 CC-BY-4.0,同时要求遵守 OpenAI 使用条款(内容由 GPT-4 生成)。读数据集卡不能只看 license 一行,还要读卡正文的附加条款。

          4. 质量检查:六维清单(呼应 01.02 数据治理)

          维度 怎么查 通过标准
          图文匹配 人工逐张看;量大时用 CLIP 算图文相似度,先查最低分 每对图文主题一致,无张冠李戴
          分辨率 脚本输出每图宽高 最小边 ≥ 384 px,图上文字清晰可辨
          重复 感知哈希近似去重;同图多次引用合并为一条 训练集内无近似重复图
          PII 人工逐张确认是否含人脸、证件、工牌 全部剔除,或打码后记录处理方式
          许可 每图一行来源记录(文件、作者、许可、URL) 逐条可回指,商用授权明确
          平衡 按图像内容类别统计数量 无单一类别占比超过 60%
          • 图里若有文字,先问一句「模型需要读出它吗」:需要,就必须保证清晰、未裁切、不被水印遮挡——模糊截图是 OCR 类任务的头号死因,而本单元收官项目的核心恰恰是读懂课程截图。

          5. 泄漏:训练图与评测图重叠 = 记忆而非泛化

          • VLM 对图像的记忆力极强:同一张图只要进过训练,评测时模型很可能直接背出见过的问答,而不是真的学会「看新图作答」。这与 01.03 的 valid 纪律同源,但图文泄漏多一层:文本 valid 只要求「不同题」,图文 valid 还要求「不同图」。
          • 泄漏自检三问:1) valid 的每张图是否从未以任何形态出现在 train(原图、裁剪、二次截图都算)?2) 同一事件的连拍图是否被拆进两个集合?3) 数据卡是否记录了 train/valid 图集无交集?
          • 泄漏的恶果:valid 分数虚高,一旦上线面对真实新图立刻现形。「考过的题」不算能力,「没见过的图答对了」才算——这也是下一章微调前后对比必须遵守的考场纪律。

          6. 动手活动:自建图文对数据

          动手活动 1:制作 24+6 图文对

          目标:产出 vlmdemo/data/ 下可训练、可审计的图文数据(train 24 条 + valid 6 条)。

          步骤:场景沿用单元主线「课程截图问答」。图像来源两种:自己截的课程 PPT/讲义图(自有无版权障碍),或 Wikimedia Commons 等平台标注 CC0 / CC-BY 的图(CC-BY 需在 licenses.csv 里记录署名)。先定三条规则,再写样本:答案只能依据图中可见信息;图上没有的信息明确拒答;图像不含人脸等 PII。

          vlmdemo/data/
├── images/           # t-001.png、t-002.png、……
├── train.jsonl       # 24 条
├── valid.jsonl       # 6 条
└── licenses.csv      # 每张图的来源与许可
          text
          • 写 24 条 train + 6 条 valid;valid 必须用 train 从未出现过的图,每张图配一个问题,难度先窄后宽:描述内容 → 数数量 → 关系判断 → 「图里没有的」拒答边界;
          • 每条样本按第 4 章六维清单人工勾选;刻意放 3~5 条边界样本:问题涉及图上没有的信息,标准答案写拒答——模型学会「看不到就说看不到」,靠的正是这类样本;
          • licenses.csv 一行一图,字段 file,source,author,license,url,note;自己的截图 source 填 self-captured、license 填 own——没有来源记录的图,不允许进入数据集。

          7. 动手活动:检查脚本与数据卡

          动手活动 2:自动化检查并交付数据卡

          目标:用脚本证明数据「schema 正确、图像达标、无泄漏」,并交付 data-card.md。

          步骤:创建 vlmdemo/src/check_data.py,让它自动做五件事:逐行解析 JSON 并校验顶层字段;校验最后一条消息是 assistant;检查每张图存在且最小边 ≥ 384 px;检查 train/valid 图集无交集(泄漏);汇总 licenses.csv 的许可分布。

          import json
from pathlib import Path
from PIL import Image

BASE = Path("vlmdemo/data")
for split in ["train", "valid"]:
    rows = [json.loads(x) for x in (BASE / f"{split}.jsonl").read_text().splitlines() if x]
    for r in rows:
        assert {"id", "image", "messages"} <= set(r), f"{split} 缺字段: {r.get('id')}"
        assert r["messages"][-1]["role"] == "assistant", f"{split} 末条非 assistant: {r.get('id')}"
        im = Image.open(BASE / r["image"])
        assert min(im.size) >= 384, f"图太小: {r['image']} {im.size}"
    print(split, len(rows), "schema 与图像检查通过")

tr = {json.loads(x)["image"] for x in (BASE / "train.jsonl").read_text().splitlines() if x}
va = {json.loads(x)["image"] for x in (BASE / "valid.jsonl").read_text().splitlines() if x}
assert not (tr & va), "泄漏:train/valid 图集存在重叠"
print("泄漏检查通过:train 与 valid 图集无交集")
          python

          运行 python vlmdemo/src/check_data.py,报错要逐条修:图不达标就换图或重新截图,不要放宽阈值——阈值是你对图像质量的承诺。最后交付数据卡 vlmdemo/data/data-card.md,字段照抄 01.03 的实践:来源、作者、数量(train/valid)、许可记录、拒答样本数、人工审核人、六维检查结果。

          完成标准:脚本无报错;valid 与 train 图集零重叠;数据卡能定位每张图的来源与许可。

          8. 总结

          关键判断 一句话
          数据形态 VLM 微调 = (图像、指令、回答) 三元组;caption 质量决定模型上限
          schema messages 铁律不变;顶层 image 引用 + user 内 type:image 内容块
          为什么难 配错、模糊、重复、PII、许可、平衡,六类错误都藏在图文关系里
          许可 读数据集卡不能只看 license 一行;DMCA 下架与缺失许可字段都是真实红旗
          泄漏 valid 必须「不同题且不同图」;考过的题不算能力
          验证 检查脚本输出 schema、数量、图像信息与许可分布;数据卡留档

          思考题:为什么「同一张图换个问题」放进 valid 会让验证失去意义?为什么说「数据集卡上缺失 license 字段」本身就是红旗?

          参考答案

          VLM 对图像的记忆极强,该图一旦在训练中出现过,模型就可能直接背出见过的问答,valid 分数只能证明它记住了图,不能证明它对陌生图泛化——泄漏把验证从「没见过的考场」退化成「背过的题」。而数据集卡是下游使用者判断能否商用的唯一入口,缺失许可字段意味着权利链条断裂,任何商用或再分发都会把自己暴露在法律风险中,正规项目会直接拒绝采用这样的数据。
