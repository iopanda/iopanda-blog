          01.01.07

          语言建模

          2026-09-02 · iopanda

          • course
          • language-modeling
          • foundations

          上一章认识了 Transformer 的骨架——注意力让每个 token 都能参考全部上下文。但骨架本身不会说话:让模型「开口」的,正是本章的语言建模(language modeling)目标。你会看到一个反直觉的事实:「预测下一个词」这一件事,同时训练出了语法、知识、翻译、写代码与基础推理。理解了它,你就拿到了解读几乎所有大模型产品的钥匙。

          学习目标:学完本章,你将能够——

          1. 用一句话定义语言建模,并写出它的概率分解公式;
          2. 解释为什么「预测下一个 token」是一个标签免费的自监督任务;
          3. 说明语言建模「给文本打分」与「生成文本」的双重用途;
          4. 对比 n-gram、早期神经语言模型与现代大语言模型的核心差异;
          5. 解释困惑度、temperature、top-k / top-p 的含义与用途。

          1. 概念:语言建模是什么

          • 语言建模(Language Modeling) 是对一串 token(词或子词)出现的概率进行建模。给定词表 $V$ 和序列 $w_1 w_2 \dots w_T$,模型要能算出: $$P(w_1 w_2 \dots w_T) = \prod_{t=1}^{T} P(w_t \mid w_1 \dots w_{t-1})$$ 这个等式叫链式法则:整句话的概率 = 每个词在「前面所有词之后」的条件概率的乘积。
          • 所以语言建模的日常形态只有一句话:给定前文,预测下一个 token 的概率分布。今天的 GPT、Llama、Claude 在预训练阶段做的全部事情,就是反复做这件事。
          • 为什么这样定义:自然语言有内在不确定性——「我今天吃了___」后面可以接苹果、午饭、火锅、闭门羹……不存在唯一正确答案。因此模型输出的不是一个词,而是词表上每个 token 的概率分布。

          1.1 一个类比:输入法联想与接龙

          • 手机输入法把 ni hao 重排成「你好」而不是「你嚎」,靠的正是语言模型:在拼音相同的大量候选里,选出「按中文习惯概率最高」的那个词序列。聊天机器人的「续写」与输入法的「联想」是同一个任务,只是规模差了几万倍。
          • 语言模型同时给了你两样东西:一是概率(判断哪句话更自然、更像人话),二是分布(从这个分布里采样,就能源源不断地产出新文本)。

          2. 为什么需要它:从「看懂」到「会说」

          • 在语言建模成为主流之前,机器只能做「看懂」类任务:分个类、打个标签、判断个正负面。但**「生成一句从来没人写过的话」**是开放问题,没有标准答案,监督学习那套「给 (x, y) 样本」的框架接不住——谁来给无穷多种回答逐一标答案?
          • 语言建模的巧妙之处,是把「生成」这个开放问题收编成一个处处有答案的预测问题:互联网上每一段文本,天然就是「前文 → 下一个词」的免费训练样本。这就是自监督:标签从数据自己身上长出来,不需要人工标注。
          • 历史上它最初也不是为了「聊天」:1980 年代 IBM 的 Jelinek 团队在语音识别中发现,声学模型给出多个候选读音后,需要一个「哪句话更像真英语」的先验概率 $P(\text{文本})$ 来挑出正确句子,于是引入了统计语言模型(n-gram)与困惑度。
          • 为什么偏偏是「预测下一个词」这么简单的任务? 三个原因:
          原因 说明
          标签免费 全网文本都是自监督语料,规模可以无限大
          任务够难 要预测对,模型必须学会语法、事实、逻辑、风格、世界知识
          目标统一 「给文本打分」= 理解,「从分布采样」= 生成,一鱼两吃
          • 一句话:语言建模让「理解」与「生成」第一次共用同一个训练目标,这也是它能一路 scale 成今天大模型的原因。

          3. 它有什么作用:一切生成式 AI 的地基

          • 文本生成:聊天、续写、摘要、翻译、写代码、Agent 的思考链——无论产品外壳多复杂,底层循环都是同一个:根据已有 token 预测下一个,采样,拼回去,再来一次。
          • 给候选打分:语音识别(把 wuhan 候选句按语言概率重排)、机器翻译的候选重排序、拼写纠错,都依赖「$P(\text{句子})$ 越大越通顺」这一信号。
          • 预训练表示:自回归(GPT 式)与双向(BERT 式)语言模型的隐藏层,都沉淀了通用的语言表示,可以微调后做分类、检索、抽取等下游任务;向量检索、RAG 用的文本嵌入也常由语言模型产生。
          • 工程价值:一个预训练好的语言模型 = 开箱即用的「语言先验」,产品团队无需自己训练,用提示词、检索、微调即可适配具体业务(呼应 01 章「基础模型」的分层图)。规模与数据量的增长带来能力跃迁(scaling law),是 09、10 章的主题。

          4. 详细介绍

          4.1 三代模型:n-gram → 神经语言模型 → 大语言模型

          • 第一代 · n-gram(1980s):用马尔可夫假设偷懒——下一个词只依赖最近 n−1 个词,然后直接查语料里的频数表: $$P(w_t \mid w_{t-n+1} \dots w_{t-1}) \approx \frac{\text{count}(w_{t-n+1} \dots w_t)}{\text{count}(w_{t-n+1} \dots w_{t-1})}$$ 问题随之而来:组合爆炸与数据稀疏——语料里 5-gram 大多一次都没出现过,频率为 0 就得「判死刑」,于是需要加一平滑、回退等技巧;且 n 一大参数量指数膨胀,上下文却依然很短。
          • 第二代 · 神经语言模型(2003 起):Bengio 等人的开创性工作**「A Neural Probabilistic Language Model」**用嵌入(embedding)+ 神经网络取代频数表:相似的上下文被映射到相近的向量,「没见过的词组」也能靠相似性给出合理概率,一举缓解稀疏问题,还顺带学出了有语义的词向量。
          • 第三代 · 大语言模型(2018 起):序列建模交给 Transformer(上一章),GPT 证明只要模型够大、数据够多,「预测下一个词」就能涌现出翻译、问答、写代码等能力;此后模型参数从亿级涨到万亿级,预训练语料从几十 GB 涨到十几万亿 token。
          代际 上下文建模 优点 致命局限
          n-gram 只看最近 n−1 个词 简单、快、可解释 稀疏、上下文极短
          神经 LM(Bengio/RNN/LSTM) 分布式表示,上下文变长 泛化好、词有语义 串行难并行、长程遗忘
          Transformer LLM 注意力看全上下文 并行、长程、可规模化 算力与数据成本巨大

          4.2 训练与评估:损失、困惑度、采样

          • 训练目标(交叉熵损失):对序列每个位置,模型输出词表上的一个概率分布,真实的下一个 token 作为「标准答案」。交叉熵 = 负对数似然,模型给正确 token 的概率越高,loss 越低。反向传播逐层更新参数——和 02、03 章学的框架完全一致,只是数据换成了「前文 → 下一个词」对。
          • Teacher forcing(强制教学):训练时把真实历史喂给模型预测下一步,而不是喂它自己上一步的生成结果——否则一步错、步步错,误差在序列上滚雪球,训练根本稳不住。
          • 困惑度(Perplexity):$\text{PPL} = \exp(\text{平均交叉熵})$,直观理解是模型平均每次要在几个候选里「猜」。PPL 越低越好:一个 PPL 为 20 的模型,平均相当于在 20 个等概率词里做选择。注意:困惑度低 ≠ 下游任务表现好,它只衡量「像不像训练语料的话」,评测最终还要看具体任务指标。
          • 生成时的采样参数:temperature 控制分布软硬(t 大 → 更随机发散,t 小 → 更确定保守);top-k 只从概率最高的 k 个词里选;top-p(nucleus) 动态截取累计概率到 p 的最小候选集。贪心解码(总选概率最高)最容易复读,采样过猛则容易跑题,实际产品要在这两头之间调平衡。

          4.3 单向 vs 双向:GPT 与 BERT

          因果语言建模(GPT) 掩码语言建模(BERT)
          任务 只看左侧,预测下一个词 遮住中间词,看两侧猜它
          方向性 单向(自回归) 双向
          擅长 生成(必须不偷看未来) 理解(分类、检索、抽取)
          代表 GPT 系列、Llama、Claude BERT、RoBERTa
          • 生成任务必须因果:如果模型生成第 5 个词时能偷看第 6 个词,循环就不成立了。这也是为什么主流对话大模型几乎都是 decoder-only 的自回归架构;BERT 式的双向预训练则更多用作「表示引擎」。
          • 两者广义上都算「语言建模」的变体——共同思想都是:用文本自带的上下文关系做预测,把预测压力逼成语言能力。

          4.4 为什么「只会预测」却什么都会 & 它的边界

          • 预测下一个词看似肤浅,实则极难:要预测对「他推开门,___」,模型得知道门会吱呀响、人会说「我回来了」、甚至情节接下来要发生什么——语法、事实、推理、风格全被压缩进了权重。Karpathy 在《Intro to Large Language Models》里点破:训练压缩了互联网文本,而压缩即智能——能力不是额外加的,是「把世界规律压缩进参数」的副产品。
          • 但请记住它的结构性边界:训练目标是「像人话」,不是「为真」。模型对「事实正确」没有内置校验,所以会一本正经地编造(幻觉)、在长文本里复读、对没见过的问题硬答。工程上要用 RAG 补事实、工具调用补实时数据、评测与人工兜底——这些是 01 后续系列的主题。

          5. 总结

          5.1 本章一览

          概念 一句话
          语言建模 用链式法则把句子概率拆成「逐词条件概率」并建模
          训练目标 预测下一个 token(自监督,标签来自文本本身)
          双重作用 给文本打分(理解)+ 从分布采样(生成)
          三代演进 n-gram(查频数)→ 神经 LM(学表示)→ Transformer LLM(规模化)
          关键指标/参数 困惑度(越低越好)、temperature、top-k、top-p
          边界 目标是「像人话」而非「为真」,幻觉需系统手段兜底

          5.2 思考题

          1. 为什么语言建模不需要人工标注数据?「标签」到底藏在哪?
          2. 为什么生成式模型必须是单向(因果)的,而 BERT 可以看两侧?
          3. 把 temperature 调到 0 与调到很高,生成结果分别会怎样?产品上各自适用什么场景?
          4. 困惑度从 100 降到 20,意味着模型的什么能力变强了?它能直接代表「回答更准确」吗?

          参考答案

          1. 互联网文本本身就是「前文 → 下一个词」的天然样本:把任意文本切成前缀和下一个 token,就得到一条训练数据,不需要人标注——这就是自监督。
          2. 生成是逐词展开的,第 t 个词若能看到第 t+1 个词(未来),生成循环就失去意义;BERT 只做「猜被遮住的词」,不需要按顺序产出文本,所以可以充分利用两侧上下文,更适合理解任务。
          3. temperature→0 近似贪心,输出确定、保守、易复读,适合代码、结构化输出;调高则发散、有创造力,但易跑题甚至胡言乱语;产品常在「事实性任务用低温、创意任务用高温」之间权衡,并配合 top-p。
          4. PPL 从 100 到 20 表示模型对「下一个词」的平均候选数从 100 降到 20,说明它更懂语言规律;但它只衡量「像不像训练语料的话」,不直接代表事实准确或任务表现,下游能力要单独评测。
