          01.01.08

          模型架构

          2026-09-02 · iopanda

          • course
          • model-architectures
          • foundations

          06、07 两章确立了主心骨:Transformer 是骨架、「预测下一个词」是目标。但现实世界不只有「写文本」这一件事——还有看图、听声、生成图像,以及「参数越少越便宜」的工程约束。本章把镜头拉远,回答:模型到底可以长成哪些样子,每种样子擅长什么、为什么。你会得到一张架构全景图(CNN、RNN/LSTM、Transformer、Diffusion、MoE),以及一套按任务选架构的决策框架。

          学习目标:学完本章,你将能够——

          1. 画出主流架构全景:CNN、RNN/LSTM、Transformer、Diffusion、MoE 各自解决什么问题、活跃在哪些场景;
          2. 解释 Encoder-only、Decoder-only、Encoder-Decoder 三类架构的结构差异、代表模型与擅长任务;
          3. 说清 Dense 与 MoE 的区别:路由器、总参数 vs 激活参数、负载均衡;
          4. 描述多模态模型「视觉编码器 + 对齐」的融合思路,并对比两条实现路线;
          5. 面对一个具体任务,用选型框架选出合适的架构,并读懂模型卡上的关键字段。

          1. 概念:模型架构是什么

          • 模型架构(architecture)= 数据在模型内部流动的「管线设计」:层怎么堆叠、token 之间通过什么机制交换信息(卷积窗口、循环状态还是注意力)、前馈部分长什么样、每个输入实际激活多少参数。
          • 它是「模型」三维度里最先被定下的一个:上一章讲过,训练目标是学什么(预测下一个词),架构则是用什么形状的机器去学。同一个目标,套在不同骨架上,能力和代价完全不同。
          • 架构 ≈ 工程师对任务的先验判断——「我认为这类数据里,哪些结构关系是重要的」。比如图像里「相邻像素才相关」,文本里「任意两词都可能相关」。先验对了,学习事半功倍;先验错了,模型再大也学不动。

          1.1 一张图记住全景

          模型架构家族(按「信息怎么流」记忆)
├─ CNN ───────────── 像素网格:卷积核滑窗(局部相关)─── 图像理解
├─ RNN / LSTM ────── 时间序列:隐藏状态串行传递 ─────── 早期序列任务、时序预测
├─ Transformer ───── 任意序列:注意力一步直达(全对全)── 文本/多模态主骨架
│   ├─ Encoder-only ────── 双向读(BERT)→ 理解/检索
│   ├─ Decoder-only ────── 因果写(GPT)→ 生成,现代 LLM 主流
│   ├─ Encoder-Decoder ─── 先读后写(T5)→ 翻译/摘要
│   ├─ + MoE 稀疏化 ────── 专家路由(Mixtral/DeepSeek-V3)→ 大容量低成本
│   └─ + 视觉/音频编码器 ── 多模态融合(LLaVA/GPT-4o)→ 看图说话
└─ Diffusion ──────── 噪声→数据:逐步去噪 ──────────── 图像/视频/音频生成
          text
          • 注意结构:CNN、RNN 是 Transformer 之外的「经典家族」;MoE 与多模态不是新家族,而是叠在 Transformer 上的改造——这也解释了为什么今天几乎所有大模型,你都能在它的模型卡里找到「Transformer」字样。

          2. 为什么需要架构:数据不会自己告诉你它长什么样

          • 不同数据形态有天然的结构,把结构写进模型(而不是让模型从头猜),是深度学习几十年的核心经验:
          数据形态 内在结构 写进架构后的效果
          图像 局部性:相邻像素构成纹理/边缘 CNN 滑窗:参数少、天然平移不变
          语音/时间序列 时序性:当前值依赖过去 RNN 状态传递(曾);如今多被 Transformer 取代
          文本 长程依赖:句首决定句尾 注意力:任意两位置一步可达(06 章)
          连续高维生成(图像) 目标分布复杂、无「标准答案序列」 扩散:把生成拆成一步步去噪
          超大规模 LLM 容量要大、单次推理要省 MoE:专家分工、稀疏激活
          • 没有万能架构(No Free Lunch):图像用「全对全注意力」也能做(如 ViT),但要更多数据才能学会局部性;文本用「滑窗卷积」也能做,但长程依赖要堆很深。架构的价值是把数据里确定的结构免费送进模型,省下学习成本。
          • 三个现实约束驱动架构演进:① 并行与算力(GPU 时代,串行 RNN 出局);② 容量与成本(参数越多越聪明,但显存和推理费也越高);③ 生态与工具链(主流架构才有成熟的训练、量化、部署工具)。

          3. 它有什么作用:架构决定能力、成本与部署方式

          • 对能力:架构决定模型能捕获哪种关系(长程/局部/时序),也就划定了能力上限;同等数据下,架构与任务越匹配,效果越好。
          • 对成本:架构区分出两笔账——总参数决定显存与存储(权重要全部驻留),激活参数决定每个 token 的算力与延迟。MoE 的精妙就在把这两笔账分开(4.3 节)。
          • 对部署:架构决定推理时的关键资源:自回归要维护 KV cache(09 章会讲)、扩散要跑多步采样、多模态要处理高分辨率 patch——选型直接写进你的算力预算单。
          • 对生态:架构即「方言」。同一种架构(如 decoder-only)才有统一的开源权重、量化工具、推理框架支持;冷门架构往往要自己踩坑。

          4. 详细介绍

          4.1 全景:五大架构家族

          家族 核心机制 主要解决什么问题 典型代表 典型场景
          CNN 卷积核滑窗,局部连接+权值共享 图像的局部性与平移不变 AlexNet、ResNet 图像分类、检测、OCR
          RNN/LSTM 隐藏状态逐 token 串行传递 变长序列的时序依赖(曾) LSTM、GRU 早期翻译/语音;如今时序预测
          Transformer 注意力让任意位置直接交互 长程依赖 + 并行训练(06 章) GPT、BERT、T5 文本与多模态的主骨架
          Diffusion 前向加噪、反向学去噪 稳定生成高维连续数据 DDPM、Stable Diffusion 文生图、图生图、视频、音频
          MoE FFN 复制为多个专家,路由器挑选 容量大但单个 token 算得少 Mixtral、DeepSeek-V3 超大 LLM 的训练与低成本推理
          • CNN(卷积神经网络):用可学习的卷积核在像素网格上滑动,同一套权重扫过全图(权值共享),天然假设「相邻像素相关、目标平移位置不影响类别」。AlexNet(2012)凭它引爆深度学习;ResNet(2015)用残差连接让上百层可训练。今天视觉主干仍是 CNN 与 ViT 并存——CNN 高效省算力,适合移动端;ViT(2020)证明纯注意力也能做视觉,但需要更多数据。
          • RNN/LSTM(循环网络):把序列压缩进一个「隐藏状态」,逐词往后传。LSTM(1997)用门控缓解梯度消失,曾是翻译、语音的主力(05 章讲过它引出注意力)。致命伤是串行:第 t 步必须等前 t−1 步,喂不饱 GPU。如今文本任务几乎全被 Transformer 取代,RNN 退守金融时序、流式信号等小场景,以及近年 RWKV、Mamba 这类「线性注意力/状态空间」改良。
          • Transformer:06 章已拆解,此处只定位:它是当前唯一主线——注意力解决了长程依赖与并行训练两大难题,且规模法则清晰(参数、数据、算力按幂律换能力)。
          • Diffusion(扩散模型):概念上是「两步走」——前向过程把图像逐步加高斯噪声直到变成纯噪声(固定规则,不需学习);反向过程训练一个神经网络学会「从带噪图像一步步去噪还原」。为什么需要它?直接建模图像分布极其困难,GAN 对抗训练又出了名地不稳定;扩散把「一次生成」拆成上千个简单的去噪子任务,每步目标明确、训练稳定。它有什么作用?文生图/图生图/视频/音频生成的事实标准(Stable Diffusion、Midjourney 均属此类)。关键参数:时间步数 T(如 1000 步的噪声调度)、采样步数(DDIM 等加速采样器可用 20~50 步出图)。技术细节:Stable Diffusion(LDM,2022)把去噪搬进 VAE 的潜空间大幅降算力,以 U-Net 为骨干、用交叉注意力注入文本条件。注意一个对照:图像是连续高维数据,扩散合适;语言是离散 token,自回归解码更自然——这正是 LLM 清一色 decoder-only 的深层原因。

          4.2 按信息流分:Encoder-only / Decoder-only / Encoder-Decoder

          • 06 章讲过:Transformer 原版由编码器(Encoder,双向读输入)与解码器(Decoder,因果地逐词生成)组成。取哪一半、怎么拼,就是三类架构,本质区别只有一个:注意力能看见谁。
          Encoder-only Decoder-only Encoder-Decoder
          注意力方向 双向(能看两侧) 单向(因果,只看左侧) 输入双向 + 输出单向
          一句话 「读」 「写」 「先读后写」
          预训练目标 掩码语言建模(BERT,见 07 章) 因果语言建模(GPT) 去噪自编码 / text-to-text
          代表模型 BERT、RoBERTa、DeBERTa GPT、Llama、Mistral、Qwen、DeepSeek 原版 Transformer、T5、BART
          擅长任务 分类、语义检索/嵌入、抽取 对话、写作、代码、Agent 翻译、摘要、语音识别等转换任务
          • 为什么 decoder-only 成了今天的主流? ① 生成是产品的主形态(聊天、写作、代码),而生成必须因果,decoder-only 是最直接的实现;② 同一个权重既能生成也能做理解(把分类题写成「请回答……」),接口统一;③ 推理服务简单:只需维护一份 KV cache,不区分「编码阶段/解码阶段」。Encoder-only 则仍是嵌入/检索赛道的常客(向量数据库里的 embedding 模型多出自它);Encoder-Decoder 在「输入很长且结构转化强」的任务(翻译、摘要)上仍有结构性优势——这也是为什么 T5 至今未被完全淘汰。
          • 选型直觉:要「理解出结果」→ encoder-only;要「生成内容」→ decoder-only;输入输出都是长文本且需转换 → encoder-decoder。今天的 API 生态里,decoder-only 大模型已顺带覆盖后两类,但本地部署小模型时这个区分仍很实用。

          4.3 Dense vs MoE:路由器、激活参数与负载均衡

          • 概念:传统 Transformer 的每一层 FFN 是一整块,每个 token 都经过它的全部参数,这叫稠密(Dense)模型。MoE(Mixture of Experts,混合专家)把每层 FFN 复制成 N 个结构相同的「专家」,前面加一个路由器(gating network):路由器看当前 token 的表示,给它打分,只挑分数最高的 top-k 个专家真正计算,输出按路由权重加权求和。
          • 为什么需要它:大模型的能力大致随总参数(知识容量)增长,但推理成本随每次实际计算的参数(激活参数)增长。Dense 模型两笔账绑死——想要 70B 的能力就得付 70B 的算力。MoE 把它们解耦:总参数管容量,激活参数管成本,用稀疏激活实现「知识量接近大模型、单 token 算力接近小模型」。
          • 关键组件与参数:
            1. 路由器:一个小的线性层,对每个 token 输出在 N 个专家上的概率分布,取 top-k;
            2. 总参数 vs 激活参数:两者之比≈「稀疏度」。Mixtral 8x7B:总参数 46.7B、激活 12.9B(每层 8 专家、top-2);DeepSeek-V3:总参数 671B、激活约 37B(每层 256 个路由专家加 1 个共享专家、每个 token 激活 8 个);
            3. 负载均衡:若所有 token 都涌向同一个专家,其余专家闲置、硬件利用率崩盘。经典做法是给损失函数加辅助负载均衡损失(惩罚路由分布不均匀,Switch Transformer 起使用);DeepSeek-V3 进一步提出无辅助损失的均衡策略(给每个专家加动态偏置来调节路由),训练更稳;
            4. 专家并行(EP):把不同专家放到不同 GPU,配合 all-to-all 通信,是超大 MoE 训练的标配。
          Dense(稠密) MoE(稀疏)
          每层结构 一个 FFN,所有参数参与 N 个专家 FFN,路由器挑 top-k
          总参数 vs 激活 相等 总 ≫ 激活(常差 5~20 倍)
          单 token 算力 随总参数线性增长 只随激活参数增长
          显存/存储 全量权重 所有专家都须驻留显存(总参数)
          代表 Llama 3 8B / 70B Mixtral 8x7B、DeepSeek-V3、Qwen-MoE
          短板 容量与算力绑死 路由开销、显存大、微调/量化更复杂
          • 工程判断:MoE 用「更大的显存/存储」换「更低的算力/延迟」——只在总参数足够大、并发足够高时才划算;小模型、低并发或边缘设备上,Dense 反而更省心。这也是为什么开源社区既有 Dense 的 Llama,也有 MoE 的 Mixtral、DeepSeek 并存。

          4.4 多模态架构:视觉编码器与对齐

          • 概念:让一个模型同时处理文本与图像(乃至音频、视频)。Transformer 只吃 token,所以多模态的核心问题是:怎么把图像变成模型能读的 token,并让这些 token 与文本 token 「说同一种语言」。
          • 机制拆解(以 LLaVA 为代表的对齐路线):① 视觉编码器:用 ViT 把图像切成 16×16 的 patch,编码成一组向量(直接借 CLIP 预训练好的 ViT-L/14,便宜又有效);② 投影层(对齐):一个线性层或小 MLP,把视觉向量映射到文本 embedding 的维度空间;③ 融合:对齐后的视觉向量与文本 token 拼接,一起送进 decoder-only 的 LLM。训练分两阶段:先冻结编码器做特征对齐预训练,再对全模型做指令微调。
          • 两条实现路线:
          路线 做法 代表
          外挂对齐 现成 LLM + 视觉编码器 + 投影层拼接,分阶段训练 LLaVA、MiniGPT-4
          原生多模态 从预训练起就把图像 patch、音频帧 token 化进统一词表,一个 Transformer 端到端学 GPT-4o、Gemini
          • 为什么需要它:现实世界的信息本就是多模态的(看图、听音、读文档);单模态模型既浪费了数据,也撑不起「视觉问答、语音助手、视频理解」这类产品。
          • 作用与工程要点:一个接口同时吃图文,解锁看图说话、文档解析、屏幕理解等能力;CLIP(2021)用对比学习在 4 亿图文对上训练双塔(拉近配对图文、推远错配),产出的视觉表示成了整个对齐路线的底座。工程上要注意:patch 数随分辨率平方增长(512×512 图≈上千个视觉 token),直接推高算力与 KV cache——所以多模态推理的账单往往由「图」而不是「字」决定。

          4.5 选型框架:从任务到架构

          你的任务 推荐架构 代表模型 为什么
          文本分类/抽取/语义检索(要 embedding) Encoder-only BERT 系、bge 系 双向表示更利于理解;检索要高质量向量
          对话/写作/代码/Agent Decoder-only Llama、Qwen、DeepSeek 生成型产品的主形态,生态最全
          翻译/长文档摘要(结构转化强) Encoder-Decoder T5、BART 编码器先消化全文,解码器再产出
          看图说话/文档解析/多模态问答 多模态(对齐或原生) LLaVA、GPT-4o、Gemini 任务本身跨模态
          文生图/图生图/视频生成 Diffusion Stable Diffusion 系 连续高维数据生成的事实标准
          图像分类/检测(非生成) CNN 或 ViT ResNet、ViT 任务传统、模型小、延迟低
          预算有限但想要大模型能力 Decoder-only + MoE Mixtral 8x7B、DeepSeek-V3 激活参数小,推理单价低
          • 读模型卡(config.json)四件事:① architectures 字段——确认是哪类(如 LlamaForCausalLM = decoder-only);② 总参数 vs 激活参数(区分 MoE);③ 上下文长度与分词器;④ 精度(FP16/BF16/量化)。看懂这四项,你就能在选型时把「能力、显存、单价、延迟」四本账算清楚——这正是下一章训练、推理与服务的入口。

          5. 总结

          5.1 本章一览

          概念 一句话
          模型架构 数据流过模型的计算管线,体现对任务的先验
          五大家族 CNN(图像局部)、RNN(时序,已退场)、Transformer(文本主线)、Diffusion(图像生成)、MoE(稀疏化改造)
          三类信息流 Encoder-only 读(BERT)、Decoder-only 写(GPT,主流)、Encoder-Decoder 读写(T5)
          Dense vs MoE Dense:总参数=激活参数;MoE:路由器挑 top-k 专家,容量与算力解耦
          多模态 视觉编码器(ViT)+ 投影对齐 + LLM;或原生统一 token 空间
          选型本质 任务形态 → 信息流方向 → 容量与成本预算 → 生态支持

          5.2 思考题

          1. 为什么「生成图像用扩散、生成文本用自回归 decoder」?两者的数据形态差异在哪?
          2. Mixtral 8x7B 总参数 46.7B、激活 12.9B:推理算力对标多大的 Dense 模型?部署显存又得按哪个数准备?
          3. 同样做文本理解,BERT 为什么常被拿来当检索模型,而很少直接做聊天?
          4. 多模态的「对齐」到底在对齐什么?直接把视觉向量和文本向量拼一起,会遇到什么问题?
          5. 拿到一个新模型,你会先看模型卡(config.json)的哪几个字段来判断它适不适合自己的任务与机器?

          参考答案

          1. 图像是连续高维数据,没有天然的「逐词展开」顺序,直接回归像素极难,扩散把生成拆成上千步简单去噪,稳定可控;语言是离散 token,天然有从左到右的顺序,自回归解码(每步一个 token)既简单又和语言结构一致。
          2. 推理算力对标约 13B 的 Dense(激活参数 12.9B);但部署显存要按总参数 46.7B 准备(约 94GB FP16,4-bit 量化约 24GB),因为所有专家都要驻留显存。
          3. BERT 双向编码,擅长把输入「压成」高质量表示,适合产出 embedding 做检索/相似度;它不会逐词生成,天然不适合对话这种生成任务。
          4. 对齐是把视觉向量映射到与文本 token 相同的表示空间(同一维度、相近语义),这样注意力才能在图文之间自由交互;直接拼接,视觉向量与文本向量「语言不通」,模型学不到图文关系,还会因分布不匹配拖慢训练。
          5. 看 architectures(哪类架构)、总参数 vs 激活参数(是否 MoE,决定显存与单价)、上下文长度(决定能装多长的输入)与精度要求(决定能否本地部署)。
