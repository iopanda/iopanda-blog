          01.01.06

          Transformer 架构

          2026-09-02 · iopanda

          • course
          • transformers
          • foundations

          上一章我们认识了注意力机制:它让 token 之间「互相打量、按重要性汇总信息」。本章回答一个更激进的问题:如果完全不写循环、不写卷积,只用注意力这一种构件,能不能搭出一个完整的、能干活的语言网络? 2017 年谷歌的论文《Attention Is All You Need》给出了答案——能,这就是 Transformer。它是 GPT、BERT、T5 乃至今天几乎所有大语言模型的共同骨架,值得你花一整章把它拆开看明白。

          学习目标:学完本章,你将能够——

          1. 用自己的话说出 Transformer 是什么,并说清它和 RNN、CNN 的本质区别;
          2. 解释 2017 年之前序列模型(尤其 RNN)的三重困境,以及「纯注意力」为何能同时化解;
          3. 说出 Transformer 的四大核心组件,并解释每个组件「为什么这么设计」;
          4. 描述编码器、解码器各自的职责,解释因果掩码的作用;
          5. 区分 encoder-only、decoder-only、encoder-decoder 三种架构,并说出 GPT 属于哪一种。

          1. 概念:Transformer 是什么

          • Transformer 是一种神经网络架构:它把一串向量(通常是 token 的嵌入表示)作为输入,通过多层「自注意力 + 前馈网络」的堆叠,输出一串同样长度、但携带了全局上下文的新向量。因为内部信息流动像「变换」一样层层改写表示,故得名 Transformer。
          • 它由谷歌 8 位研究者于 2017 年 6 月在论文《Attention Is All You Need》中提出(NeurIPS 2017 发表),原文一句话概括:**「完全基于注意力机制、彻底抛弃循环与卷积」**的序列模型。
          • 用流水线理解:输入 token → 嵌入 + 位置编码 → N 层编码块 → 输出表示。每个编码块内部只做两件事:多头自注意力(token 之间交换信息)和逐位置前馈网络(每个 token 独立做非线性加工)。

          1.1 与 RNN、CNN 的本质区别

          对比维度 RNN / LSTM(循环) CNN(卷积) Transformer(注意力)
          处理方式 逐 token 串行,后一步等前一步 滑动窗口局部卷积 全序列同时计算
          看多远 靠隐藏状态逐步传递,远距离衰减 靠堆层扩大感受野 一步直达任意两个位置
          并行性 差(顺序依赖) 好 好(全是矩阵乘法)
          结构前提 认为「相邻才有关系」 认为「窗口内才有关系」 不预设关系,由数据学习
          • 关键点:RNN 与 CNN 都隐含「位置结构」假设,而 Transformer 对输入不抱任何位置偏见——关系远近完全由注意力权重学习出来。这也解释了为什么它需要「位置编码」来补偿(见 4.3 节)。

          2. 为什么需要它:三个绕不开的瓶颈

          • 2017 年之前,处理序列(翻译、摘要)的主流是 RNN/LSTM。它有三个结构性瓶颈,Transformer 正是为同时解决它们而生:
          1. 串行计算,无法并行:第 t 个词必须等前 t-1 个词算完,训练长句极慢,且与 GPU/TPU 擅长的并行计算「错配」;
          2. 长距离依赖衰减:两个相关词隔得越远,信息要穿过越多的循环步,梯度与语义都容易消失——「银行在河……过了桥」里的指代很难学;
          3. 路径过长:想让相距 n 的词互相影响,RNN 至少要 n 步顺序操作;论文指出这对学习「跨距离的决策」是根本性障碍。
          • 与此同时,上一章的注意力机制已经证明:它能用一次「查询—键值」打分,直接建模任意两个 token 的关系,且全部是矩阵运算、天然可并行。既然如此,为什么还要循环结构? 论文的回答斩钉截铁:不要了——注意力本身就是够用的构件,这就是标题「Attention Is All You Need(注意力就是一切所需)」的含义。
          • 战绩(论文原文):在 WMT 2014 英德翻译上,Transformer 以 28.4 BLEU 刷新纪录(超过此前所有最优集成模型),而训练只用了 8 块 P100、3.5 天——训练成本远低于同类 RNN 模型。质量更高、训练更快、还更贴合现代硬件。

          3. 它有什么作用:一张通用的「万能骨架」

          • 架构红利:同一套结构不加改动就能做翻译、摘要、问答、代码生成、图像处理……不再需要为每种任务发明新网络。此后 BERT、GPT、T5 全是它的变体;今天的主流大语言模型几乎全部是 Transformer(多数是其中的 decoder-only 一支)。
          • 规模红利:注意力与全连接层都是矩阵乘法,能吃满 GPU/TPU;这让「把模型和数据同步放大」成为可能——Transformer 之后才谈得上「大力出奇迹」的 scaling(规模扩展)。
          • 工程红利:推理时只需缓存历史键值(KV cache)即可逐个生成 token;注意力可视化还能帮工程师诊断模型在「看哪里」,这是黑箱 RNN 难以提供的可解释性。
          • 架构裁剪:Transformer 原装是「编码器 + 解码器」两件套,但工程上可以按任务只留一半——这就演化出三大流派(详见 4.5 节),生成式大模型(GPT)正是 decoder-only 流派,这是下一章语言建模的直接铺垫。

          4. 详细介绍:四个关键设计逐一看

          原论文的基准配置(base model):编码器 6 层 + 解码器 6 层;表示维度 d_model = 512;注意力 8 个头,每个头维度 d_k = d_v = 64;前馈网络隐层 2048;dropout 0.1。下面每个组件都对应一个「为什么要这样设计」的答案。

          4.1 缩放点积注意力:信息如何流动

          • 回顾上一章:每个 token 生成 Query(问)、Key(标)、Value(内容)三个向量。先算「问」与所有「标」的点积得到相似度,归一化成权重,再对「内容」加权求和——这就是缩放点积注意力:
          Attention(Q, K, V) = softmax( Q · Kᵀ / √d_k ) · V
          text
          • 为什么要除以 √d_k(缩放)? 向量维度越大,点积数值越大,softmax 越容易进入两端饱和区,梯度趋近于零、学不动。除以维度平方根把数值拉回稳定区间。这一处「小缩放」是让深层网络可训练的关键细节。
          • 为什么叫自注意力(self-attention)? 因为 Q、K、V 全部来自同一串输入(编码器里就是上一层输出)——序列在「自己打量自己」,每个词的新表示都融合了全文对它有用的信息。

          4.2 多头注意力:不止一种「关系」

          • 概念:不把 d_model 维的注意力算一次,而是拆成 h=8 个并行的子空间,各算各的缩放点积注意力,再把 8 个结果拼接、线性投影回原维度。
          • 为什么需要:单次注意力只能学一种「相关」——而句子里的关系五花八门:语法依赖、指代消解、语义相似、局部搭配……多头让不同的头各学一种关系,相当于 8 个专家小组从 8 个角度审阅同一段话,再汇总意见。
          • 作用:原论文与后续可视化都观察到,不同头确实分化出不同职能(有的盯指代、有的盯句法)。多头是「注意力从能用到好用」的关键一步,也是并行计算的天然受益者:各头互不依赖,可同时算。

          4.3 位置编码:给「无序」补上顺序感

          • 问题:注意力是「集合运算」——把一句话的 token 顺序打乱,注意力打分结果不变。但「猫追狗」和「狗追猫」意思完全相反,模型必须知道谁先谁后。
          • 原始方案:在输入嵌入上逐元素相加一组正弦/余弦编码,不同位置得到不同波形,位置信息随嵌入一起进入网络:
          PE(pos, 2i) = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
          text
          • 为什么用三角函数:同一频率下相邻位置波形平滑过渡,模型既能分辨绝对位置,也能从波形相位差感知「相对距离」;且该方案不需要额外参数、可外推到训练中没见过的更长序列。
          • 现代演进:如今的主流大模型(GPT 系列、Llama)大多改用旋转位置编码(RoPE)——把位置信息编码进 Q、K 的旋转角度,天然携带相对位置且对长文本更友好。理解「注意力本身无序、必须额外注入位置」这一点,比记公式更重要。

          4.4 前馈网络、残差连接与层归一化:让网络深而不崩

          • 逐位置前馈网络(FFN):注意力本质是「信息的加权搬运」(线性混合),本身不含非线性。每个编码块随后对每个 token 独立过一个两层全连接 + ReLU(现代常用 GELU)的网络,做一次非线性变换——这一层是模型容量与「思考」的主要来源,参数占比也最大。
          • 残差连接(Residual):每个子层输出都写成 x + Sublayer(x)——把原始输入旁路加回来。为什么需要? 网络深了梯度要穿过很多层,残差给梯度开了一条「高速公路」,让 6 层、几十层乃至上千层都能稳定训练。
          • 层归一化(LayerNorm):对每个 token 的向量做归一化(均值 0、方差 1),稳定各层数值分布。为什么需要? 深网络中激活值尺度漂移会放大训练的不稳定性,归一化相当于给每层配了「仪表盘」,让梯度下降步伐均匀。
          • 小结:编码块 = LayerNorm(残差 + 多头注意力) 与 LayerNorm(残差 + FFN) 的组合,这两件套堆 6 层就是编码器;解码器同构,但注意力被加了「锁」,见下。

          4.5 编码器、解码器与掩码:理解与生成的分工

          • 编码器(Encoder):双向阅读整句,每个位置都能看全句——产出「对输入的理解」,适合理解类任务。
          • 解码器(Decoder):逐词从左到右生成。内部有两处不同:
            1. 因果掩码(masked self-attention):算注意力时把「未来位置」的分数设成 -∞,softmax 后权重为 0——第 t 个词只能看自己和它之前的词,不能偷看答案。这保证了自回归性质(每个词只依赖已生成的词);
            2. 交叉注意力(cross-attention):Q 来自解码器自己,K、V 来自编码器输出——生成每个词时回头「查阅」输入句,这正是翻译模型「看懂原文再写译文」的机制。
          • 三大流派:原论文是完整的 encoder-decoder,但工程上按任务裁剪出三种形态:
          流派 结构 训练目标 代表模型 擅长任务
          Encoder-only 只留编码器 掩码语言建模(填空) BERT 理解、分类、抽取
          Decoder-only 只留解码器 因果语言建模(续写) GPT、Llama 生成、对话、通用助手
          Encoder-decoder 两件套齐全 条件生成 T5、原始 Transformer 翻译、转换类任务
          • 为什么 decoder-only 反而统治了今天?因为它把「一切任务都改写成续写」——模型只会一个动作:预测下一个 token,却因此获得通用能力。这扇门通向下一章的语言建模。

          5. 局限:注意力不是万能的

          • 平方级成本:每个 token 都要和全部 token 打分,计算与内存随序列长度 O(n²) 增长——长上下文是 Transformer 的天然软肋(工程上已有 FlashAttention、稀疏注意力、线性注意力等缓解手段,属 08 章内容)。
          • 位置靠「注射」:注意力本身无视顺序,模型对位置的感知完全依赖外部编码的强弱,处理超长文本时位置信号会稀释。
          • 骨架而非知识:Transformer 只是信息路由的「骨架」,它本身不含事实与常识——能力来自海量文本上的预训练。骨架 + 数据 + 算力三者齐备,才构成今天的大语言模型。

          6. 总结

          6.1 本章一览

          概念 一句话
          Transformer 纯注意力、无循环无卷积的序列架构(2017,谷歌)
          为什么需要 RNN 串行慢、远距离衰减、与硬件错配
          核心组件 缩放点积注意力、多头、位置编码、FFN + 残差 + LayerNorm
          掩码的意义 因果掩码挡住未来,保证逐词自回归生成
          三大流派 encoder-only(BERT)/ decoder-only(GPT)/ encoder-decoder(T5)

          6.2 思考题

          1. 为什么说「RNN 无法并行,而 Transformer 可以」?并行性差除了慢,还带来什么连锁后果?
          2. 如果去掉缩放因子 √d_k,模型训练可能出什么问题?请从 softmax 的梯度角度解释。
          3. 把「猫追狗」的 token 顺序打乱后重排,Transformer 的注意力打分不变——这句话对吗?模型靠什么区分顺序?
          4. 解码器生成第 5 个词时,因果掩码保证了什么?如果去掉掩码,训练会变成什么样?
          5. GPT 是 decoder-only,那它做「翻译」时输入输出如何组织?(提示:想想「一切任务皆续写」)

          参考答案

          1. RNN 第 t 步依赖第 t-1 步的隐藏状态,只能串行;Transformer 的注意力是矩阵运算,所有位置同时算。慢之外,顺序结构还限制了可并行训练的设备规模,进而限制了模型能多大——这是「规模扩展」路线的前提障碍。
          2. 维度大时点积数值大,softmax 进入饱和区,对「谁更重要」的分辨变钝且梯度趋零,参数几乎无法更新。√d_k 把分数缩回合适量级。
          3. 对——单看注意力,序列是无序集合。模型靠位置编码(原始正弦波/RoPE)区分顺序,位置信息叠加进嵌入后才参与打分。
          4. 第 5 个词只能参考前 4 个已生成词,训练时也模拟这种「看不到未来」的处境;去掉掩码等于让模型偷看答案,训练与推理行为不一致,生成质量崩坏。
          5. 把任务拼成提示词模板,如「把『猫追狗』翻译成英文:」,模型接着续写「The cat chased the dog」——翻译被统一成条件续写,这正是 decoder-only 通用化的秘密。
