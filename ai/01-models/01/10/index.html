          01.01.10

          模型能力与局限

          2026-09-02 · iopanda

          • course
          • ai-models
          • foundations

          这是 Foundations 单元的收尾章:前面九章回答了「模型怎么造出来、怎么跑起来」,本章回答「它到底能做什么、不能做什么,不能做的事如何兜底」。读完你会得到一张「能力地图 + 失效清单 + 责任分工表」,这是进入预训练、微调、评测等后续单元前的必要认知装备。

          学习目标:学完本章,你将能够——

          1. 列出语言模型最擅长的五类任务,并解释「为什么擅长」;
          2. 说出四类核心局限(幻觉/知识时效/上下文/非确定性)的成因与各自缓解手段;
          3. 识别提示注入、信息泄露等系统级风险,并把防线分到模型/系统/人三层;
          4. 用「任务定义 → 评测集 → 持续指标」三步法评估任何一次模型使用;
          5. 说出「模型-系统-人」三层责任原则,并为某个 AI 功能画出责任分工。

          1. 概念:能力与局限是一枚硬币的两面

          • 模型能力:模型把训练数据中学到的统计规律泛化到新输入上的本领——会改写、会总结、会接话、会续写。
          • 模型局限:同一套机制在信息不足、分布之外或缺少校验时的必然失效——编造、过时、健忘、时好时坏。
          • 为什么两者必须一起讲?因为模型没有内置的「我知道/不知道」开关(01 章已提示):它不会主动报告自己的不确定。能力是「会说话」,局限是「说的话不一定为真」——两者源于同一个机制:它学的是「下一个词像什么」,不是「下一个词对不对」。

          生活类比:模型像一个读过海量书、反应极快、但从不查证、记忆只有最近几页的速读者。你问它什么它都能接上话,却分不清「记得的」和「编的」。

          擅长的一面 同源的另一面(局限)
          生成流畅自然 流畅不等于事实正确(幻觉)
          记住海量训练知识 知识停留在训练截止日
          一次可处理很长的输入 窗口有限,超出即忘
          每次回答有创造性 同一问题结果可能不同

          作用:把「能力地图」和「失效清单」同时装进脑子,工程决策(哪里敢全自动、哪里必须加人)才有依据。本章不是让你害怕模型,而是让你在知道边界的前提下放心用。

          2. 为什么需要:边界决定架构,责任决定成败

          • 对模型能力与局限的误判,是 AI 工程最常见的两类失败:
          误判 表现 后果
          高估能力 把输出直接当事实入库、直接执行动作 幻觉污染数据、自动操作酿成事故
          低估能力 明明可自动化仍全流程人工 成本与效率优势归零,失去采用价值
          • 边界决定架构:局限不是「缺点清单」,而是系统设计的输入——哪类局限用检索补(时效、事实)、哪类用工具补(实时数据、计算)、哪类用校验补(格式、权限)、哪类用人补(高风险判断):
          局限/风险 首选系统手段 对应后续章节
          事实错误、幻觉 RAG 检索增强、输出注明来源 01.06 评测与基准
          知识过时 搜索/工具调用实时取数 01.02 数据管线
          上下文不够 摘要压缩 + 检索切片 01.04 部署与生成控制
          非确定输出 低温 + schema + 重试校验 01.04 Generation Controls
          高风险动作 人工复核、最小权限 01.07 安全与治理
          • 一句话:读本章前,你看到的是「模型什么都会」;读完后,你看到的是「每个能力旁边都写着使用条件」。

          3. 它擅长什么:五类核心能力

          • 语言模型本质是「在约束下续写文本」的机器,因此凡是能用语言表达、且答案藏在语言规律里的任务,它都表现出色。最常用的五类:
          能力 是什么 为什么擅长 典型场景 使用注意
          改写 换风格、换语气、扩写/缩写而语义不变 续写天然擅长「保持语义换说法」 文案润色、翻译、代码转译 检查是否丢了限定条件
          总结 把长文压成要点 注意力机制能从长上下文抓重点(05/06 章) 会议纪要、文档摘要 关键数字需抽查核对
          分类 把文本归入预设类别或抽取字段 分类 = 输出受限的续写,给几个示例(few-shot)即可 工单路由、情感分析、实体抽取 领域漂移后要重新评测
          生成 开放创作:初稿、代码、创意 从语言分布采样(07 章),分布学得越广越能组合 代码补全、头脑风暴、写初稿 质量波动大,需要审阅门槛
          模式发现 从非结构化文本中找规律、聚类、找异常 预训练压缩了海量文本的统计关联 日志归纳、合同异常条款扫描 「规律」可能是巧合,必须验证
          • 一个「全能实习生」的比喻:它上手快、语感好、知识面广,但不能独立对事实负责——你给它明确任务和复核机制,它产出惊人;你撒手不管,它就一本正经地胡说。
          • 作用:这五类能力是上层所有应用(助手、Agent、搜索)的积木;先识别任务属于哪一类,再决定用提示词、RAG 还是微调去落地。

          4. 详细介绍:四类核心局限与缓解

          • 共同根源只有一条:模型只学过「文本像什么」,从未学过「世界是什么」。训练目标是最大化下一个词的概率,不是建立可查证的事实库;因此以下四类失效是结构性的,只能缓解、无法根除。

          4.1 幻觉(Hallucination)

          • 概念:模型输出语法流畅、自信满满但与事实或用户提供的上下文不符的内容。可分两类:事实幻觉(编造事件、数据、来源)与忠实性幻觉(与对话中的既有材料矛盾)。
          • 为什么发生:① 生成时它只是在做「最像样的续写」,事实对它只是统计上的「常见搭配」;② 知识以参数形式压缩,冷门细节在训练中被「平均」掉;③ 训练与对齐普遍奖励「给出答案」而非「承认不知道」,模型学到的倾向是猜,而不是说「不知道」。
          • 缓解:检索增强(RAG)强迫它「看着资料说话」并要求给出来源;提示里写明「没有依据就明说不知道」;事实型任务调低 temperature;高风险场景人工复核。IBM 的结论值得记住:幻觉可以显著减少,但无法完全消除——所以系统必须默认「它偶尔会编」。

          4.2 知识时效

          • 概念:模型的知识冻结在训练数据截止日期,此后发生的事它不知道;而它不会主动声明「我的知识过时了」。
          • 为什么发生:预训练一次成本极高(09 章),不可能随新闻实时更新;参数化知识也不支持「改一条记录」式的增量修改。
          • 缓解:需要时效信息的任务,优先接工具调用/搜索引擎/数据库,让它「去查」而不是「回忆」;或走 RAG 把最新文档喂进上下文;只有长期稳定的领域知识才值得用重训或微调刷新。

          4.3 上下文限制

          • 概念:模型一次只能「看到」上下文窗口内的 token(常见 4K~200K 不等),窗口之外的内容对它不存在;窗口内的记忆只是临时工作台,对话结束即清零。
          • 为什么发生:注意力计算量随序列长度增长(05/06 章),窗口大小是算力与成本的工程取舍;同时研究发现模型对超长上下文的中间部分利用率偏低(lost in the middle)。
          • 缓解:长文档先摘要压缩再处理;用检索只把相关片段放进窗口,而不是整库硬塞;把长任务拆成多轮短任务;把「数据库」放在系统侧(向量库),窗口只当「工作台」。

          4.4 非确定性

          • 概念:同一提示、同一模型,多次调用结果可能每次不同,尤其 temperature > 0 时;这对测试、复现、对账都是挑战。
          • 为什么发生:推理本质是从概率分布采样(07 章);temperature 控制分布尖锐程度,top-p/top-k 控制候选范围,采样本身自带随机性。
          • 缓解:事实与代码类任务把 temperature 调低或置 0、固定 seed;用结构化输出约束格式(schema/JSON);业务侧做幂等设计与重试校验;评测时多次采样看分布,不要用单次结果下结论。

          4.5 局限与缓解一览

          局限 一句话成因 一句话缓解
          幻觉 学「像不像」,不学「对不对」 RAG + 要求注明不确定 + 人工复核
          知识时效 知识是训练快照 工具调用/搜索取实时数据
          上下文限制 窗口有限,且只是临时工作台 压缩 + 检索切片 + 任务拆分
          非确定性 生成是随机采样 低温 + schema + 多次采样评测

          5. 风险:从模型局限到系统事故

          • 前四节是模型单点的局限;一旦模型被接进系统、喂进外部数据、授予工具权限,局限就会放大成风险。OWASP《LLM 应用十大风险(2025)》把这类问题排在最前——工程上必须按风险对待,而不是按「模型怪癖」容忍。
          风险 是什么 为什么会发生 主要防线
          提示注入(LLM01) 输入内容(用户提问,或网页/文档里的隐藏文字)篡改模型行为,令其执行攻击者指令 模型分不清「指令」与「数据」,外部内容也能指挥它 指令/数据分离、输出校验、最小工具权限;不把系统提示当安全边界
          敏感信息泄露(LLM02) 输出泄露训练数据中记住的、或上下文中的隐私与密钥 模型会复述记忆与上下文;日志、插件都可能成为出口 脱敏与数据最小化、密钥不进提示词、DLP 检测
          偏见放大 对特定人群或话题输出系统性偏差 训练语料本身含社会偏见,模型学会并放大 分群体评测、提示去偏、敏感场景人工审查
          版权与抄袭 逐字复现训练语料中的受版权文本 高频文本被模型「背下来」 输出相似度检测、合规审查、审慎用于商业发布
          过度自动化 模型被授予过高行动权限,幻觉直接变成真实动作(删数据、下单、发信) 权限过宽、缺少人在回路 最小权限、分级自动化、高影响动作强制人工确认
          • 注意共同模式:这些风险大多不是「模型太笨」,而是「系统把模型的输出当成了可信事实或可信指令」——防线应设在系统与人,而不是指望模型永远不出错。

          6. 如何正确评估:别用「感觉」,要用「测量」

          • 概念:评估 = 用可复现的方法回答「这个模型在我的任务上到底行不行」,而不是拿几个漂亮 demo 下结论。
          • 为什么需要:模型的「强」是平均意义上的强,换到你的领域、你的输入分布,表现可能完全不同;没有评测的「感觉好用」不可靠(01 章第四问)。
          • 三步法:
          步骤 做什么 常见错误
          ① 任务定义 写清输入/输出、成功标准、错误代价 任务边界模糊,无法判断对错
          ② 评测集 建黄金数据集:典型样例 + 边界样例 + 已知失败样例 样例太少、只测顺利路径
          ③ 持续指标 上线后持续监控准确率、拒绝率、漂移、抽检反馈 上线即停测,退化无人知
          • 详细介绍三点:任务定义决定「对错」标准——摘要任务看要点覆盖还是逐字忠实?客服任务看解决率还是语气?标准不同,同一个模型的结论可能相反。评测集要覆盖失败模式(幻觉多发的问题、长输入、对抗输入),而不是只报平均分;平均分漂亮但特定失败致命的情况很常见(01.06 评测单元会展开)。持续指标要接生产:模型会换代、输入会漂移,指标必须能报警。
          • 一句话:**能力需要证明,局限需要测量。**两者都靠评测,不靠印象。

          7. 模型-系统-人:三层责任原则

          • 概念:AI 出错时,责任不该笼统落在「模型不行」或「用户不小心」上,而应按在哪一层可以预防来分配:模型层负责选对与声明边界,系统层负责兜底与拦截,人层负责判断与复核。
          • 为什么需要:真实事故几乎都是三层同时失守——模型幻觉(模型层)+ 没有校验与权限控制(系统层)+ 无人复核就自动执行(人层)。NIST《AI 风险管理框架(AI RMF)》的核心思想正是:把可信性要求贯穿设计、开发、使用全生命周期,由各角色分担责任。
          层级 负责什么 典型手段
          模型层 选对模型、如实声明能力边界 模型卡(model card)、任务与模型匹配、能力外任务不用它
          系统层 把「模型可能错」当默认前提,工程兜底 RAG、护栏、输出 schema 校验、最小权限、日志审计、持续评测
          人层 在错误代价高的地方把关 高风险动作人工复核、对最终输出负责、合规与数据权限管理
          • 一个实用判断:谁最后按下按钮,谁就要能校验结果。全自动的前提不是「模型足够可靠」,而是「出错代价足够小、系统能发现并回滚」。
          • 责任划分也回答一个常见困惑:「幻觉是模型的错吗?」——模型层只能说它没把边界说清楚;把幻觉输出直接当事实执行,是系统与人的失职。把责任放到能预防的那一层,问题才真正可解。

          8. 总结

          8.1 本章一览

          主题 一句话
          能力来源 模型擅长的是语言统计规律,不是世界知识
          五类擅长 改写、总结、分类、生成、模式发现
          四类局限 幻觉、知识时效、上下文限制、非确定性(可缓解、难根除)
          系统风险 提示注入、信息泄露、偏见、版权、过度自动化
          评估三步 任务定义 → 评测集 → 持续指标
          责任三层 模型选对与声明、系统兜底与拦截、人判断与复核

          8.2 思考题

          1. 为什么说「生成越流畅,越要警惕幻觉」?两者共享哪个机制?
          2. 一个客服机器人需要回答实时价目表问题:该用 RAG、工具调用还是重训模型?为什么?
          3. 什么是间接提示注入?为什么它比用户直接输入的恶意指令更难防?
          4. 你要上线「AI 自动回复客户邮件」功能:按模型-系统-人三层,每层至少写出一条措施。
          5. 「模型通过了我们 200 条评测样例」能说明它可靠吗?还缺什么?

          参考答案

          1. 两者都源于「下一个词预测」:模型只追求「像样」,流畅度来自分布学得好,事实性却没有任何机制保证——流畅恰恰是它「自信地错」的放大器。
          2. 优先用工具调用/搜索 API 实时取数,或 RAG 检索最新价目表:价目表更新频繁且事实要求高,重训成本高且时效仍差;把「数据」放在模型之外,让模型只负责组织语言。
          3. 间接提示注入是攻击者把指令藏在网页、文档、邮件等外部内容里,模型读取内容时被「带跑」。它更难防是因为内容本身是正常业务数据、用户并未恶意,系统无法靠「过滤用户输入」挡住,必须做指令/数据分离与输出校验。
          4. 模型层:选指令遵循能力强的模型,并声明适用边界;系统层:只授只读权限、输出过 PII 与敏感词过滤、全程留日志、每日抽检;人层:设定「仅低风险内容可自动发送」,其余转人工确认。
          5. 不够:200 条样例无法覆盖真实输入分布;还需要任务定义明确、样例覆盖失败模式与边界情况、上线后持续监控指标,并测算错误代价以决定是否需人工兜底。
