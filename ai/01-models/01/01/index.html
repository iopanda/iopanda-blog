          什么是 AI 模型

          本章不只解释「模型」这个词,而是回答三个递进的问题:它到底是什么、为什么需要它、它有什么用。读完你会建立一个判断框架,知道后续所有章节(神经网络、Transformer、语言建模)在整张拼图里的位置。

          学习目标:学完本章,你将能够——

          1. 用自己的话定义 AI 模型,并区分模型、算法、权重三个易混概念;
          2. 解释「基础模型 / 大语言模型 / 生成式 AI」的关系;
          3. 说出为什么传统编程规则写不出今天的大模型能力;
          4. 画出一张「模型 → 产品」的分层图(模型、提示词、知识库、工具);
          5. 用四个问题快速评估任何一次模型选型。

          1. 概念:AI 模型是什么

          • AI 模型是一个从输入到输出的数学函数:它接收数据(文本、图像、语音……),经过内部计算,输出预测或新内容。
          • 它的特殊之处在于:函数的具体行为不是人写的,而是从大量样本里「学」出来的。
          • 用公式表达:y = f(x; θ),其中 x 是输入、y 是输出、θ 是模型参数。训练 = 调整 θ,让 f 的输出接近正确答案。

          1.1 与「普通程序」的本质区别

          对比维度 传统程序 AI 模型
          规则来源 程序员逐条手写 从数据中自动归纳
          面对新情况 没写到的就出错 能泛化到没见过的输入
          内部结构 清晰可读的 if/else 数百万参数的数值矩阵
          错误形态 逻辑 bug 概率性偏差、幻觉
          • 为什么需要模型而不是规则? 因为很多任务人类无法写出规则:怎么判断一张图里有猫?怎么把中文翻译成英文?人类自己能做到,却无法把「判断标准」写成几百条 if。这类任务的共同点是:例子多、规则难——这正是模型(从例子学规则)的用武之地。

          2. 为什么需要它:三类问题的转变

          • 回顾 AI 历史的三个问题形态,就能看清模型解决了什么:
          时代 问题形态 局限
          规则时代 「我写规则,机器执行」 复杂任务规则写不完
          统计机器学习 「我设计特征,机器学映射」 特征工程靠人工,表达力有限
          深度学习/基础模型 「我给大量数据,机器自己学表示」 需要算力、数据、评测纪律
          • 模型(尤其是基础模型)带来的范式转变:过去每个任务训练一个专用模型;现在先在海量数据上预训练一个通用模型,再通过提示、检索、微调适配多种任务——这就是 2021 年斯坦福提出的「基础模型(Foundation Model)」概念的核心。
          • 一句话:基础模型解决的是「通用能力」问题,让 AI 从「一个任务一个模型」走向「一个模型多种任务」。

          3. 它有什么作用:从模型到产品

          • 模型本身不是产品。真正交付给用户的是系统——模型只是其中的「大脑」:
          ┌─────────────────────────────────────────────┐
│              应用(聊天机器人/搜索助手/Agent)    │
├──────────┬──────────┬──────────┬────────────┤
│  模型     │  提示词   │  知识库   │  工具      │
│ 理解+生成  │ 规定任务  │ 补充私有信息│ 查数据/调API│
└──────────┴──────────┴──────────┴────────────┘
          text
          • 这个分层解释了后续章节的安排:模型内部(03~08 章)解决「能力从哪来」;知识检索、工具调用、Agent(02 系列)解决「能力如何被可靠使用」。
          • 作用总结:模型承担的是「理解和生成」这一核心智能动作;其余(记忆、执行、校验)由系统组件分工完成。

          4. 容易混淆的三个词

          词 含义 例子
          算法 解决问题的方法/步骤 梯度下降、注意力机制
          模型 算法 + 参数结合后的可运行产物 GPT-4、Llama 3
          模型权重 训练完成后保存的参数文件 llama-3-8b.gguf
          • 日常说「下载了一个模型」,准确说是下载了权重;「用 PyTorch 训练」,是让算法去更新权重,最终产出模型。

          5. 模型不等于「全能」

          • 大模型会写诗、会写代码、会翻译,看起来无所不能,但它有三个结构性特征:
            1. 概率性:它生成的是「语言上合理的延续」,不是「查证过的事实」;
            2. 无真实记忆:对话中的「记得」是上下文窗口内的临时状态;
            3. 能力边界模糊:它没有内置的「我知道/不知道」开关,容易一本正经地编造(幻觉)。
          • 因此工程上要用系统手段补足:检索增强(RAG)提供事实、工具调用提供实时数据、评测约束质量、人工复核兜底。

          6. 使用模型时应问的四个问题

          1. 输入和输出各是什么,错误的代价有多大? 决定要不要加校验/人工;
          2. 需要领域知识吗? 若需要,优先考虑 RAG(外部检索)、工具调用还是微调(01.03);
          3. 如何评测质量、延迟、成本与安全? 没有评测的「感觉好用」不可靠(01.06);
          4. 数据与合规边界是什么? 输入是否含敏感信息?模型供应商的数据政策?

          7. 总结

          7.1 本章一览

          概念 一句话
          AI 模型 从数据中学出来的输入→输出函数
          为什么需要 例子多、规则难的任务,人写不出规则
          基础模型 预训练通用模型,适配多种下游任务
          模型 vs 权重 算法+参数=模型;权重=参数文件
          产品分层 模型+提示词+知识库+工具=可用系统

          7.2 思考题

          1. 为什么「写规则」的方式做不出图像识别?试着列一个「判断图片有无猫」的规则,看它有多脆弱。
          2. 「基础模型」和「大语言模型」是同一个东西吗?区别在哪?
          3. 模型生成的内容可能出错,工程上能用哪些手段兜底?
          4. 找三个你日常使用的 AI 产品,拆解它们分别用了模型、知识库、工具的哪些部分。

          参考答案

          1. 猫的姿态、角度、遮挡、品种变化无穷,规则会指数级膨胀且互相冲突;模型从标注图片中学习「像猫的特征组合」,能泛化。
          2. 不等同:LLM 是基于文本训练的模型;基础模型是更宽的概念,还包括图像、音频、多模态等模型。所有 LLM 都是基础模型,但基础模型不都是 LLM。
          3. 检索增强提供事实依据、工具调用获取实时数据、输出 schema 约束格式、评测集回归、高风险场景人工复核。
          4. 例如客服机器人=模型(对话)+知识库(FAQ 检索)+工具(查订单接口);代码助手=模型+工具(执行测试);搜索助手=模型+实时检索。
