          数据清洗与去重

          2026-09-02 · iopanda

          • course
          • model-pretraining
          • data-cleaning

          上一章确认了「文本从哪里来、能否使用」,本章回答更麻烦的问题:下载好的原始文本能不能直接喂给模型。先建立三个概念再动手——清洗到底在删什么、为什么原始文件一个字都不能改、精确去重能挡住什么又挡不住什么。读完你会得到一份带统计审计报告的 data/processed/ 语料,交给下一章做切分。

          学习目标:学完本章,你将能够——

          1. 区分原始数据、清洗数据与训练数据,说清清洗的目标与边界;
          2. 解释「清洗不是把文本变漂亮」,以及为什么必须保留原始文件;
          3. 实现编码统一、空白规范化、异常过滤与精确去重;
          4. 用随机样本、长度分布和重复率验证清洗效果,而不是凭直觉下结论;
          5. 为每次清洗保留可复现的规则版本与统计日志。

          1. 清洗目标:为什么不是「把文本变漂亮」

          • 概念:数据清洗(Data Cleaning)是对原始文本做删除与规范化的处理,目标是移除会破坏训练或违反约束的内容,同时尽可能保留语言建模所需的信号。清洗后得到清洗数据(processed);它还要经过切分(第 04 章)与打包,才成为模型真正读到的训练数据(train)——三个阶段在报告里不能混用。
          • 为什么需要:语言模型的全部知识来自文本中的统计规律。原始语料若混入乱码、HTML 残留、模板导航页,模型会把 <div>、页脚版权这类噪音也当成语言规律来学;同一文本被反复收录,又会让模型花大量步数去「背课文」。清洗删掉的是让模型学错或白学的内容,而不是「看起来不好看」的内容——这正是它与「变漂亮」的本质区别。
          • 为什么不这样做会出问题:跳过清洗直接训练,损失不会立刻显现,而是表现为重复内容诱发逐字背诵、验证分数虚高、下游任务泛化变差。研究者在 C4 语料中发现,一个仅 61 词的英文句子竟被重复收录超过 6 万次,未去重模型超过 1% 的无提示输出是训练数据的逐字复制。训练一旦完成,污染就永久写进权重,事后无法区分模型学到的是语言还是垃圾。
          • 取舍:清洗必然有损失,好规则的目标是可解释地删除,而不是删得越多越好。每一条规则都应能回答:删什么、为什么删、误伤了多少。

          需要处理的问题大致分为五类:

          问题类型 例子 不处理的后果
          编码与空白混乱 BOM、\r\n、不可见控制字符 产生伪段落边界与「半个字符」,干扰 token 切分
          非语言残留 HTML 标签、导航文案、乱码 模型学到网页模板,而不是语言
          异常长度 空白行、半个句子、整本书 长度分布失衡,训练不稳定、样本语义不完整
          重复内容 同一文本被多个来源反复收录 浪费训练步数,诱发逐字背诵(见第 3 节)
          隐私与机密 身份证号、密钥、内部文档 模型可能原样输出,带来合规与安全风险(01.07 详讲)

          2. 不可变流水线:原始文件为什么一个字都不能改

          • 概念:不可变流水线(Immutable Pipeline)是一组工程纪律:原始文件只读,永不手工修改;清洗脚本是「读入原件 → 变换 → 写出新文件」的纯函数;每次运行都产生独立的统计报告。
          • 为什么需要:清洗本质是「删掉什么」的判断,事后几乎一定会被追问:当时删了什么、为什么删、阈值是多少。若直接在原始文件上手工修改且不记录,规则就丢失了,任何结果都无法复现、无法追溯。更隐蔽的风险是误伤不可逆:手工改动后原始证据消失,你再也无法重跑更宽松的规则来对比。
          • 作用与分工:raw/ 保存原件(证据),脚本从 raw/ 读取并写入 processed/(产物),报告记录每次运行(审计)。想调整阈值?改脚本重跑,而不是改文件。
          读取 UTF-8 文本 → 规范换行与空白 → 删除空行/异常控制字符
→ 按规则过滤长度 → 精确去重 → 输出处理后文本与统计

          3. 去重:精确去重能挡住什么、挡不住什么

          • 概念:精确去重(Exact Deduplication)对标准化后的文本计算 SHA-256 摘要,凡摘要已出现过的样本一律丢弃。它的判定标准是「逐字节相同」,与「意思相近」无关。
          • 为什么需要:网络语料是「一份内容被转载千次」的重灾区,重复文本会诱发逐字背诵。GPT-3 团队在清洗 Common Crawl 时就做了文档级模糊去重,平均删除约 10% 的数据,目的正是防止冗余、并保护留出验证集衡量过拟合的真实性。去重研究进一步表明:去重后的模型输出背诵文本的频率可降低约十倍,且用更少的训练步数即可达到同等或更好效果。
          • 作用:对 Mini GPT 这类规模的教学语料,精确去重成本低、结果完全确定,能干净地消灭「同一段文字出现两次」这种最常见的重复。
          • 局限:SHA-256 对单个字符的变化都会产生完全不同的摘要,因此它无法识别「只改了标点」「删了几句」「换一种说法」的近重复(near-duplicate)段落。近重复检测需要 n-gram、MinHash 或语义相似度等额外方法,并配合人工核查。本教程先实现精确去重,但报告里必须写明这一局限。
          • 为什么必须在切分前去重:去重必须横跨 train 与 valid/test 的边界——同一文档若同时进入训练集与验证集,模型是在「记题」而不是「学会」,验证分数会被虚高。下一章(04)才做切分,所以本章先把重复清干净,这是顺序上的硬约束。

          4. 动手:最小清洗流程

          本教程把 Gutenberg 文本按空行拆成段落,并把每段压成一行;因此下一章可以把「一行」看作一个完整样本。不要照抄规则后就认为它适合所有语料:长度阈值、要删除的控制字符和文档边界,必须由你对数据的抽样检查决定。

          在 src/clean_data.py 创建下列完整文件。务必检查编辑器没有把反斜杠或缩进改掉:

          from collections import Counter
from hashlib import sha256
from pathlib import Path
import re

RAW_PATH = Path("data/raw/alice.txt")
OUTPUT_PATH = Path("data/processed/documents.txt")

def normalise(text: str) -> str:
    text = text.replace("\ufeff", "").replace("\r\n", "\n").replace("\r", "\n")
    text = re.sub(r"[\x00-\x08\x0b\x0c\x0e-\x1f]", "", text)
    return re.sub(r"\s+", " ", text).strip()

raw_text = RAW_PATH.read_text(encoding="utf-8")
start = raw_text.find("*** START OF THE PROJECT GUTENBERG")
end = raw_text.find("*** END OF THE PROJECT GUTENBERG")
if start == -1 or end == -1:
    raise ValueError("没有找到 Gutenberg 边界；先检查 data/raw/alice.txt 是否下载正确")
body = raw_text[start:end]

seen: set[str] = set()
kept: list[str] = []
counts: Counter[str] = Counter()
for raw in re.split(r"\n\s*\n", body):
    counts["input_paragraphs"] += 1
    text = normalise(raw)
    if not (20 <= len(text) <= 2_000):
        counts["length_filtered"] += 1
        continue
    fingerprint = sha256(text.encode("utf-8")).hexdigest()
    if fingerprint in seen:
        counts["exact_duplicates"] += 1
        continue
    seen.add(fingerprint)
    kept.append(text)

OUTPUT_PATH.parent.mkdir(parents=True, exist_ok=True)
OUTPUT_PATH.write_text("\n".join(kept) + "\n", encoding="utf-8")
print(dict(counts), {"kept": len(kept), "output": str(OUTPUT_PATH)})

          python src/clean_data.py
python -c "from pathlib import Path; rows=Path('data/processed/documents.txt').read_text(encoding='utf-8').splitlines(); print('paragraphs=', len(rows)); print(rows[:3])"
          bash

          预期看到 kept 大于 100,且前三条是正常英文段落。若 kept=0,先查看原文件的开头和 START 标记,不要放宽长度阈值来掩盖下载错误。若你换用自己的多行文档,不能将每一行错误地当作独立样本;应先识别真实的文档分隔符,再将「一个文档」的完整文本传给清洗函数。

          动手活动:清洗并审计语料

          目标:产生 data/processed/train.txt 和 reports/data-cleaning.md。

          步骤:编写 src/clean_data.py,固定 UTF-8 读取、换行标准化、空白行过滤、最小/最大长度过滤和精确去重;输出原始字符数、保留字符数、删除样本数、重复率;随机抽取 20 条清洗前后样本对照。

          完成标准:脚本可重复运行且输出相同结果;报告能说明删除了什么、删除多少、为什么删除。

          5. 常见错误

          • 在训练和测试之间去重之前先切分,导致相似文本泄漏;
          • 过度清洗,删除标点、大小写或格式后损失语言信号;
          • 只看统计数字,不进行人工抽样;
          • 将含个人信息或机密信息的文本「匿名化后默认安全」。

          6. 用报告证明清洗没有毁掉数据

          每次清洗都保留输入输出计数、规则版本和随机样本。至少审查三类样本:被保留的普通文本、被长度规则删掉的文本、被判为重复的文本。报告中的「随机」应记录 seed,且抽样结果不要被人工替换成漂亮案例。

          指标 计算方式 异常信号
          保留率 保留文档数 / 输入文档数 过低时检查规则是否误伤
          精确重复率 重复文档数 / 输入文档数 过高时追查数据源拼接
          长度分位数 文档字符数的 P50/P95 突然变化表示解析可能有误
          字符抽样 decode 后人工阅读 乱码、HTML、隐私数据残留

          7. 总结

          高质量数据管道应具备五项特征:

          特征 含义
          原始数据保留 raw/ 只读,永不手工修改
          规则脚本化 每个清洗步骤都有可重复运行的代码
          版本可追溯 规则版本与语料版本一一对应
          统计可解释 删了什么、删了多少、为什么删都有记录
          人工抽样 抽样人工阅读,不只相信数字

          思考题:为什么应在数据切分前做跨文档去重?为何 SHA-256 相同只能证明「精确重复」而不能找出改写文本?

          参考答案

          同一文档若同时进入 train 与 valid/test,验证分数会虚高,模型在「记题」而非「学会」,评测因此失真。SHA-256 对一个字符的变化都会产生完全不同的值,因此摘要相同只能证明文本逐字节相同;改写文本的检测需要 n-gram、MinHash 或语义相似度等近重复方法,并配合人工核查。
