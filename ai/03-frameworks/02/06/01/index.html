          RAG 框架选型矩阵 概览

          前面五组内容已经把 03.02 RAG and Retrieval Frameworks 的五条主路线拆开了：LlamaIndex 代表文档对象与查询对象路线，Haystack 代表显式检索工作流路线，RAGFlow 代表端到端 context engine / 平台路线，LightRAG 代表轻量 graph-enhanced retrieval 路线，Pathway 代表实时数据流与增量更新路线。[41][42][43][44][45] 到这一步，真正值钱的问题已经不是“这些框架分别是什么”，而是：当一个系统要做 RAG，你怎么判断它最先会死在哪一类 retrieval complexity 上？ 本模块就是把前五条路线收口成一张面向开发者和架构师的选型矩阵。

          学习目标：学完本模块，你将能够——

          1. 用一张表比较五类 retrieval framework 的设计中心、强项、代价与盲区；
          2. 区分对象复杂度、管道复杂度、平台复杂度、图检索复杂度、实时流复杂度；
          3. 用数据形态、更新频率、查询形态、治理要求、团队能力五个维度做框架判断；
          4. 识别四类常见错配：把静态知识库当流系统、把复杂工作流当单索引、把图检索当默认答案、把平台当库；
          5. 为一个课程助教或企业知识系统写出 retrieval framework 选型卡。

          本目录计划关注：

          1. 选型方法论：先诊断主矛盾，再用排除法筛选，而不是直接比“谁更强”；
          2. 五个框架横向矩阵：第一性差异、数据形态、查询形态、治理运营、反向排除信号；
          3. 五类典型业务场景对比，以及四类常见错配；
          4. 课程助教系统的完整 retrieval framework 选型卡。
