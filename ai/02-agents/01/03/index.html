          为什么是现在：三个条件同时到位

          2018 年前后，自动根因分析是运维领域的热门方向。主流做法是规则引擎加统计模型：把告警、指标和人工维护的服务依赖图喂进去，按阈值与拓扑关系推断根因。这条路线普遍卡在同一处——需要覆盖的故障形态太多，规则库的维护成本随系统规模线性上升。

          当时也有人试过让模型来读日志。但 2018 年可用的模型不是今天这种东西：以 BERT 为代表的一代模型擅长分类与抽取，上下文只有 512 个 token，不按指令规划动作，也没有任何工具调用协议。让它读完日志自己决定调用哪个诊断脚本，做不到——缺的是三样基础设施，靠工程技巧补不上。

          到 2023 年前后，同样的事情变成几天的工作量。这一节要解释的就是这个差别：三个条件在那个时间窗口里同时到位，而模型本身没有突变。

          三代 Agent，差别在大脑从哪里来

          Agent 不是 2023 年的发明。理解这一点的意义在于：每次“Agent 热”背后都是底层能力的换代，而换代改变的永远是同一件事——造一个 Agent 的边际成本。

          第一代是符号主义的经典 Agent。SOAR（1987）用产生式规则模拟通用问题求解，BDI（1995）用信念—愿望—意图模型刻画理性行动。这一代把“规划”研究得相当透彻，其形式化程度至今仍被引用。它的困境在于知识获取：每条规则都要由人写出，换一个领域就要重写一套知识库。工程上表现为一个熟悉的曲线——前期效果提升很快，随后人力投入与收益完全脱钩。

          第二代是强化学习 Agent。AlphaGo（2016）不需要人教围棋规则，通过与自己对弈学出策略，其能力远超任何手写规则的方案。但它把“一个任务一个训练”推到了极致：每项技能都需要独立的仿真环境、独立的奖励设计、独立的训练过程。AlphaGo 不会下象棋，这正是这一代方法的定义方式。

          第三代是 LLM Agent。语言模型本身成为通用决策器：ReAct（2022 年 10 月）证明把推理与行动交织起来可以显著提升多步任务的成功率；ChatGPT（2022 年 11 月）把这种推理能力送到公众面前；AutoGPT 与 BabyAGI（2023 年 3 至 4 月）演示了“给定目标、自主拆解、反复调用工具”的成品形态。

          三代的区别不在于“谁更像智能体”，而在于大脑的来源：手写规则、单任务训练、通用预训练。每换一代，构造一个新 Agent 的成本下降一个数量级——第一代以月计，第二代以周计，第三代以小时计。这才是“热”的经济学基础。

          能想、能做、能记

          把上面那段历史翻译成工程语言：让 LLM Agent 成立需要三块并行的能力，而它们在 2023 年前后集中到位。

          第一块是通用推理：模型能不能想。 没有它，规划只能由人预先写死，系统就退回经典 Agent 的知识获取瓶颈。GPT-3（2020）起，少样本学习与思维链（chain-of-thought）能力开始稳定出现，意味着同一个模型可以在没有专门训练的情况下拆解一个陌生任务。这是此前所有方法都缺的那一块：通用性。

          第二块是工具调用协议：模型能不能做。 2023 年 6 月 13 日，OpenAI 在 API 中加入 function calling，模型可以直接按 JSON schema 输出“调用哪个函数、参数是什么”。在此之前，所有 Agent 项目都必须靠提示词约定格式、再用正则或容错解析器去猜模型想调什么——这套做法在生产环境中的失败率高得无法接受。协议的出现把工具调用从工程技巧变成模型能力，这是产品化的前提。

          第三块是上下文窗口：模型能不能记。 2020 年 GPT-3 的窗口约为 2K token，2023 年 6 月到 16K，2023 年 11 月 GPT-4 Turbo 到 128K，2024 年 Claude 3 到 200K、Gemini 1.5 到 1M。窗口的意义不在于“能读长文档”，而在于多步任务中中间状态能否留在上下文里。窗口装不下 system 规则、历史动作和工具返回，循环在第三步就会失忆，后续决策全部建立在残缺信息上。

          三块能力对应三种失效模式：没有推理，Agent 只会执行预定步骤；没有工具协议，Agent 接不上任何真实系统；没有足够窗口，Agent 记不住自己做过什么。任缺其一，系统都只能停留在演示阶段。

          时间线上的两个放大器

          三个条件解释“能不能做”，但不解释“为什么是 2023 年而不是 2022 年或 2024 年”。另外两个因素决定了它何时被看见、何时做得起。

          触达。 ChatGPT 上线两个月用户破亿，把“模型会推理”从论文结论变成公共常识。需求端——产品团队、资本、开发者——在同一时间被激活，这解释了 2023 年春天为什么会在数周内涌现出大量 Agent 项目。

          成本。 同期 API 价格下降了一个数量级。这一点常被忽略：Agent 的调用次数是普通对话的十到几十倍，一个多步任务可能消耗几十次模型调用。在 2022 年的价格下，AutoGPT 这类产品跑一次的成本足以让任何团队放弃。价格曲线下降，才让“多烧几次调用”成为可接受的工程选择。

          所以准确的说法是：Agent 在 2023 年变得可负担。 能力、需求、价格三条曲线在同一年交汇。

          与经典 Agent 的本质差异

          用一句话概括：经典 Agent 的智能写在程序里，LLM Agent 的智能写在语言里。

          这个差别在工程上表现为四件事。规划从“手写状态机”变成“自然语言推理”；知识从“专家逐条编码”变成“预训练语料中的世界知识”；换领域的成本从“重写规则库”降到“改一段提示、换几个工具”；工具接入从“深度定制、与推理逻辑耦合”变成“声明式注册”。

          代价同样明确。经典 Agent 的行为在规则范围内是可预期的，规则之外直接报错；LLM Agent 的行为在大多数情况下合理，但存在幻觉、跑偏与不确定性，而且这些失败不会以报错的形式出现——它会以一个看起来完成的答案出现。这是后面几节反复要处理的问题。

          这里也解释了第 2.4 节要讲的自主度：经典 Agent 的高自主建立在“规则完备”的假设上，LLM Agent 的高自主建立在“语言理解”的假设上。前者害怕规则未覆盖的情况，后者害怕理解偏差。

          热度不是能力

          把热度当成能力。 2023 年的演示项目极多，但幻觉、不可控、成本失控是同一批模型带来的新失效模式。三个条件解决的是“能不能运转”，不解决“运转结果是否可信”。

          认为经典 Agent 已经过时。 在确定性、可审计、需要追责的场景——风控规则、审批流、计费——状态机比自然语言可靠得多。真正成熟的做法往往是把两者混合：确定的流程用代码固定，判断点交给模型。

          假设条件齐备就等于成功。 三个条件是必要条件。护栏、评测、人工确认点仍然要做，第 2.4 节与第 2.6 节分别讨论。

          这件事在 2020 年为什么没人做成

          遇到一个“用 Agent 做 X”的提案时，我会问一个问题：这件事在 2020 年为什么没人做成？

          如果答不出缺哪个条件，通常意味着需求本身不成立：这件事多半不需要自主决策。如果答得出，就继续问第二层：那个条件今天是否真的到货，它带来的新风险（幻觉、成本、权限）是否已被处理。这个方法能把“我们也要做一个 Agent”的冲动，转化为对具体缺口的判断。

          三个条件解释了时机，但没有解释结构。真正的工程问题从下一节开始：一个能运转的 Agent 内部由什么组成，每个部分失效时会发生什么。
