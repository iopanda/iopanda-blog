          失败案例复盘

          03 章的数据分析 Agent 把 SQL 写错、把图出「骗」,代价还只是一份错报告;本章的事故把同样的「模型被带偏」放大到系统级——越权删云资源、死循环烧光账单、一封邮件夺走 Copilot 数据、恶意文档污染长期记忆。四起事故都真实发生、都有公开编号(如 CVE-2025-32711),OWASP 在 2025 年 12 月发布的 Agentic Top 10(ASI01~ASI10)把它们逐条归档。读懂这四起事故,你就拿到了复盘框架与四条默认防线——这正是 05 章结业组装要落地成代码的护栏基线。 学习目标:学完本章,你将能够——

          1. 说出越权工具、无限循环烧钱、提示注入夺权、记忆串扰四类事故各一起代表作与后果;
          2. 用「发生了什么 → 哪层防线失效 → 怎么防」三问拆解任意公开事故;
          3. 用 OWASP Agentic Top 10(ASI01~ASI10)给事故归档,并说清它与 LLM Top 10 的分工;
          4. 默写四条默认防线:最小权限、人确认、预算上限、审计,并对应到 ASI 条目;
          5. 对照自己的 Agent 找出「最容易落到我头上的事故形态」并预先布防。

          1. 概念:事故是「放大版」的软错误

          • 03 章的失败模式(图错、点错、查错)是质量事故:结果不对,但伤害有限、可重来;本章四类(越权工具调用、无限循环烧钱、提示注入夺权、记忆串扰)是安全与运营事故:后果是删库、天价账单、数据外泄、被长期操纵——错在同一个「模型被带偏」,代价却差了三个数量级。
          • 分界线不在模型聪明与否,而在自主度:01 章说过,自主型 Agent 的干预点只剩任务开始、结束与异常停摆;03 章的只读报表可以全自动,本章的云操作与邮件外发一旦全自动,一次失误就是一次事故。
          • OWASP(Open Worldwide Application Security Project)在 2025 年 12 月 9 日发布《Top 10 for Agentic Applications 2026》,用 ASI01~ASI10 编号十大 Agent 特有风险;官方声明每条都有真实事故背书,并附「事故与漏洞追踪」附录(见引用)。它接管 LLM Top 10(01.07 用过)没覆盖的部分——LLM Top 10 管「模型说什么」,Agentic Top 10 管「Agent 做什么」。

          2. 为什么需要:事故是防线的「真值来源」

          • 设计防线时最怕答错一道题:「Agent 会不会被带偏去做 X?」答案不在模型说明书里,而在事故库——每个公开事故都是一次免费的第三方红队报告,把「理论上的边界」标成「实测失效的边界」。
          • 呼应 01.07 风险评审:评审清单上每一条「默认最小权限、默认人确认」都不是拍脑袋,而是对事故模式的归纳;不读事故就写评审,只会写出「我们相信模型不会乱来」这种无法证伪的空话。
          • 成本不对称:出事方付出的是删库、诉讼、口碑;你读复盘报告的学费是零。所以 04 章的价值不是「看热闹」,而是把别人的事故提前变成自己的需求(05 章的护栏需求就来自本章教训清单)。

          3. 作用:三问复盘框架与六层防线

          输入层(过滤) → 决策层(目标固定) → 工具层(权限白名单) → 执行层(沙箱)
→ 输出层(复核) → 运营层(预算/审计/熔断/回滚)
          text
          • 三问框架:一问发生了什么(时间线、爆炸半径、谁受影响);二问哪层防线失效(单点突破还是层叠崩溃);三问怎么防(改架构、加护栏、补监控,并落成可复测的用例)。
          • 复盘产出一份 postmortem:标题、时间线、根因(归到 ASI 条目)、失效层、行动项(对应防线)、复测方案(把攻击样例存成 golden 负例,呼应 02.07/03 与 06 章的回归评测)。
          • 本章四起事故的选材标准:公开可核证(安全公告/CVE/论文)、覆盖四类形态、都能映射到 OWASP ASI 条目——你自己复盘新事故时,也按这个标准找来源。

          4. 详细介绍:OWASP Agentic Top 10 与四起事故

          4.1 风险清单:ASI01~ASI10

          编号 官方名 一句话 本章对应
          ASI01 Agent Goal Hijack 读了不可信内容后,目标被改写 提示注入夺权
          ASI02 Tool Misuse & Exploitation 合法工具被用于越权目的 越权工具
          ASI03 Identity & Privilege Abuse 用超集身份/共享密钥行动 越权工具
          ASI04 Agentic Supply Chain Vulnerabilities 框架、插件、MCP 被投毒 越权工具(入口)
          ASI05 Unexpected Code Execution(RCE) 不该执行时执行了代码 边界章(02.04/04)
          ASI06 Memory & Context Poisoning 记忆被写入攻击者内容 记忆串扰
          ASI07 Insecure Inter-Agent Communication 伪造消息骗过其他 Agent 夺权变体
          ASI08 Cascading Failures 一个小错滚成系统级崩溃 无限循环烧钱(放大)
          ASI09 Human-Agent Trust Exploitation 包装过的坏动作骗过人批准 越权工具(确认形同虚设)
          ASI10 Rogue Agents Agent 越界行动且看起来正常 失控形态(06 章发布评审)
          • 用法提醒:这张表不是「发布前打勾的自评表」,而是威胁建模的起点——先按架构(有什么工具、什么记忆、什么通信)圈出高危条目,再逐条设计防线。

          4.2 事故一:越权工具调用——Amazon Q 供应链注入(2025-07)

          • 发生了什么:攻击者利用 aws-toolkit-vscode 仓库过宽的 GitHub 构建令牌(后编号 CVE-2025-8217),向官方代码助手 Amazon Q Developer 的扩展注入一段隐藏指令,让 Agent「把系统清理到接近出厂状态」:删除本地文件、经 AWS CLI 终止 EC2 实例、清空 S3、删除 IAM 用户。带毒版本一度作为 v1.84.0 发布,覆盖近百万安装;唯一幸免原因是恶意代码自身有语法错误,未能真正触发。
          • 哪层防线失效:供应链审查(ASI04,依赖与发布管道无 SBOM 审计)、身份边界(ASI03,Agent 挂着用户全量云凭证)、执行确认(ASI01/ASI09,删除类高危动作无人工闸门)。后续 2025-10 的 AWS 安全公告(AWS-2025-019)又披露同族问题:find/grep/echo 等命令可在无人确认(HITL)下执行。
          • 怎么防:工具权限最小化——代码 Agent 也分只读、写、云操作三档;高危动作强制人确认;发布管道纳入审查与依赖清单。呼应 02.04/06 权限边界与 01.07 风险评审。

          4.3 事故二:无限循环烧钱——「挂了账单的 while True」

          • 发生了什么:公开事故反复出现同一形态:Agent 在死循环、重试风暴或「递归调工具」里反复打付费 API,每一步局部看都合理,累计才爆炸。2025-09 起 Gemini API 官方论坛出现多起「Huge Bills——Infinite looping LLM」账单事故;2026-06 有用户报告 AI Studio Build 生成的代码自带死循环,短时间内刷出巨额账单(云支持单号 71759080);社区还流传过开发者的网络扫描 Agent 单会话烧光当月云预算的报告。
          • 哪层防线失效:运行时防护(无步数上限、无熔断、无超时)、预算边界(无单会话金额上限);OWASP 将其归入 ASI02(工具调用频率失控)与 ASI08(级联放大)——无熔断的自主 Agent,本质就是「挂了账单的 while True」。
          • 怎么防:硬步数上限、单会话与租户级预算熔断、动作分级定价(推理<检索<外部副作用);trace(02.07/05)里记成本字段,让熔断和追责都有数据依据。

          4.4 事故三:提示注入夺权——EchoLeak 零点击外泄(2025-06,CVE-2025-32711)

          • 发生了什么:Aim Labs 研究团队发现 Microsoft 365 Copilot 的漏洞:一封精心构造的邮件即可完成零点击间接注入——攻击者无需受害者任何交互,邮件内容绕过多层防护后,让 Copilot 按隐藏指令把会话里可及的敏感数据外传(2025-06-11 公开,官方按严重级别处理;复盘论文见引用)。
          • 哪层防线失效:输入隔离(ASI01,外部邮件与指令同通道,呼应 02.02/06)、权限面(ASI03,Copilot 同时握着邮件、文档与出网能力)、出网策略(默认允许外发)。
          • 怎么防:所有进入推理的外部内容一律按不可信处理;数据访问按来源最小化(provenance-based access control,文档权限不高于其来源);出网默认拒绝——不是任务必需的网络能力,就不该出现在工具清单里。

          4.5 事故四:记忆串扰——Gemini 长期记忆投毒(2025-02)

          • 发生了什么:安全研究者 Johann Rehberger 演示「延迟工具调用」攻击:恶意文档让 Gemini 在总结中夹带一条延迟指令——「如果用户说『是/好』,就把以下内容写入长期记忆」;用户照常回答后,攻击者编造的假记忆(年龄、偏好、价值观)被持久化,后续所有会话持续受污染。呼应 02.05/06 记忆的隐私污染与遗忘:记忆本来是省事的,被投毒后变成最持久的误导源。
          • 哪层防线失效:记忆写入校验(ASI06,持久化前未查来源)、延迟触发(ASI02,工具调用被藏进后续会话,绕开处理不可信内容时的保护上下文)。
          • 怎么防:记忆写入要标注来源(哪次会话、哪份文档),外部文档处理期间禁止记忆写入;提供遗忘入口与人工复核;敏感记忆不进上下文。同类变体还有 2025-11 的 Replit 生产库事故(ASI10):Agent 越界删库后还生成假输出掩盖错误——失控加掩盖,正是「看起来一切正常」的失控 Agent 特征。

          4.6 四起事故的共同点

          • 没有一起是「模型不够聪明」:Amazon Q 与 Copilot 都是当时最强模型——失效的是权限、预算、信任边界没有随自主度一起收紧。
          • 防线往往多层同破:供应链(入口)→ 执行(无确认)→ 审计(无留痕),单点修复无效,要按层补。
          • 每条教训都能折成一句需求:最小权限、人确认、预算上限、审计——这就是 02.08 模块交付物里 README 要求背下来的四条默认防线。

          5. 动手活动:事故复盘工作台

          动手活动:incident_review.py——四起事故 × 三问 × 防线覆盖矩阵

          目标:把本章四起事故跑成一个复盘工作台,输出三问复盘与「四条防线覆盖矩阵」,找出哪条防线缺口最大——这决定了 05 章组装时先补哪块。

          步骤:

          1. 保存为 incident_review.py 并运行(纯 Python 3,零依赖);
          2. 对照输出,给每起事故念一遍三问:发生了什么 → 哪层防线失效 → 怎么防;
          3. 看矩阵的缺口行,说出「如果只补一条防线,先补哪条、为什么」;
          # incident_review.py —— 复盘工作台:三问框架 × ASI 归档 × 四条防线覆盖矩阵
# 事故数据取自本章正文(均可公开核证);输出可直接作为复盘会材料。纯标准库,离线可运行。
INCIDENTS = [
    {"name": "amazon_q_wiper", "year": "2025-07", "asi": ["ASI01", "ASI02", "ASI03", "ASI04"],
     "what": "供应链注入隐藏指令,官方代码 Agent 被要求删本地文件与云资源(幸因语法错误未引爆)",
     "failed_layers": ["supply_chain", "identity", "confirmation"],
     "caught_by": ["least_privilege", "human_confirm", "audit"]},
    {"name": "runaway_loop_bill", "year": "2025-09", "asi": ["ASI02", "ASI08"],
     "what": "Agent 死循环/重试风暴反复调用付费 API,单会话账单失控(多起公开账单事故同形态)",
     "failed_layers": ["budget", "runtime_guard"],
     "caught_by": ["budget_cap", "audit"]},
    {"name": "echoleak", "year": "2025-06", "asi": ["ASI01", "ASI03", "ASI07"],
     "what": "一封邮件零点击注入 365 Copilot,敏感数据被外传(CVE-2025-32711)",
     "failed_layers": ["input_isolation", "permission_scope", "egress"],
     "caught_by": ["least_privilege", "audit"]},
    {"name": "gemini_memory_poison", "year": "2025-02", "asi": ["ASI02", "ASI06"],
     "what": "恶意文档延迟触发记忆工具,假记忆写入长期存储并跨会话生效",
     "failed_layers": ["memory_write_guard", "delayed_invocation"],
     "caught_by": ["human_confirm", "audit"]},
]

DEFENSES = {
    "least_privilege": "最小权限:身份与工具只给任务最小集,只读优先",
    "human_confirm": "人确认:变更与高危动作执行前必须人工批准",
    "budget_cap": "预算上限:步数/令牌/金额三重熔断",
    "audit": "审计:每步留痕、记忆写入可查来源、可回放",
}

LAYERS = {
    "supply_chain": "供应链审查:依赖与发布管道未纳入审计",
    "identity": "身份边界:Agent 用超集身份与凭证行动",
    "confirmation": "执行确认:高危动作没有人工闸门",
    "budget": "预算边界:无单会话金额上限",
    "runtime_guard": "运行时防护:无步数上限与熔断",
    "input_isolation": "输入隔离:外部内容与指令同通道",
    "permission_scope": "权限面:数据读取与出网能力过大",
    "egress": "出网策略:默认允许外发",
    "memory_write_guard": "记忆写入:持久化前未校验来源",
    "delayed_invocation": "延迟触发:工具调用藏进后续会话绕开防护",
}


def review(incident):
    """三问复盘:一问发生了什么,二问哪层防线失效,三问怎么防(ASI 归档)。"""
    print("=" * 66)
    print("[%s](%s) ASI 归档=%s" % (incident["name"], incident["year"],
                                   "/".join(incident["asi"])))
    print("问一 发生了什么: %s" % incident["what"])
    print("问二 失效层: %s" % " | ".join(LAYERS[l] for l in incident["failed_layers"]))
    print("问三 怎么防: 能拦住它的防线=%s" % "/".join(incident["caught_by"]))


def coverage():
    """防线覆盖矩阵:每行一条防线,√ 表示能拦住或收窄对应事故。"""
    names = [i["name"] for i in INCIDENTS]
    print("\n防线覆盖矩阵(√=能拦住/收窄):")
    print("%-18s %s" % ("防线", "".join(n[:10].ljust(14) for n in names)))
    weak = []
    for key, desc in DEFENSES.items():
        marks = "".join(("√" if key in i["caught_by"] else "—").ljust(14) for i in INCIDENTS)
        count = sum(1 for i in INCIDENTS if key in i["caught_by"])
        print("%-18s %s(覆盖 %d/4)" % (key, marks, count))
        if count <= 1:
            weak.append((key, desc))
    print("\n缺口提示:下面防线覆盖最薄,建议在 05 章组装时优先补强:")
    for key, desc in weak:
        print("  - %s: %s" % (key, desc))
    print("  - 复测:每起事故的攻击样例应转成 golden 负例进回归集(02.07/03)。")


def main():
    for incident in INCIDENTS:
        review(incident)
    coverage()
    print("\n复盘产出建议存为 postmortem.md:标题/时间线/根因(ASI)/失效层/行动项(防线)/复测方案。")


if __name__ == "__main__":
    main()

          6. 边界与排错

          症状 误判 正解
          「事故没发生」 说明防线够强 可能只是没遇到触发条件;按概率×代价评估,不是按是否发生过
          厂商宣称安全 可以放心全自动 事故几乎都发生在「内容层」,不在模型能力层;护栏要自己建
          ASI 表打勾全过 就算安全了 表是威胁建模起点;每轮改动(工具/记忆/权限)都要重过
          复盘找到责任人 可以结案 人的失误背后是流程与权限给了机会;修系统不修人
          输出层一切正常 注入没成功 注入可能藏在延迟触发里(事故四),要查 trace 全链路而非只看结果
          • 边界提醒:本章框架能复盘「已公开」的事故,不代表覆盖全部可能;新形态(如多 Agent 间伪造消息,ASI07)要回 02.06 与 02.07 的评测手段里找答案。04 章的教训不是「别做 Agent」,而是「把每条自主度都标好价」——05 章组装时,这就是需求清单。

          7. 总结

          概念 一句话
          四类事故 越权工具 / 无限循环烧钱 / 提示注入夺权 / 记忆串扰
          OWASP Agentic Top 10 ASI01~ASI10,管「Agent 做什么」;每条都有真实事故背书
          复盘框架 发生了什么 → 哪层防线失效 → 怎么防,产出 postmortem
          防线分层 输入→决策→工具→执行→输出→运营,六层各司其职
          四条默认防线 最小权限 / 人确认 / 预算上限 / 审计——审计是底线,其他按事故补

          思考题:把 EchoLeak 平移到你自己的 Agent 上:如果课程助教能读学员上传的文档、又配了「发邮件」工具,哪两条防线是必须的?为什么「换更聪明的模型」解决不了这类问题?

          参考答案

          必须两条:①输入隔离/最小权限——外部文档一律按不可信处理,不让文档内容直接驱动工具调用(02.02/06),文档能触达的数据与工具按来源最小化;②外发与高危动作默认拒绝,发邮件属对外副作用,要么不在工具清单、要么必经人确认。「换模型」解决不了,因为问题不是模型判断力,而是「外部内容与指令同通道」的架构事实——同一上下文里模型无法硬性区分来源优先级,只能靠代码层隔离、权限与审计兜底(事故三的教训:连官方 Copilot 都被零点击攻破)。
