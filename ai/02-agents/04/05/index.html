          沙箱划得住什么

          一个数据分析 Agent 被要求“把上学期各章的平均分导出来，画个趋势”。

          它写了一段 pandas 代码。第一次运行报错：文件路径不对。于是它加了调试代码，打印当前目录和上一级目录的列表。看到了 config/，又读了一个看起来像配置的 yaml，因为“可能是数据源声明”。

          最后报告里出现了数据库连接串——它在整理“数据来源说明”时，把读到的那段原文贴了进去。

          整个过程中没有任何攻击者。模型只是在调试，只是“顺手多读了一点”，只是把中间结果当成材料写进了交付物。代码执行工具的危险，主要来自这种无恶意的过度探索。

          这个工具与其他工具的根本差别

          普通工具的行为是你写定的：get_chapter_stats 做什么，代码里有确定答案。

          代码执行工具的行为由模型现场生成。你无法事先枚举它能做什么，因为它是图灵完备的——今天它读 CSV，明天它启动一个子进程，后天它发起一次 HTTP 请求。这是形态上的差别，靠配置补不回来。

          所以防护思路也要换。前三类工具靠“限制能做什么”，这一类只能靠“限制能做到哪一步之后没有后果”。

          五道控制

          文件系统。 只读挂载必要数据，一个可写的临时目录，宿主机路径一律不出现。上面那个事故的根因就在这里：.. 可达，配置就在 .. 里。

          网络。 默认关闭。需要联网查资料时，走域名白名单，并且把请求记录下来。默认开启的网络，等于给注入攻击一条出口。

          资源。 CPU、内存、进程数、运行时长四项都设上限。默认值可以这样起步：1 核、512MB、30 秒、128 个进程。跑不动时宁可让模型换写法，也不要放开限制。

          身份。 非 root 运行，容器内不注入任何密钥。这条最容易被忽略，也最致命：密钥一旦在环境变量里，模型一句 os.environ 就能读到，然后写进回答。

          输出。 标准输出截断、堆栈信息过滤、文件路径替换成占位符。堆栈里带主机名和绝对路径，进上下文就收不回来。

          控制 默认 放开条件
          文件系统 只读 + 单个临时目录 按需挂载具体目录
          网络 关闭 域名白名单 + 日志
          资源 1 核 / 512MB / 30s 按任务类型分档
          身份 非 root、无密钥 永不放开
          输出 截断 + 脱敏 永不放开

          隔离级别

          四种做法，防护强度依次上升。

          子进程。 在应用进程里 exec 一段代码。隔离几乎为零，能读到进程的全部环境变量和文件系统。只适合单用户本地脚本。

          容器。 独立文件系统、独立网络命名空间、cgroup 限制。这是多数产品的选择，够用，但要接受共享内核。

          gVisor 之类的用户态内核。 拦截系统调用，容器逃逸的难度显著上升。代价是兼容性与性能。

          微虚拟机（Firecracker 一类）。 硬件虚拟化边界，启动时间在百毫秒级。托管平台跑不可信代码基本都用这一层。

          选择依据是一个问题：这段代码是谁写的？ 如果是你的模板加模型填参数，容器够用；如果是模型从零写、还要执行多次，微虚拟机更合适。

          有一个前提要接受：容器逃逸与内核漏洞是现实存在的。 所以真正的设计原则是“假设沙箱会被突破”——沙箱里不放密钥、不挂宿主目录、不发网络，突破了也拿不到东西。

          沙箱之外的三条

          输入也要限制。 沙箱保护的是机器，不保护你交给它的数据。把整份学生名单交给一个“做个统计”的任务，即使代码跑在微虚拟机里，结果文件里依然全是个人信息。

          结果要人看一遍。 尤其是第一次上线新工具时。上面那份报告里出现连接串，任何一个人扫一眼都能发现，而自动化检查不会。

          同类任务要能复现。 模型每次写的代码不同，同一次任务两次运行可能给出不同结果。把生成的代码存下来，附在结果旁边，是唯一能让结果可复核的办法。

          它挡不住的部分

          结果错误。 沙箱保证代码跑不出边界，不保证跑出正确结果。模型写的聚合逻辑错了一行，沙箱照样让它跑完。

          合法出口的数据外泄。 允许联网时，白名单内的域名依然可以被用来传数据——把内容拼进 URL 参数就行。真正的限制是“不要把敏感数据交给可联网的执行器”。

          多租户串扰。 共享的临时目录、共享的包缓存，都可能成为跨用户的信息通道。每个执行实例一个独立目录，是最低要求。

          下一步：把工具变成可插拔的

          到这里，工具是你自己写的、自己验的。现实里越来越多的工具来自第三方——别人写好的 server，你只需要接上。

          下一节讲 MCP，它把接入成本降到了很低，也把“这个工具是谁写的”变成了一个必须回答的问题。
