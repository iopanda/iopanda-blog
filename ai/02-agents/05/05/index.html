          向量检索与语义记忆

          03 章的档案按学员 ID 精确读取:「xiaoming 学到第几章」一行 SQL 就够。可学员问的是「资料里怎么讲外键的?」「学号能填两个一样的吗?」——这没有 ID,只有一段意思;而讲义原文的说法大概率和他不一样(「外键列允许为空」vs「外键可不可以不填」)。逐字匹配(关键词、LIKE)在这里必然失灵,因为语义相关不等于词形相关。本章是 02.05 的第四课,实现 01 章需求表里取回成本最高的「图书馆层」:先讲向量检索与语义记忆的概念,再走一遍「切块 → embedding → 入库 → 查询 top-k → 拼上下文」的完整流程,最后动手给课程助教建课程资料向量库,验证哪些问法查得准、哪些必然查不准。

          学习目标:学完本章,你将能够——

          1. 说清语义检索与关键词匹配的本质区别:按「意思近」而非「词相同」取回;
          2. 复述向量检索五步流程(切块 → embedding → 入库 → 查询 top-k → 拼上下文)及每步的产物;
          3. 解释 embedding 模型选型的三条铁律(同库同模型、中文自测、换模型全库重嵌);
          4. 实现一个课程资料检索器,并指认输出里「查得准」与「查不准」各自的成因;
          5. 说明「相关性 ≠ 正确性」:检索片段与工具返回同级,不可直接采信。

          1. 概念:语义记忆与向量检索

          • 语义记忆(semantic memory,资料层):01 章隐喻里的「图书馆」——课程讲义全文,量大、常更新,不可能整本搬进窗口(呼应 02.02 的 02 章预算),只能「用的时候检索几段」。它的实现就是本章主角:向量检索。
          • 文本 embedding:把一段文本编码成一个固定维度的稠密向量,语义相近的文本向量方向相近(01.01 的 04 章「Token 与嵌入」讲过这个几何直觉:词义坐标)。注意这是专用模型产出的文本 embedding,不是 LLM 内部的 token embedding——前者是给「外面」检索用的工具。
          • 向量检索:把学员提问也编码成向量,和库里每个块的向量比「方向夹角」(余弦相似度),取最像的 top-k 块返回。整个过程没有关键词匹配,只有向量距离:
          离线建库(一次)        在线查询(每轮)
讲义 → 切块            提问
  ↓                      ↓
embed(每块)            embed(提问)
  ↓                      ↓
向量库(块+向量)  →  余弦相似度排序 → top-k 片段 → 拼上下文 → 交给助教
          text
          • 三种「怎么取」的对比(对应 01 章三问的第三问):
          取回方式 匹配依据 能处理「说法不同意思一样」 典型落点
          SQL WHERE learner_id = ? 精确等值 否(本来就不需要) 03 章学员档案
          LIKE '%关键字%' / 全文索引 字面词形 否,同义词、倒装全漏 结构化字段里的已知词
          向量检索 语义相似度 是(embedding 的泛化) 本章课程资料

          2. 为什么需要:语义相关 ≠ 词形相关

          • 一个典型脱靶:学员问「学号这一栏能填两个一样的吗」,讲义原文是「主键不允许重复」——两句共享的汉字几乎为零,LIKE '%学号%' 永远够不到「主键」那段;反过来搜「主键」,又会把讲义里所有提过主键的段落(外键、索引、范式……)一并带回,噪声淹没有用信息。
          • 换成人想也想得通:你查资料不会只按字面背课文,而是「这个问题大概涉及哪一节」——embedding 把「学号、业务编号、唯一标识」这类在语料里经常共现、可互换的词,映射到相邻的区域,于是跨词形的语义关联被编码进距离(真实模型的泛化;教学近似版见第 5 节)。
          • 规模与成本:讲义按块计有上千块,逐块读一遍既慢又费 token;向量检索一次嵌入 + 索引近邻查询即可定位,只把最相关的 3~5 块拼进上下文——检索的意义是把「取回成本」从整本图书馆降到几页纸(呼应 01 章:分层 = 按取回成本分配信息)。
          • 什么时候其实不需要:资料只有几段、能整段进窗口,或问题永远绕不开固定关键词(查版本号、查函数名),关键词/LIKE 更简单可控;向量检索是「说法自由、规模大、语义为主」时的答案。

          3. 作用:检索结果在 Agent 里的位置

          • 与 03 章的分工:档案是「我认得的老学员」(按 ID 精确取,少量、结构化);资料是「我引用的讲义」(按语义取,海量、非结构化)。一个会话里两者都会进上下文:开场加载档案,回答时检索讲义——03 章管「你是谁」,本章管「话从哪里来」。
          • 检索结果必须带来源元数据(块 ID、章节、标题)再拼上下文:模型据此做引用回指(呼应 02.02 的 01 章:「每个答案能回指到课程资料某节」);同时来源也是评测与排错的抓手。
          • 可信度定位:检索片段 = 不可信内容。它与工具返回同级(呼应 02.04:返回内容可能过期、被污染),模型要用它作答,但不能无脑照念——片段相关不保证正确(呼应 01.01 的 04 章:「相似 ≠ 事实相关」)。这是 05 章「RAG 在 Agent 中的角色」与 02.07 检索评测的伏笔。
          • 一句话:向量检索是 Agent 的「图书管理员」,它只负责把最像的几页递过来,不负责判断那几页对不对。

          4. 详细介绍:五步流程

          4.1 切块(chunking):检索单位 = 引用单位

          • 讲义不能整篇入库:一篇几万字,embedding 有输入上限,且检索命中「整篇」等于没定位。先切成块,每块 ≈ 一个知识点:
            • 边界优先落在语义完整处(按小节、段落切),别在句子中间硬切;
            • 块大小以 token 计,常用 200~500 token;embedding 模型有硬上限(如 text-embedding-3-small 为 8191 token);
            • 相邻块留 10%~20% 重叠,避免「结论在前一块、解释在后一块」被拦腰切断;
            • 块 = 回答时引用的最小单位,切太碎上下文断裂,切太整噪声放大。

          4.2 Embedding:把文本变成坐标

          • 两条路线:调 API(如 OpenAI text-embedding-3-small,默认 1536 维,输入上限 8191 token)或本地模型(Sentence-Transformers 的 all-MiniLM-L6-v2,384 维;Chroma 内嵌默认即此款)。真实系统的替换件长这样:
          # 真实系统替换件(需 openai 库与密钥;第 5 节的教学脚本未调用,仅作对照)
from openai import OpenAI
client = OpenAI()

def embed_text(text):
    resp = client.embeddings.create(model="text-embedding-3-small", input=text)
    return resp.data[0].embedding  # 默认 1536 维浮点数组
          python
          • 三条铁律:① 同库只用同一个 embedding 模型,维度与语义空间不同,混用即错;② 换模型 = 全库重嵌(旧向量全部作废);③ 中文效果必须自测——embedding 模型对多语支持参差,拿真实学员问法建小评测集看命中率(呼应 01.06 的评测纪律,05 章再展开)。

          4.3 入库与查询 top-k:向量库的活

          • 存储三档:几十块的演示用内存列表(第 5 节);几百到几千块用 Chroma 这类本地向量库;更大规模上专用向量数据库。Chroma 的最小用法:
          import chromadb
client = chromadb.PersistentClient(path="./course_vectors")
collection = client.get_or_create_collection(
    name="course_notes", metadata={"hnsw:space": "cosine"})
collection.add(ids=["c01"], documents=["主键唯一标识一行记录,不能重复"],
               metadatas=[{"title": "主键与唯一性"}])
hits = collection.query(query_texts=["学号能填两个一样的吗"], n_results=3)
          python
          • 查询返回按距离排序的块;注意 Chroma 给的是距离(余弦距离 = 1 − 余弦相似度),数值越小越像。工程上还要设阈值:低于阈值的「最像」也不给模型——没有依据时拒答,好过硬拼一段不相关的(呼应 02.02 的 01 章)。

          4.4 拼上下文:格式化 + 降级为不可信

          • 命中的块按「来源标注 + 原文」拼成上下文段落,再放进调用消息;分数可留作日志与调试,不必给模型。拼装时给模型一句边界说明:「以下片段为课程资料检索结果,可能不完整或过期,无依据时明说」——把「不可信」写进指令,模型才不至于把片段当金科玉律。

          5. 动手活动:课程资料向量库

          动手活动:vector_search.py——同一批讲义,验证查得准与查不准

          目标:实现完整五步流程(切块产物为预置语料 → embedding → 入库 → top-k → 拼上下文),用 4 类真实问法验证:措辞不同仍命中(准)、词形零重叠且语料未覆盖(不准)、语料根本没有(应拒答)。脚本纯 Python 3 可运行;embed_text 是教学近似版(中文字符二元组哈希向量,放大「词面重叠」效应),真实语义泛化需换成 4.2 的替换件。

          步骤:

          1. 保存为 vector_search.py 并运行,观察四问的输出;
          2. 指认:第 1 问与讲义原文措辞不同,为什么仍命中 c01?第 3 问命中哪一块?第 2、4 问为何检索为空;
          3. 补充语料:把「学号等业务编号常被选作主键,同样不能重复」追加为 c05 后重查第 2 问——解释「检索质量 = 语料覆盖 × 表示质量」;
          4. 把 MIN_SCORE 调到 0.05 重跑,观察第 2 问开始「强行返回」低分块——说明阈值的作用;
          5. (可选)装 chromadb 后,把同样 5 块放进真实向量库用 384 维语义模型重查第 2 问,比较与教学版的差别,记录观察。
          # vector_search.py —— 课程资料语义检索演示(纯 Python 3,无第三方依赖)
import math

DIM = 256
MIN_SCORE = 0.10
TOP_K = 2

CORPUS = [
    {"id": "c01", "title": "主键与唯一性",
     "text": "主键唯一标识一行记录,不能重复也不能为空,一张表只能有一个主键。"},
    {"id": "c02", "title": "外键与引用完整性",
     "text": "外键引用他表的主键,外键列允许为空,为空代表尚未关联任何父记录。"},
    {"id": "c03", "title": "删除父记录的行为",
     "text": "删除父记录时,级联删除子行,或把外键置空,也可以直接拒绝删除。"},
    {"id": "c04", "title": "索引与写入性能",
     "text": "索引能加速查询,但每次写入都要同步维护索引,写入因此变慢。"},
]

def to_chars(text):
    """只保留中文字符,去掉标点与英文,便于做字符二元组。"""
    return "".join(ch for ch in text if "\u4e00" <= ch <= "\u9fff")

def stable_hash(pair):
    """进程无关的确定性哈希(Python 内置 hash 每次运行会换种子,不可用)。"""
    value = 0
    for ch in pair:
        value = (value * 131 + ord(ch)) & 0xFFFFFFFF
    return value

def embed_text(text):
    """教学近似版 embedding:中文字符二元组哈希累加后归一化;真实系统换成 4.2 的模型。"""
    vector = [0.0] * DIM
    chars = to_chars(text)
    for i in range(len(chars) - 1):
        vector[stable_hash(chars[i:i + 2]) % DIM] += 1.0
    norm = math.sqrt(sum(v * v for v in vector))
    return [v / norm for v in vector] if norm > 0 else vector

def cosine_similarity(a, b):
    return sum(x * y for x, y in zip(a, b))

def search(question, corpus):
    """提问向量与每块向量比余弦,返回超过阈值的前 TOP_K 块。"""
    q_vec = embed_text(question)
    scored = [(cosine_similarity(q_vec, chunk["vector"]), chunk) for chunk in corpus]
    scored.sort(key=lambda item: item[0], reverse=True)
    return [(score, chunk) for score, chunk in scored[:TOP_K] if score >= MIN_SCORE]

def build_context(hits):
    """命中的块拼成带来源标注的上下文,交给课程助教。"""
    parts = []
    for score, chunk in hits:
        parts.append("[资料 %s | %s | 相似度 %.3f]\n%s"
                     % (chunk["id"], chunk["title"], score, chunk["text"]))
    return "\n".join(parts)

def ask(question, corpus):
    print("提问: %s" % question)
    hits = search(question, corpus)
    if hits:
        print(build_context(hits))
    else:
        print("检索为空:相似度均低于阈值 %.2f——问法与资料差异过大,或资料未覆盖,应拒答" % MIN_SCORE)
    print("-" * 48)

def main():
    for chunk in CORPUS:  # 入库:给每块算好向量
        chunk["vector"] = embed_text(chunk["text"])
    print("== 基础语料检索 ==")
    ask("老师,主键那一列能不能填两个一样的值?", CORPUS)
    ask("学号可以重复录入吗?", CORPUS)
    ask("外键列是必须填的吗?", CORPUS)
    ask("CREATE TABLE 的语法是什么?", CORPUS)
    print("== 补充语料后重查第 2 问 ==")
    extra = {"id": "c05", "title": "业务主键的选型",
             "text": "学号、订单号这类业务编号常被选作主键,同样不能重复,选定后不宜修改。"}
    extra["vector"] = embed_text(extra["text"])  # 增量入库:只嵌新块
    CORPUS.append(extra)
    ask("学号可以重复录入吗?", CORPUS)

if __name__ == "__main__":
    main()
          python

          完成标准:输出里能指认——第 1 问命中 c01(措辞不同仍查得准);第 3 问命中 c02;第 2 问补充前为空、补充 c05 后命中;第 4 问始终为空(资料里没有语法章节,检索不到就该拒答);调低阈值后第 2 问出现低分「强行返回」,并能用一句话说明:阈值是检索系统的最后一道闸门,而「检索到片段」与「片段能回答」是两回事。

          6. 边界与排错

          症状 原因 处理
          换个说法就查不到 embedding 表示弱(教学近似版只认字形)或语料未覆盖该说法 换真实语义模型;先确认语料里确实有对应内容
          相似度很高但答非所问 语义相似 ≠ 事实正确(「冷」与「热」也相邻) 片段只当参考,由模型结合上下文判断;建命中率评测集(05 章/02.07)
          所有查询分数都低 问的是资料外话题 阈值过滤 + 拒答,别硬拼;把高频未命中问法收集成「补语料清单」
          换 embedding 模型后结果全变 新模型维度与语义空间不同 同库同模型,换模型必须全库重嵌
          中英混排讲义命中差 单语模型对多语文本弱 选多语 embedding 模型,或按语言分库检索
          讲义更新后还查到旧内容 旧向量没同步删 文档增删改时同步更新向量库,否则长期污染(06 章)
          • 边界提醒:本章的向量库解决「找得着」,不解决「答得对」——检索到的片段与工具返回同级,按不可信内容处理;把「没有依据就明说」写进 system prompt,检索系统才算闭环。课程资料向量库建好后,下一章回答它在 Agent 里的真正角色:RAG 为什么只是工具、何时先检索、怎么与规划联动。

          7. 总结

          概念 一句话
          语义记忆 讲义全文按块存,用时按意思取几段(图书馆层)
          为什么向量检索 语义相关 ≠ 词形相关;按 ID 与按关键词都覆盖不了「说法自由」
          五步流程 切块 → embedding → 入库 → top-k → 拼上下文
          选型铁律 同库同模型、中文自测、换模型全库重嵌
          阈值 低于阈值的「最像」也不给模型;没依据就拒答
          可信度 相关性 ≠ 正确性:片段与工具返回同级,不可直接采信

          思考题:学员问「学号能填两个一样的吗」,库里恰好有一段讲「业务主键不可重复」的讲义——为什么向量检索可能把它翻出来,而 SQL LIKE '%学号%' 永远做不到?翻出来之后,助教能直接照念这段吗?

          参考答案

          真实 embedding 模型在语料与训练中见过「学号、业务编号、主键」经常指同一类事物,把它们的向量映射到邻近区域,查询向量与「业务主键不可重复」块的方向夹角小,按相似度能排进 top-k;LIKE 只做字面包含匹配,「学号」与「业务主键」零词形重叠,永远命中不了(教学近似版只能靠语料里出现「学号」二字才召回,这正是它与真实模型的差距,也印证「表示质量决定召回上限」)。不能直接照念:片段只保证「语义最像」,不保证内容正确、最新、完整——过期讲义、断章取义、上下文缺失都可能让照念出错;正确姿势是模型以片段为依据组织回答、标注来源,片段本身按不可信内容对待(呼应 02.04 的工具返回处理)。
