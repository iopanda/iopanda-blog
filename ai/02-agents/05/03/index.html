          会话记忆与会话压缩

          01 章的需求表里,「跟上本会话话题」被分到便签级(情景记忆)。它的朴素实现太诱人了:把每一轮问答原文都存下来,下次调用原样塞回上下文——保真、零设计成本。可代价随轮数线性膨胀:token 账单、超窗报错、注意力稀释,02.02 的 02 章已经算过这笔账。本章是 02.05 的第二课,把「情景记忆」实现成正经组件:先讲完整历史与摘要历史的取舍,再给滑动窗口、滚动摘要、关键事实抽取三类压缩技术,最后动手实现一个「摘要 + 最近 N 轮」的会话记忆类,用同一段 25 轮对话对比三种配置的行为差异——目标是长对话不爆上下文,且不丢学员背景与承诺。

          学习目标:学完本章,你将能够——

          1. 说清会话记忆的朴素实现(消息列表全量回填)与它必然线性膨胀的原因;
          2. 对比完整历史与摘要历史的保真度、token 成本与实现代价;
          3. 解释滑动窗口、滚动摘要、关键事实抽取各自保留什么、丢掉什么;
          4. 实现一个「摘要 + 最近 N 轮」的会话记忆类,并测出三种配置的 token 占用与压缩次数;
          5. 用「关键事实召回」验收压缩质量:长对话不爆上下文,且不丢学员背景与承诺。

          1. 概念:会话记忆 = 把历史装回上下文

          • 会话记忆(conversation memory,短期记忆):让模型在「本会话内」记得前面说过什么。模型本身无状态(01 章),所以实现只有一招——应用保存消息列表,每次调用把它拼进 messages 重放:
          # 最朴素的会话记忆:每轮追加,下次调用全量重发
messages = [
    {"role": "system", "content": "你是课程助教,仅依据课程资料回答。"},
    {"role": "user", "content": "主键和外键有什么区别?"},
    {"role": "assistant", "content": "主键唯一标识本表记录;外键引用他表主键。"},
]
          python
          • 重放即记忆:模型「记得」第 1 轮,是因为第 10 轮调用时它还在 messages 里——不是模型调用了记忆中枢(呼应 02.01 的无状态模型,与 02.02 02 章「窗口 ≠ 记忆」)。增长是道算术题:每轮问答新增 2 条消息,课程助教还常夹带工具结果与检索片段(单条动辄数百 token),十几轮就能逼近 128K 窗口。所以会话记忆对象必须回答:窗口预算内,给模型看哪些历史——这就是压缩的由来。

          2. 为什么需要:完整历史的三个代价

          • 全量回填最保真,但三个代价随轮数一起恶化:
          代价 机制 后果
          token 成本 历史线性累积,每轮按输入计费 越聊越贵,账单线性爬升
          超窗风险 输入 + 输出逼近窗口上限 报错 context_length_exceeded,或被框架静默截断(通常丢最旧)
          注意力稀释 内容越长,模型对旧段的遵循越差 「第 2 轮的约定」到第 30 轮形同虚设
          • 取舍的本质:完整历史(保真、可回看、贵)vs 摘要历史(省 token、快、丢细节)。工程答案不是二选一,而是按「信息年龄」分级:最近几轮要原文——追问细节、指代「刚才那道题」都靠它;更早的轮次只需要语义——事实、结论、承诺。开会做纪要同理:没人逐字背完整场会议,只留决议与待办。
          • 什么时候触发压缩:两个信号——① 轮数超阈值(如 20 轮);② token 占用超窗口预算的 70%~80%(呼应 02.02 02 章的利用率阈值)。第 5 节的演示用「轮数」触发,保证结果可复现。

          3. 作用:压缩在会话记忆里的位置

          • 会话记忆对象的生命周期是一个循环:
          写入:每轮 add(学员提问 / 助手回答 / 工具结果)
  ↓
检查:轮数超限 或 token 超预算?
  ├─ 否 → 原样保留
  └─ 是 → 压缩:最旧轮次 → 压缩器 → 滚动摘要;原文只留最近 N 轮
  ↓
组装:render() 输出 [关键事实 + 滚动摘要 + 最近 N 轮原文]
          text
          • 与 02.02 02 章的分工:那章以「上下文窗口」为主语,讲预算分配、滑窗、纪要、前置等窗口管理策略;本章以「会话记忆对象」为主语,把「纪要 + 最近 N 轮」实现成可复用组件,并补上那章没展开的关键事实抽取。03 章再把同一思路扩展到跨会话:02 章管「会话内不忘事」,03 章管「重启后还记得」。
          • 一句类比:压缩是会话记忆的「内存换页」——原文是主存,滚动摘要是被换出的页,最近 N 轮是常驻热页;MemGPT 的分层记忆就把这个类比系统化了(见引用)。

          4. 详细介绍:三类压缩技术

          4.1 滑动窗口(sliding window)

          • 只留最近 N 轮原文,更早的直接丢弃;实现最简,一行切片。代价是硬遗忘:被滑掉的早期信息模型彻底看不到——学员第 2 轮说的「我是零基础」,第 20 轮提问时已不在场。适合对早期内容低依赖的轻会话,不适合需要长期跟踪学员背景的辅导。

          4.2 滚动摘要(rolling summary)

          • 压缩时把被丢弃轮次交给摘要器(真实系统用模型生成:「用三句话总结这段对话,保留事实、结论与承诺」),纪要置于 system 之后享受开头效应(呼应 02.02 02 章的关键信息前置),随压缩追加,自身膨胀到配额上限时做「纪要的纪要」。代价:每次压缩一次模型调用(token + 延迟);摘要会失真——概括天然丢细节,还可能只留助教结论、漏掉学员自述的「零基础」。

          4.3 关键事实抽取(key-fact extraction)

          • 与概括不同:不是「把对话讲短一点」,而是抽出结构化事实条目——学员水平、偏好、进度、待办承诺,每条独立存储、同名覆盖(学员说「其实我学过 SQL」→ 覆盖「零基础」);抽取可交给规则(命中关键词)或模型(输出 JSON),03 章会看到它进化成「学员档案」。与摘要互补:摘要是「浓缩的对话」供回顾,事实是「可更新的档案」供决策,在记忆对象里 summary 与 facts 是两条独立通道。

          4.4 三类技术对比

          技术 保留什么 丢掉什么 成本 适用
          滑动窗口 最近 N 轮原文 早期的一切 最低 轻会话,早期无长期依赖
          滚动摘要 早期语义(一段话) 细节措辞,可能失真 压缩时一次模型调用 中长会话保语义
          关键事实抽取 结构化事实条目 非事实的过程性内容 抽取调用 + 维护 schema 跟踪学员背景与承诺
          • 组合拳(本章动手实现的正是它):「摘要 + 最近 N 轮」+ 事实通道——原文保近期细节,摘要保早期语义,事实保决策依据。

          5. 动手活动:实现「摘要 + 最近 N 轮」记忆类

          动手活动:conv_memory.py——三种配置跑同一段 25 轮对话

          目标:实现 ConversationMemory 类(写入/检查/压缩/组装四件套),用同一份 25 轮辅导对话分别跑「全量历史 / 纯滑动窗口 / 摘要+最近N轮」三种配置,输出 token 占用、压缩次数与关键事实召回,验证模块验收:长对话不爆上下文,压缩不丢关键事实。

          步骤:

          1. 保存为 conv_memory.py 并运行(纯 Python 3,无第三方依赖;count_tokens 是粗略估算,真实限额以 API 的 usage.prompt_tokens 为准);
          2. 记录三种模式的最终占用、是否超预算、压缩次数,以及「零基础 / 三道题」两条关键事实(埋在第 1、2 轮)的召回结果;
          3. 解释:为什么全量模式超预算而另外两种没有?为什么滑动窗口丢了两条关键事实?
          4. 把 add 方法里的 self.extract_facts(content) 一行注释掉重跑——观察摘要模式丢掉了什么,说明关键事实抽取补的是摘要的哪个盲区;
          5. 把 keep_rounds 从 4 改成 10 重跑,观察两种压缩模式的占用与召回如何变化。
          # conv_memory.py —— 会话记忆:全量 / 滑窗 / 摘要+最近N轮(纯 Python 3,无第三方依赖)
def count_tokens(text):
    """粗略估算 token:中文字符 1 字约 1 token,其余按 4 字符约 1 token。"""
    cn = sum(1 for ch in text if "\u4e00" <= ch <= "\u9fff")
    return cn + (len(text) - cn + 3) // 4

class ConversationMemory:
    """三种模式共用同一接口;摘要模式用『助手结论入纪要』近似真实摘要器。"""
    def __init__(self, mode, keep_rounds, limit):
        self.mode = mode                # full / window / summary
        self.keep_rounds = keep_rounds  # 最多保留几轮原文(每轮两条消息)
        self.limit = limit              # 上下文预算(token),仅用于统计与提示
        self.history = []               # 原文消息
        self.summary = ""               # 滚动摘要:超长截断,模拟『纪要的纪要』
        self.facts = {}                 # 关键事实:同名覆盖
        self.compact_count = 0          # 压缩次数(仅 summary 模式递增)

    def add(self, role, content):
        """写入一条消息;full 全量保留,window 超轮丢弃,summary 超轮入纪要。"""
        self.history.append({"role": role, "content": content})
        if self.mode == "summary":
            self.extract_facts(content)
        if len(self.history) > self.keep_rounds * 2:
            if self.mode == "window":
                del self.history[:2]
            elif self.mode == "summary":
                self.compact()

    def used(self):
        return count_tokens(self.render())

    def render(self):
        """组装本轮上下文:关键事实 → 滚动摘要 → 最近 N 轮原文。"""
        parts = []
        if self.facts:
            parts.append("[关键事实] " + "；".join("%s=%s" % (k, v) for k, v in self.facts.items()))
        if self.summary:
            parts.append("[滚动摘要] " + self.summary)
        parts += ["[%s] %s" % (m["role"], m["content"]) for m in self.history]
        return "\n".join(parts)

    def compact(self):
        """最旧一轮的助手结论并入滚动摘要,user 原文丢弃(演示盲区);纪要超长截断。"""
        old, self.history = self.history[:2], self.history[2:]
        notes = [m["content"] for m in old if m["role"] == "assistant"]
        if notes:
            self.summary = (self.summary + "；" if self.summary else "") + notes[0]
        if count_tokens(self.summary) > 150:
            self.summary = self.summary[-150:]
        self.compact_count += 1

    def extract_facts(self, content):
        """关键事实抽取(演示版):命中关键词即写入,再次出现则覆盖。"""
        rules = {"学员水平": "零基础", "待办": "出三道题"}
        for key, value in rules.items():
            if value in content:
                self.facts[key] = value

def build_events():
    """构造 25 轮辅导对话:第 1、2 轮埋两条关键事实,之后循环提问。"""
    topics = [
        ("主键和外键有什么区别?", "结论:主键唯一标识本表记录,不能为空且全表唯一;外键引用他表主键,保证引用完整性。"),
        ("外键列可以空着吗?", "结论:可以,前提是列允许 NULL,代表该行还没关联到任何父记录。"),
        ("ON DELETE 有几种行为?", "结论:CASCADE 连坐删除子行,SET NULL 把外键置空,RESTRICT 拒绝删除。"),
        ("索引会拖慢写入吗?", "结论:会,每次 INSERT 或 UPDATE 都要同步维护索引,写入因此变慢。"),
        ("事务的 ACID 是什么?", "结论:原子性、一致性、隔离性、持久性,隔离性管并发下的脏读问题。"),
    ]
    events = [
        ("user", "我是零基础,从来没碰过数据库,想入门。"),
        ("assistant", "结论:收到,按入门学员安排,从最基础的概念讲起。"),
        ("user", "明天要交作业,帮我出三道练习题吧。"),
        ("assistant", "结论:已按模板出 3 道题,覆盖主外键与级联,答案回指课程资料。"),
    ]
    for i in range(21):
        question, answer = topics[i % len(topics)]
        events.append(("user", "再问一个:%s" % question))
        events.append(("assistant", answer))
    return events

def recall_of(mem, keyword):
    return keyword in mem.render()

def run(mode, events, limit, keep_rounds):
    mem = ConversationMemory(mode=mode, keep_rounds=keep_rounds, limit=limit)
    for role, content in events:
        mem.add(role, content)
    over = "超预算!" if mem.used() > limit else "正常"
    print("%-8s | 占用 %4d/%d %s | 压缩 %2d 次 | 零基础:%s | 三道题:%s" % (
        mode, mem.used(), limit, over, mem.compact_count,
        recall_of(mem, "零基础"), recall_of(mem, "三道题")))

def main():
    limit = 1150
    events = build_events()
    print("课程助教 25 轮辅导对话 · 上下文预算 = %d token" % limit)
    print("--- 同一份对话,三种会话记忆配置 ---")
    run("full", events, limit, keep_rounds=4)
    run("window", events, limit, keep_rounds=4)
    run("summary", events, limit, keep_rounds=4)

if __name__ == "__main__":
    main()

          完成标准:输出里能指认——全量模式超预算;滑动窗口占用最低、压缩 0 次,但两条关键事实召回均为 False;摘要+最近N轮占用封顶(远低于预算)、压缩多次,两条关键事实召回均为 True;注释掉 extract_facts 后摘要模式至少丢掉「零基础」,并能用一句话说明:纪要保大意且会截断,事实通道逐字保留决策依据,两条通道缺一不可。

          6. 边界与排错

          症状 原因 处理
          压缩后忘了「学员是零基础」 纪要只浓缩助手结论,漏掉用户自述 关键事实抽取走独立通道,别只看助手消息
          每轮都触发压缩(抖动) 阈值过低,或单条消息巨大 token 与轮数双条件触发;巨大单条在源头截断(呼应 02.02 02 章)
          纪要越长越没用 纪要自身膨胀,中段被稀释 纪要放 system 之后;超配额做「纪要的纪要」
          压缩本身太贵、太慢 每次压缩都是一次模型调用 放宽阈值、后台异步压缩、规则抽取兜底
          • 边界提醒:会话记忆只管「本会话」;会话结束历史清空(或转存),「重启后还记得」是 03 章外部存储的职责。压缩丢细节是特性不是 bug——先想清楚哪些细节必须保(用事实通道),再谈压多狠;压缩动作要留审计痕迹,别让模型「无感失忆」。

          7. 总结

          概念 一句话
          会话记忆 应用保存消息列表、每次调用重放,让无状态模型「显得有记忆」
          三个代价 token 账单、超窗截断、注意力稀释——都随轮数线性恶化
          取舍 近期要原文(追细节),早期要语义(省 token)——按信息年龄分级
          三类技术 滑窗(硬遗忘)、滚动摘要(保大意)、关键事实抽取(保决策条目)
          组合拳 「摘要 + 最近 N 轮」+ 事实通道;验收看占用封顶与关键事实召回

          思考题:为什么「全量历史最保真」的聊天机器人做法,在长对话里反而最先被淘汰?学员第 1 轮说「我零基础」,第 25 轮只问「那 ORM 呢?」——纯滑动窗口的助教与「摘要+最近N轮」的助教,回答会有什么差别?

          参考答案

          全量历史按输入 token 计费、随轮数线性膨胀,先撞窗口上限,后烧注意力,长对话下「保真」反而保不住任何内容。纯滑动窗口的助教早已把第 1 轮滑出窗外,不知道学员零基础,会用术语直接讲 ORM,学员大概率听不懂;「摘要+最近N轮」的助教即便纪要没逐字记下「零基础」,事实通道也存了「学员水平=零基础」,组装上下文时它就在场,回答会先补背景再讲 ORM——差别不在模型,在记忆对象把什么留了下来(第 5 节的召回实验就是证据)。
