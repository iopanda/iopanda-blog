          质量、社区、价格与商业化边界

          Promptfoo 对产品经理很有吸引力的一点，是它同时满足几个条件：开源、开发者友好、CI/CD 清晰、安全叙事强、还有企业版升级路径。真正做选型时，要拆开看它的社区热度、发布节奏、免费版边界、Enterprise 边界，以及 red teaming 的计量方式。[1][2][3][4]

          学习目标：学完本章，你将能够——

          1. 从社区数据判断 Promptfoo 的成熟度；
          2. 理解其 Community 与 Enterprise 的边界；
          3. 看懂公开价格与 probe 计量方式；
          4. 识别它的优势成本与隐性成本；
          5. 做出更现实的 adoption 建议。

          1. 社区规模与活跃度

          截至 2026-09-03，GitHub API 显示 Promptfoo 大约有 24.8k stars、2.3k forks、571 open issues，最近更新时间与推送时间都非常新，说明它已经是主流开源 LLM testing/red teaming 项目。[2]

          从 releases API 看，2026-06 到 2026-08 间持续发布 0.121.x 到 0.122.x，还有 code-scan-action 等配套发布，说明它不仅活跃，而且产品面正在持续扩展。[3]

          2. 开源边界与企业边界

          README 明确写到 Promptfoo remains open source and MIT licensed，同时说明它已成为 OpenAI 的一部分。[1]

          Pricing 页面则把产品边界说得很清楚：[4]

          • Free Forever / Community：开源工具，适合个人开发者和小团队；
          • Enterprise：团队协作、API access、team controls、SSO、可定制扫描与更多 probes；
          • Enterprise On-Premise：需要把 code scanning 和相关能力放在自己基础设施里的组织。

          这意味着 Promptfoo 的商业化边界是很清晰的：

          • 本地测试、基础评测、基础漏洞扫描可以开源做；
          • 团队协作、企业权限、更多扫描规模与托管能力进入 enterprise 语境。

          3. 价格怎么理解

          Pricing 页给出的公开信息很实用：[4]

          • Free Forever：含所有 model providers/integrations、red teaming（10k probes/month）、vulnerability scanning；
          • Enterprise：custom red teaming limits、team sharing & collaboration、Promptfoo API access、SSO 等；
          • Enterprise pricing：custom quote，需要联系销售。[4]

          这里最关键的不是具体价格表，而是 probe 这个计量单位。Pricing 页解释：probe 是 red team 测试中对目标系统发起的单次请求。[4]

          这对产品经理很重要，因为 Promptfoo 的成本模型不是传统 seat-only，而是和扫描规模直接相关。

          4. 为什么它看起来便宜，但不一定总是最省

          看起来便宜的原因

          • 开源免费层很强；
          • 本地运行 evals，不一定先买平台；
          • 小团队能非常低成本起步。[1][4]

          可能不便宜的原因

          • 红队规模大时，probe 数量会快速增长；
          • 企业协作、SSO、API access、on-prem 都会进入商业采购；
          • 团队还要投入时间维护 configs、assertions、CI pipeline 和扫描策略。

          所以 Promptfoo 常常是“起步很便宜，规模化后要认真算账”的工具。

          5. 质量怎么看

          Promptfoo 的质量可以从四个面看：

          1. 产品聚焦度：eval、red team、code scanning、CI/CD 非常聚焦。[1][5][6]
          2. 开发者体验：README 明确强调 live reload、caching、local execution、CLI。[1]
          3. 工程成熟度：GitHub 活跃、release 连续、docs 完整。[1][2][3]
          4. 边界清晰度：Community 与 Enterprise 的差异非常明白，不容易误解。[4]

          6. adoption 建议

          阶段 建议
          本地验证 先用 Free 版搭一套最小 eval + assertions
          团队试点 把 promptfoo eval/redteam 接到 GitHub Actions 或 GitLab CI
          生产前门禁 把 severity threshold、scan history、红队模板常态化
          企业治理 再评估 Enterprise/On-Prem、SSO、API access、团队协作

          7. 总结

          关键问题 一句话
          社区规模如何 主流开源 LLM testing / red teaming 项目 [2]
          价格如何 免费层强，企业版按需求定制 [4]
          最大边界是什么 团队协作、SSO、API access、probe 扩容进入 enterprise
          最大隐性成本是什么 配置维护、扫描规模增长、门禁治理
          最适合谁 想快速把 AI 测试与安全门禁接进流程的团队

          思考题：为什么 Promptfoo 的“免费层很强”对小团队是巨大优势，但对大团队不一定是最终决策点？

          参考答案

          因为小团队最先关心的是能不能低成本起步，而大团队更关心协作、权限、历史、API、规模、审计与支持。免费层解决的是进入门槛，不自动解决组织治理。
